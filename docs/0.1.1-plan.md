## 1. 目标与成功判据

**目标**：修掉 0.1.0 已确认的契约断点、证据漏洞、持久化边界与文档漂移，让“模型按工具返回值就能走通流程”和“引擎拒绝伪造证据”两条链路完整闭合。

**成功判据**：

1. P4 模型只靠 `novel_brief` 返回的 `fields.score_exclusions` 就能一次算对 `total`。
2. 任何阶段只要该阶段 `novel_brief` 缺失或 digest 过期，`novel_status` / `novel_pipeline` 的 `next.tool` 必须先补 `novel_brief`；P5/P6 被阻塞且 brief 当前后给出 `novel_revise`；`ready_to_archive` 在 P8 brief 当前后给出 `novel_archive`；不能是只读的 `novel_status`。
3. 四个 P6 语义项必须使用四条不同、至少 8 字、来自不同句子且互不重叠的正文引用；复制同一句或同一句的滑动子串会被拒绝。
4. PG-09 的开头/中间/结尾边界使用正文实际段落号，不能用提交的 `paragraph` 字段绕过；middle 必须来自正文内部。
5. 新埋设伏笔的 summary title 与最终 title 都必须出现在正文；角色、地点、伏笔三类实体都不能只在台账里“凭空出现”。
6. `engines.dsh` 在 semver `includePrerelease` 语义下拒绝 `0.3.0-alpha.1`，仍接受 `0.2.2-rc.1`。
7. `novel_brief` 的非当前章请求被拒绝；`novel_status` 同时给出请求章与当前活跃章；`novel_state` 的 `review`/`check` 按章读取。
8. 非法 YAML（状态文档、plan、registry）、同 pid 陈旧锁、合法 `..foo` 路径、重复 staging path 都有回归测试；plan 损坏可被 `novel_plan_chapter` 修复。
9. `EngineService.dispose()` 由 `apply()` 的 `ctx.effect` 托管，卸载幂等。
10. 真实宿主门：临时 `DSH_HOME` 中 `pack → plugin add → --dump-config → 启动 web → 面板/预设/工具/命令 → remove` 通过；无法自动化的部分必须明确标注，不得用假 Context 冒充。

**非目标（0.2）**：英文界面、规则包运行时加载、云同步、多人协作、新工具/新命令、schema version bump、第二个运行时依赖。

## 3. 切片与文件

### S1 · 模型可见契约（P0）

**文件**：`src/tools/index.ts`、`src/engine/service.ts`、`src/types.ts`、`tests/tools-extra.spec.ts`、`tests/engine-extra.spec.ts`、`tests/brief.spec.ts`。

- `novel_brief` 的 render 增加 `fields`（含 `score_exclusions`、`next_tool`），context 改为紧凑 JSON。
- 阻塞时按当前 stage 选择下一步：`P5`/`P6` 若该阶段 brief 未签发，先返回 `novel_brief`；签发后返回 `novel_revise`；不得返回 `novel_status`。
- `getBrief` 拒绝 `chapter !== pipeline.chapter`。
- `getStatus` 增加 `active_chapter`；工具 render 同时显示请求章与活跃章。
- `queryState` 的 `review`/`check` 按 `chapter` 读取对应文件；未给章时读当前章。

**测试**：P4 的 fields 渲染；阻塞 next；非当前章 brief；status 双章；历史 review/check。

### S2 · 证据与 SSOT（P1）

**文件**：`src/engine/semantic.ts`、`src/engine/gates.ts`、`src/engine/state-delta.ts`、`tests/semantic.spec.ts`、`tests/gates.spec.ts`、`tests/state-delta.spec.ts`、`tests/helpers.ts`、相关 e2e/fixture。

- P6：四条引用必须不同，每条至少 8 字；重复引用返回 `SEMANTIC_EVIDENCE_INVALID`。
- PG-09：用 `actualParagraph` 校验 opening/ending 边界；提交段落号只用于“误差不超过 1”的定位提示。
- 新伏笔：`title` 必须出现在正文；三处测试 fixture 的标题必须真实可查。

**测试**：四条同句失败；四条不同 8 字通过；opening 实际第 3 段、提交第 2 段被拒；ending 同理；新伏笔标题不在正文被拒；标题在正文通过。

### S3 · 持久化与生命周期（P1/P2）

**文件**：`src/store/fs.ts`、`src/store/lock.ts`、`src/store/path.ts`、`src/store/txn.ts`、`src/engine/service.ts`、`src/index.ts`、`tests/store.spec.ts`、`tests/store-extra.spec.ts`、`tests/lock.spec.ts`、`tests/txn.spec.ts`、`tests/smoke.spec.ts`。

- `readDoc` 捕获 YAML 解析错误，转成 `ENGINE_SCHEMA_INVALID`，消息带路径。
- `FileLock`：pid 存活时，`startedAt` 不可解析不得单独触发回收；pid 死亡才回收。
- `resolveInside`/`isInside`：只拒绝 `..` 段，不误杀 `..foo`。
- `runTransaction`：重复 staging path 在写盘前拒绝。
- `EngineService.dispose()`：清空 stores/replay/compiled/lastRoot，幂等；`apply` 用 `ctx.effect` 托管。

**测试**：坏 YAML；活 pid 坏时间戳不被抢；死 pid 坏时间戳被回收；`..foo`；重复 path；dispose 幂等与 host 卸载。

### S4 · 宿主兼容与版本（P1）

**文件**：`package.json`、`tests/preset.spec.ts` 或新增 `tests/compatibility.spec.ts`。

## 9. 全量复核补强（2026-10-27）

对 0.1.1 工作区做 Git/源码/测试/真实宿主与真实模型复核后，在原切片之外确认并修复了以下链路缺口：

| 级别 | 缺口 | 修复 |
|---|---|---|
| P0 | `next` 只在 P5/P6 阻塞时补 brief，P1/P2/P3/P4/P6/P8 仍可能直接给出被 PG-01 拒绝的工具 | 所有阶段先比较 brief digest；缺失/过期返回 `novel_brief`；`ready_to_archive` 在 P8 后返回 `novel_archive` |
| P0 | `runCheck` 失败后偷偷重签 P6 brief，模型未真正收到更新上下文 | 删除重签；必须重新 `novel_brief P6` 才能 revise |
| P1 | `PG-11` 任一轮次耗尽会误伤其他计数器 | 按操作/阶段使用 review、revise、check 各自计数；耗尽时 `next=novel_rollback` 且显示 PG-11 |
| P1 | 同 pid 陈旧锁/释放失败会造成永久写锁 | 进程内 `liveNonces` + 释放失败可回收 + hard-link 回收比较 |
| P1 | 手写 `chapters.yaml` 无 `archive_digest` 可假重放 | 无 digest 直接拒绝；补回归 |
| P1 | 归档未复核阅读证明；`PG-07` 未复核互斥扣分；review 手工改写可绕过 | 归档加入 PG-09 与 proof；PG-07 重新应用 exclusions；pipeline 记录 `review_digest`，归档拒绝被改写的 review |
| P1 | PG-09 middle 不校验正文内部；语义证据可用同句不重叠子串 | middle 边界；按句子 + 非重叠区间去重 |
| P1 | 新世界实体可只进台账；伏笔 title 未校验 summary/类型 | 正文 + summary 双回查；title 类型/双来源校验 |
| P2 | plan/registry YAML 仍泄漏解析错误；损坏 plan 无恢复入口 | 统一 `ENGINE_SCHEMA_INVALID`；load 容错并暴露 `plan_error`，可被 plan_chapter 覆盖 |
