## 2. Aegis Visibility 与 Change Necessity

### 2.1 为什么必须改代码

这些不是文案问题：

- `LOCKED_DETAIL_DRIFT` 的基准取错 owner，会持续误报；
- `RELATION_UNKNOWN` 在 P6 结构性必然误报；
- `getBrief` 收据无 current 标记，长书无法判断哪条有效；
- `novel_state` 全量返回，21 章已 51 条伏笔 / 209 条时间线 / 175 条收据；
- `PLEASURE_DENSITY` 与 `FS_REVISITED_TOO_SOON` 的阈值/词表只按全书或全局，题材不适配；
- 数字规则已有 owner，但缺结果块、facts 为空提醒和算式覆盖；
- 自评 1–3 / low 没有判定锚点，分布表看不出弱章。

仅改文档、规则包文案或 brief 无法修正这些误判与读模型。

### 2.2 最小代码边界

不新增服务、不改 13 个门控 ID、不新增第 29 个工具、不重做面板。只在既有 owner 上扩展：

- `domain/wordcount.ts`：计量字段；
- `rules/checks.ts`：锁定、关系、数字、对话、爽点、伏笔规则；
- `engine/service.ts`：`queryState` 分页、`getBrief` 收据、`runCheck` numeric 块、status/report 读模型；
- `engine/state-delta.ts` / `engine/gates.ts`：新 delta 字段和归档顺序；
- `types.ts` / `tools/index.ts` / `store/schema.ts`：可选字段与工具参数；
- `rulepacks/default.yaml` / `docs/rulepack.md`：题材 profile；
- `briefs/P3.md` / `P4.md` / `P6.md` / `P8.md`：给模型的可执行口径；
- `docs/tools.md` / `docs/states.md` / `README.md` / `CHANGELOG.md` / `DESIGN.md`：契约与版本。

### 2.3 Ripple Signal Triage

会同时触及 producer 与 consumer：`state_delta` 写入、`novel_state` 读取、`novel_check` 结果、`novel_report` 聚合、P3/P4/P6/P8 任务书和面板摘要。因此：

## 4. 反熵与退役决定

### 4.1 退役“整段旧文=锁定基准”

```text
Anti-Entropy Declaration:
- Deletion Class: code-retirement（行为退役，不删数据）
- Old Path/Object: locks.characters[].appearance / locks.locations[].layout 作为整段规范
- Invalid Responsibility / Authority: 把首现原文当唯一标准
- Legitimate Capability Remaining on Carrier: locks 仍保存首现证据；只有 worldbook 无该角色/地点时，才提供 1..3 条可读锚点
- New Canonical Owner: 角色 worldbook.characters[].appearance（可选）、地点 worldbook.locations[].description + layout；角色 description 是传记，不是外貌标准；locks 只做锚点补充
- Expected Preserved Behavior: 旧文档可读；无规范描述/锚点时不误报
- Expected Retired Behavior: 正常续写不再因“没有复述整段旧文”被判漂移
- External Boundary Touched: no
- Source-of-Truth Data Risk: none
- User Confirmation Required: no
```

`Retirement Decision: delete-first`（只退役行为，不删 `locks` 数据）。无 `Data Destruction Guard`。

### 4.2 退役 P6 的关系未声明 owner

`RELATION_UNKNOWN` 从 P6 机检中移除，改由归档事务在合并 `state_delta.relationships` 后调用同一个纯检查函数。旧 P6 结果不再产生；归档仍能给出 warning。没有两个 owner。

### 4.3 保留的兼容边界

- `english_punct` 不重命名，只新增 breakdown；
- `acknowledged: string[]` 不删除，新增 `acknowledged_findings`；
- 旧 `type` 不删除，新增 `type_code`；
- 旧 `timeline` 下标继续可读；新 `event_key` 可选；
- 旧 `briefs.yaml` 记录不删除；current 由读取时计算并写入新记录；
- 旧 51 条伏笔不自动补计划，旧 20 条关系不自动猜类型。
