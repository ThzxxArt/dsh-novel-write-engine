# dsh-novel-write-engine 0.2.2 迭代方案：会话级项目选择与便利能力

> 状态：**已实施**；爸爸已确认按 A，并补入 `/novel scan`、`/novel resume`、面板完整卷视图三件套。实施证据见 `docs/0.2.2-evidence.md`，真实模型回执见 `docs/0.2.2-real-model-evidence.md`。
> 版本：`0.2.2`。
> 方向：按 A 做——**会话级绑定**，不再让“最近一次工具调用”或全局 `active` 决定一次工具调用写哪本书。
> 目标：项目选择可持久化、可多项目、可按工作区推导、面板可切换；项目被物理删除时不静默换书、不自动重建、不丢登记；在不新增工具的前提下，让发现项目、接续写作和长书浏览更顺手。

## 0. 先回答爸爸的六个问题

| 问题 | 结论 |
| --- | --- |
| 能不能不用内存？ | **能。** 删除 `EngineService.lastRoot`。项目选择不再依赖进程内“上次碰过谁”，每次从持久化绑定、会话 cwd、注册表和配置计算。内存里只保留 `FsStore` 句柄、brief 缓存等与“选哪本书”无关的缓存。 |
| 能不能持久化？ | **能。** 新增 `stateDir/session-bindings.yaml`，按 DSH `SessionId` 保存显式选择；注册表 `projects.yaml` 继续保存项目清单与面板默认项。两者都原子写、可跨 DSH 重启。 |
| 能不能注册多项目？ | **能。** 保留并增强现有注册表：`novel_init`、显式 `project_root`、首次工作区解析都会自动登记；支持按路径、标题、面板选择；项目目录永远不会因为“忘记登记”而被删。 |
| 面板能不能灵活切换？ | **能。** 面板 v4 增加项目选择器；多项目时不再猜。面板选择只改变“正在看哪本”，不改变任何会话的写作绑定。 |
| 能不能是工作区绑定？ | **能，但只做“工作区提示”，不做第二份持久化 workspace 映射。** 会话 cwd 本身由 DSH 持久化；插件按 cwd 找 `novel.yaml`、`cwd/novel` 或唯一子项目。一个工作区有多本书时返回歧义，交给会话绑定或 `/novel use`。 |
| 项目被物理删除时怎么处理？ | **保留登记与绑定，明确报错，不自动回退到别的书，不自动重建。** 目录暂时离线、移动、路径被别的项目复用，分别给不同错误与修复动作；面板显示“项目不在了”，但保留其他项目可选。 |

### 0.1 本轮补入的三件套（爸爸已选 A）

在 A 的会话级选择之上，只补三个高频便利能力。三者都**不新增工具、不改变 28 个工具 / 32 个操作，也不新增项目正文写入口**：

| 能力 | 形态 | 解决什么 | 关键边界 |
| --- | --- | --- | --- |
| 项目扫描 | `/novel scan [--register]`（命令） | 不用再手写 `activate/register` 长命令；先看工作区有哪些书，再决定登记哪些 | 只扫 cwd、cwd/novel、直接子目录；最多 50 个候选；普通 scan 不写；`--register` 只登记健康项目，不改 active、不绑会话 |
| 一键续写 | `/novel resume`（命令）+ 面板复制按钮 | 新会话快速把“书名 + root + 章节 + 阶段 + 下一步”交给模型 | 只读；不写绑定；文本要求第一次工具调用显式带 `project_root`，并要求先核对书名 |
| 完整卷视图 | 面板 v4 展示 `book.volumes` 全部卷 | 长书不再只看前 8 卷、看不到后面的卷 | 复用现有投影，不新增接口；滚动容器承载长列表，不截断数据 |

这三件套是对 A 的补充，不是第二套项目选择逻辑：扫描复用工作区发现，续写复用状态投影，完整卷视图复用已有 `book.volumes`。

## 1. 现状与根因

### 1.1 现在的解析链

`EngineService.resolveRoot()`（`src/engine/service.ts:524-537`）的顺序是：

1. 显式 `project_root`；
2. 进程内 `lastRoot`；
3. 注册表 `active`；
4. 配置 `projectRoot`，默认 `./novel`。

`lastRoot` 在 `load()` 成功时写入（`src/engine/service.ts:6591`），在 `initProject` 和 `mutate` 成功时也会写（`src/engine/service.ts:6801`）。它是 **EngineService 单实例的全局字段**，不区分会话、不持久化。

### 1.2 为什么 A/B 会串

假设 A、B 两本书，A 已激活：

1. A 会话或面板读过 A，`lastRoot = A`；
2. B 会话调用 `novel_status` 不传 `project_root`；
3. `resolveRoot` 先命中 `lastRoot = A`；
4. 模型拿到 A 的标题、章节和阶段；
5. `novel_brief`、`novel_write_draft`、`novel_archive` 仍走同一解析，把 B 会话的产出写进 A。

当前代码没有任何“会话 — 项目”绑定，也没有在“书名与会话上下文不一致”时拒绝。模型只能靠对话文本自行判断，**这不是系统保证**。

### 1.3 面板为什么也帮不上忙

`panelBundle()`（`src/engine/service.ts:4764-4775`）调用 `panelSnapshot()`，后者再走 `load(root?)`；不传 root 时同样吃全局 `lastRoot`。面板路由 `panelHandler()`（`src/remote/index.ts:49-99`）不接收项目参数，浏览器端 `NovelPanel` 也只请求固定路径（`src/client/panel.ts:1484`）。

因此面板不是“观察者”，它读一次也会改 `lastRoot`，参与污染。

### 1.4 现有注册表的能力边界

`ProjectRegistry`（`src/store/registry.ts`）只有：

- `schema_version: 1`
- `active: string | null`
- `projects: [{ root, title, updated_at }]`

它没有会话维度，`active` 是全局默认值。现有测试 `tests/round4.spec.ts:26-63` 正是在锁定“active 影响工具”和“面板跟随最近工具”的旧行为，0.2.2 必须改写这些测试，而不是保留两套语义。

## 2. 设计目标、不变量与非目标

### 2.1 目标

1. **会话隔离**：A 会话的默认项目是 A，B 会话的默认项目是 B；并发调用不串。
2. **持久化**：DSH 重启后，A/B 的显式选择仍在。
3. **可解释**：每次解析都能说清来源：显式参数、会话绑定、工作区、唯一注册项目、面板默认。
4. **不静默换书**：绑定失效、路径被复用、多个候选时，返回结构化错误，不偷偷选另一本。
5. **面板独立**：面板选择只影响视图，不影响任何会话的工具解析。
6. **删除安全**：项目目录被删、被移动、被替换时，保留登记与绑定，给恢复/重绑路径，不自动删数据。
7. **零项目数据迁移**：不改 `novel.yaml`、`state/`、`outline/` 的 schema；只在 `stateDir` 增加会话绑定文件，注册表做兼容性增字段。
8. **发现便利**：显式 `/novel scan` 能在当前工作区有限发现候选项目；`--register` 一次登记多本健康项目，但不改变任何会话的写作绑定。
9. **接续便利**：`/novel resume` 输出一段可直接粘贴的续写指令，把 root、书名、章节、阶段和下一步固定下来，减少新会话的选书摩擦。
10. **长书可读**：面板完整展示卷列表与计划/归档计数，不再用“还有 N 卷”把后面的结构藏起来。

### 2.2 不变量

- **INV-01**：工具写操作最终使用的 root，必须来自一次可解释的选择；不能来自“上一次碰过谁”。
- **INV-02**：一个 DSH 会话最多有一个显式项目绑定；没有绑定时才允许工作区推导。
- **INV-03**：显式 `project_root` 成功加载后，才写入会话绑定；失败不覆盖旧绑定。
- **INV-04**：会话绑定存在但项目不可用时，**禁止**回退到 `active`、配置或另一本书。
- **INV-05**：注册表与绑定文件是便利状态，不是正文真相；删除它们不删项目。
- **INV-06**：面板是只读投影；项目选择器只改 GET 请求的 `root` 参数，不写项目、不写会话绑定；复制续写只写浏览器剪贴板。
- **INV-07**：项目选择不依赖进程内可变全局；`lastRoot` 删除。
- **INV-08**：项目被物理删除时不自动执行 `novel_init`、不自动 `rm`、不自动改 `active`。

### 2.3 非目标

- 不做项目内容迁移、不新增 `project_id` 字段、不改 `novel.yaml` schema。
- 不做后台自动发现或递归扫描全盘；只有显式 `/novel scan` 才做工作区有限扫描，且普通 scan 不写注册表。
- 不新增工具或操作；`scan`/`resume` 只作为 `/novel` 子命令，工具数仍 28、操作数仍 32。
- 不新增项目正文写入口；`scan` 只写 `stateDir` 元数据，`resume` 只读，完整卷视图只渲染已有投影。
- 不把面板变成第二写入口；面板新增的复制按钮只写浏览器剪贴板，不发写请求。
- 不做跨项目搜索、合并、同步。
- 不做多用户/远程共享的权限模型；仍以本机 DSH 认证边界为准。

## 3. 方案比较

| 方案 | 做法 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- | --- |
| A. 会话级绑定 + 工作区提示 | 每个会话持久化一个 root；cwd 只做 hint | A/B 隔离、可重启、可解释 | 需要新增绑定文件；多项目首次要选一次 | **采用** |
| B. 只按 cwd 自动绑定 | 每次从会话 cwd 找项目 | 零配置、符合“一书一工作区” | 同一工作区多本书无解；cwd 被移动/删除时无稳定身份 | 作为 A 的第 3 层，不单独用 |
| C. 继续用全局 active | 每个会话共享 active | 改动最小 | 正是 A/B 串书的根因 | 拒绝 |
| D. 单独的 workspace-bindings.yaml | cwd → root 持久化映射 | 同工作区所有会话共享 | 与 session binding 形成第二套 owner；冲突时谁赢难解释 | 拒绝，避免重复 owner |

**选择：A + cwd hint，不引入独立 workspace 映射文件。**

一句话：**会话绑定负责“确定”，工作区负责“方便”，注册表负责“发现”，面板负责“查看”。四者不互相冒充。**

## 4. 四层选择模型

| 层 | 数据来源 | 作用域 | 是否持久化 | 是否可覆盖 |
| --- | --- | --- | --- | --- |
| L1 显式参数 | 工具 `project_root` / 命令参数 | 单次调用 | 否；成功后写入 L2 | 最高 |
| L2 会话绑定 | `session-bindings.yaml` | 一个 DSH `SessionId` | 是 | 被 L1 覆盖 |
| L3 工作区提示 | 会话 cwd（DSH 持久化） | 一个工作区 | 随会话 cwd 持久化 | 被 L2 覆盖；多候选则报错 |
| L4 默认项 | 注册表 `active` / 配置 `projectRoot` / 唯一项目 | 进程/部署 | 注册表/配置持久化 | 最低；仅无 L1/L2/L3 时 |

### 4.1 工具调用（有 Agent 会话）

```text
if project_root 显式:
    loadAt(root) 成功后 -> 绑定当前 session -> 返回
else if 当前 session 有绑定:
    loadAt(binding.root)
    校验 created_at 身份；失败 -> PROJECT_MISSING / IDENTITY_MISMATCH
else if cwd 能唯一确定项目:
    loadAt(candidate) -> 返回（不自动写会话绑定）
else:
    注册表项目数 == 1 -> 用它
    注册表项目数 == 0 + 配置 root 可用 -> 用它
    否则 -> PROJECT_AMBIGUOUS（列候选）或 PROJECT_NOT_FOUND
```

**关键：有绑定就不看 `active`。** `active` 只服务面板默认，不服务工具。

### 4.2 非 Agent 调用（CLI、内部、旧测试）

```text
显式 root
-> 注册表 active
-> 配置 projectRoot（可用时）
-> 唯一注册项目
-> PROJECT_AMBIGUOUS / PROJECT_NOT_FOUND
```

保留旧测试中“没有 Agent 时 active 可用”的语义；有 Agent 时不使用 active 作为静默兜底。

### 4.3 面板

```text
浏览器 localStorage 记住的面板选择（仅客户端，作为 query 发送）
-> 查询参数 ?root=<已登记 root>
-> 注册表 active
-> 唯一注册项目
-> 配置 projectRoot（如可用）
-> 无选择：展示项目选择器
```

服务端只看到 `query | active | single | config | none` 五种来源；`localStorage` 不进入服务端语义。面板不读会话绑定，也不写会话绑定。网文工坊挂在 DSH 的 `main` root slot，没有会话身份，因此**不能**自动判断“当前对话是 A 还是 B”；项目选择器是正确边界，不假装跟随会话。

配置项 `projectRoot` 的默认权有一个收窄：当它本身就是多个已登记项目之一时，面板显示 `choose`，不替用户在多项目中选一本；只有它不在“多项目”集合里、或作为唯一/唯一配置兜底时，才使用 `config`。这与 §10.4“多项目无 active 先选”一致。

## 5. 持久化数据模型

### 5.1 注册表（兼容增字段）

文件：`stateDir/projects.yaml`；`stateDir` 默认 `~/.dsh/novel-write-engine`，配置可改。构造 `FsStore` 前统一 `path.resolve(stateDir)`；空配置才落回默认目录。

```yaml
schema_version: 1
active: '/abs/novel/A'        # 面板默认；不再作为多项目工具默认
projects:
  - root: '/abs/novel/A'
    title: 'A 书'
    created_at: '2026-10-01T00:00:00.000Z'   # 新增，可选，用于移动提示
    updated_at: '2026-10-29T00:00:00.000Z'
  - root: '/abs/novel/B'
    title: 'B 书'
    created_at: '2026-10-02T00:00:00.000Z'
    updated_at: '2026-10-29T00:00:00.000Z'
```

- `schema_version` 仍为 1；`created_at` 是可选增字段，旧文件可读。
- `root` 用 `path.resolve` 规范化；同一路径只保留一行。
- `active` 可以指向暂时缺失的项目；面板会显示“项目不在了”，不自动改 active。
- `updated_at` 保持现有含义：登记/最近一次登记时间；不冒充项目正文修改时间。

### 5.2 会话绑定

文件：`stateDir/session-bindings.yaml`。

```yaml
schema_version: 1
bindings:
  - session_id: 'session-75849f4d-e951-43f3-a850-cf60b49c6e23'
    root: '/abs/novel/A'
    title: 'A 书'
    project_created_at: '2026-10-01T00:00:00.000Z'
    bound_at: '2026-10-29T17:30:00.000Z'
    source: 'explicit'        # explicit | init | command
```

- 按 `session_id` 唯一；同一会话只保留一条。已绑定同一 `root`、`title` 且 `project_created_at` 相同时不重写文件（幂等），`source`/`bound_at` 不参与重写判定；标题变化时才刷新标题与来源，避免每读一次都产生元数据写。
- `project_created_at` 是身份校验，不新增 `project_id`，不改项目 schema。
- `source` 只用于诊断，不参与优先级。
- 文件缺失 = 没有任何绑定；无显式 `project_root` 的解析遇到文件损坏 = `ENGINE_SCHEMA_INVALID`，不静默忽略；显式 root 的只读加载仍可完成，但不更新损坏的绑定。
- 坏行（缺 `session_id/root`）过滤掉，保留可读行；整文件不是对象/Schema 版本不对则报错。
- 这是便利状态，不属于项目数据；删掉它不会删任何书，只会让会话回到工作区/唯一项目推导。升级/备份项目目录时不需要包含它。
- **不自动清理**：会话结束、项目暂时离线都不删除绑定。清理只能显式 `/novel unbind` 或 `/novel registry forget`（后者不删绑定，见 §10）。

### 5.3 写入与并发

- 两个文件都用现有 `FsStore.writeText()` 的临时文件 + fsync + rename 原子写。
- 进程内：`EngineService` 新增 `metadataMutex: KeyedMutex` 和 `withMetadataLock()`，按 `stateDir` 串行化注册表/绑定的“读—改—写”，避免两个会话同时绑定丢行；`ProjectRegistry` 与 `SessionBindings` 仍只负责各自的文件格式，不各自持有第二套锁。
- 跨进程：`withMetadataLock()` 内写 `stateDir/.metadata.lock`，复用 `FileLock`；取锁前先 `mkdir(stateDir, { recursive: true })`。读不加锁，因为 rename 原子，读到的总是完整旧版或完整新版。快速路径先无锁读注册表，确认需要新增行后再取锁并二次检查，避免每次读都抢锁。
- 元数据锁超时返回 `ENGINE_LOCK_TIMEOUT`，提示“另一个 DSH 实例正在写项目登记”；不阻塞项目正文锁。
- 自动登记是 best-effort：元数据写失败不能让已经成功的项目写入失败；`initProject` 可以把失败作为 warning 返回，其他读取路径忽略并继续。

### 5.4 为什么不用 `project_id`

- 新增 `project_id` 要改 `novel.yaml` schema，所有旧项目要迁移；收益只是身份更硬。
- `created_at` 已存在且不可变（`novel_amend` 保护），足以识别“同一路径被换成另一本书”。
- 若旧项目 `created_at` 为空，身份校验降级为“路径 + 标题”，绑定里就存空字符串；不新增 `identity_weak` 字段，也不阻塞使用。路径被替换时只能提示、不能硬判，文档会写明这个弱点。

## 6. 解析算法（详细）

### 6.1 公共结果类型

```ts
type SelectionSource = 'explicit' | 'session' | 'workspace' | 'active' | 'config' | 'single'

interface Selection {
  root: string
  source: SelectionSource
  title?: string
  created_at?: string
}
```

- `Snapshot` 增加 `selection: Selection`，由 `load()` 在 `loadAt()` 成功后附加；`StatusReport` 暴露 `selection`，`novel_status` 才能告诉模型“为什么是这本书”。
- `Snapshot.root` 仍是项目根；`lastRoot` 不再是字段。
- `stateDir` 在构造 `FsStore` 前统一 `path.resolve`，避免 DSH 进程 cwd 改变导致注册表/绑定换位置。

### 6.2 `resolveRoot` 伪代码

```ts
async resolveRoot(explicit?: string): Promise<Selection> {
  const caller = this.callerContext.getStore()

  if (explicit !== undefined) {
    return { root: resolve(explicit), source: 'explicit' }
  }

  if (caller?.sessionId) {
    const binding = await this.bindings.get(caller.sessionId)
    if (binding) {
      return { root: binding.root, source: 'session' }  // 失效由 load 阶段包装
    }
    if (caller.cwd) {
      const found = await discoverWorkspace(caller.cwd)
      if (found.kind === 'one') return { root: found.root, source: 'workspace' }
      if (found.kind === 'many') throw ambiguous(found.roots)
    }
  }

  const registry = await this.registry.read()
  if (caller?.sessionId) {
    // 有会话但无绑定/工作区：只在唯一项目时兜底，绝不拿 active 在多项目里猜
    if (registry.projects.length === 1) return { root: registry.projects[0].root, source: 'single' }
    if (registry.projects.length > 1) throw ambiguous(registry.projects)
    if (await projectExists(this.config.projectRoot)) {
      return { root: resolve(this.config.projectRoot), source: 'config' }
    }
  } else {
    if (registry.active) return { root: registry.active, source: 'active' }
    if (await projectExists(this.config.projectRoot)) {
      return { root: resolve(this.config.projectRoot), source: 'config' }
    }
    if (registry.projects.length === 1) return { root: registry.projects[0].root, source: 'single' }
    if (registry.projects.length > 1) throw ambiguous(registry.projects)
  }
  throw notFound()
}
```

补充：

- `loadAt(root)` 只负责读项目，不再调用 `resolveRoot`，避免递归。
- 伪代码里的 `projectExists(root)` 指“有 `novel.yaml` 或项目 state 证据”，不是单看目录存在；`damaged` 项目仍可作为配置/唯一项目候选，交给 `loadAt` 报可修复错误，而不是静默跳过。
- `load(root?)` = `resolveRoot(root)` + `loadAt`。
- `mutate` 先 `resolveRoot`，再在项目锁内 `loadAt`；不再写 `lastRoot`。
- 显式 root 成功 `loadAt` 后：写会话绑定（如果调用方有 `sessionId`），best-effort 登记项目。
- `initProject` 是例外：先用 `input.root ?? config.projectRoot`，不调用 `resolveRoot` 的会话绑定/工作区分支；`mutate` 接受一个已解析的 `Selection`，创建成功后写绑定和登记。这样 B 会话的 `novel_init` 不会误建到 A。
- 会话绑定解析成功但项目读取失败时：
  - `PROJECT_NOT_FOUND` -> 包装成 `ENGINE_PROJECT_MISSING`；
  - 身份不一致 -> `ENGINE_PROJECT_IDENTITY_MISMATCH`；
  - 其他读取错误保持原错误码，不改成“缺失”。

### 6.3 完整优先级矩阵

| 场景 | 结果 |
| --- | --- |
| A 会话绑定 A，B 会话绑定 B | 各读各的 |
| A 会话绑定 A，B 会话无绑定，cwd 指向 B | B（workspace） |
| A 会话绑定 A，B 会话无绑定，cwd 含 A/B 两个项目 | `PROJECT_AMBIGUOUS`，列 A/B |
| A 会话绑定 A，B 会话无绑定，cwd 无项目，注册表有 A/B | `PROJECT_AMBIGUOUS`，不选 active |
| 只有一个注册项目 | 用它 |
| 无注册项目，配置 `projectRoot` 有项目 | 用它 |
| 无注册项目，配置 `projectRoot` 无项目 | `PROJECT_NOT_FOUND` |
| 绑定 A，A 目录被删 | `PROJECT_MISSING`，不回退 B |
| 绑定 A，A 路径被换成另一本 `created_at` 不同的书 | `PROJECT_IDENTITY_MISMATCH` |
| 绑定 A 丢失，注册表 B 的 `created_at` 与 A 相同 | 错误里提示 `moved_to: B`，不自动跳 |
| 无 Agent（CLI/测试） | 显式 -> active -> config -> 唯一 -> 歧义 |
| 面板无参数 | 客户端 localStorage 作为 query -> active -> 唯一 -> 配置 -> 选择器 |

### 6.4 工作区发现规则

`discoverWorkspace(cwd)` 只做有限、可解释的检查，不递归扫描全盘：

1. `cwd` 自身有 `novel.yaml` -> 该目录；
2. `cwd/novel` 有 `novel.yaml` -> 该目录；
3. `cwd` 的直接子目录中**恰好一个**有 `novel.yaml` -> 该目录；
4. 直接子目录中**两个及以上**有 `novel.yaml` -> `many`；
5. 没有 -> `none`。

不做“向上找祖先”的无限回溯：`/novels/novel.yaml` 与 `/novels/book-a/` 并存时，向上回溯会把 `book-a` 误判成父项目。若用户的工作区就是父目录，请用 `/novel use` 或显式 `project_root`。

### 6.5 cwd 的持久化

DSH 的 `Session.header.cwd` 与 `workingDirectory` 投影已经持久化会话目录；插件不复制 workspace map。工具适配层通过 `exec.agent` 和 `workingDirectory.ensure(agent, signal)` 取得 cwd：

- `exec.agent?.id` -> `SessionId`；
- `workingDirectory.ensure()` 可能因目录被删而失败：捕获后把 `cwd` 置空，继续走会话绑定/注册表；不能因为 cwd 坏了让已有绑定失效；
- 没有 `workingDirectory` 服务（headless/测试）时，只传 `sessionId`，不做工作区推导。

## 7. 会话绑定生命周期

### 7.1 什么时候写入

| 事件 | 是否绑定 | 说明 |
| --- | --- | --- |
| `project_root` 显式传入且项目加载成功 | 是 | 包括读操作；语义是“为当前会话选择这本书” |
| `novel_init` 成功 | 是 | 新项目创建成功后绑定，`source: init`；`novel_init` 本身**不读会话绑定**，避免在 B 会话里把新书建到 A |
| `/novel use <path|title|.>` | 是 | 人类显式切换；`source: command` |
| 工作区唯一候选 | 否 | 每次从 cwd 推导，避免 cwd 变化后绑定变旧 |
| 注册表唯一项目/配置兜底 | 否 | 只是兜底，不写成会话选择 |
| 面板选择 | 否 | 面板没有会话身份，也不应影响写作 |
| 读错误/写失败/身份不一致 | 否 | 不覆盖旧绑定 |

`novel_init` 的 root 规则单独处理：`input.project_root ?? config.projectRoot`，不经过会话绑定/工作区/active。否则在 B 会话里不带 root 调用 `novel_init`，会先解析到 A，然后报 `PROJECT_EXISTS`，或者在 A 里错误地尝试建书。显式 `project_root` 仍然优先；创建成功后再绑定当前会话。

### 7.2 什么时候读取/失效

- 每次不带 `project_root` 的工具调用读取绑定；没有内存缓存。
- 绑定 root 不存在：`ENGINE_PROJECT_MISSING`。
- 绑定 root 存在但 `novel.yaml` 缺失、`state/` 存在：允许加载为“损坏项目”，让 status/amend 修复；身份校验跳过。
- 绑定 root 存在但没有 `novel.yaml` 也没有 state：`ENGINE_PROJECT_NOT_FOUND`（不是 missing，避免把空目录当项目）。
- 绑定 `project_created_at` 与当前项目不同：`ENGINE_PROJECT_IDENTITY_MISMATCH`。
- 不自动删除绑定；只有 `/novel unbind` 或显式覆盖才改变。

### 7.3 子会话/子代理

- 每个 `SessionId` 独立；子代理会话不会继承父会话绑定。
- 子代理调用工具时显式传 `project_root`，或由其 cwd 推导；这样不会把父会话的选择带进另一条执行链。
- 若未来要“子会话继承”，应作为显式 `inherit` 选项，不在 0.2.2 默认。

### 7.4 为什么读操作也绑定

- 模型先 `novel_status {project_root: B}` 再 `novel_brief` 不带 root，是常见链路；读时绑定能让后续调用落到 B。
- 显式 root 是调用者的明确意图；比“猜 active”安全。
- 如果用户只是想偷看另一本，不希望在后续写入中延续，可以看完执行 `/novel unbind` 或再传回原 root。文档会写清。

## 8. 多项目注册与自动登记

### 8.1 自动登记时机

- `novel_init` 成功；
- 有 Agent 会话的工具/命令调用中，显式 `project_root` 成功加载；
- 有 Agent 会话的工具调用中，工作区唯一候选成功加载；
- `/novel use <path|title|.>` 成功绑定后 best-effort 自动登记（不改变 active）；
- 以上都只写 `stateDir/projects.yaml`，**不写项目目录**；**面板读取不触发登记写入**（面板仍是只读 GET）。
- 实现上，`load()` 只在 `callerContext` 有 `sessionId` 时做自动登记；`panelSnapshot()` 使用 `loadAt` 且不调用 `recordSelection`，所以面板只读。`projectError !== null` 的 damaged 项目不绑定、不登记。

自动登记是 best-effort，且是幂等的：已存在同一 `root` 且 title/created_at 一致时不重写。同 `root` 但 `created_at` 不同时，视为“原路径换了另一本书”：自动登记**不覆盖**已有行；需要更新登记行时，走显式 `register`/`activate`。只登记 `projectError === null` 的健康项目；`novel.yaml` 缺失的 damaged 项目不自动登记（已有行保留，面板标 `damaged`）。这样面板能发现用户实际用过的项目，而不需要每次手工 `register`。

### 8.2 注册语义

- `register`：用 `loadAt`（维护读取，**不写会话绑定**）取 title/created_at，按规范化 root upsert；不改变 active。同一 root 的旧行会被更新：`title`/`updated_at` 刷新；若 `created_at` 不同，返回 `replaced: true` 并明确提示“原路径已换成另一本书”，但**不改任何会话绑定**；旧绑定仍按 `IDENTITY_MISMATCH` 拒绝。
- `activate`：用 `loadAt` 验证存在 → register → 写 active。**只影响面板默认**，不绑定当前会话；register 返回 `replaced` 时同样提示，但仍只改 active。不能调用会触发会话绑定的 `load()`，否则 admin 命令会把当前会话一起改掉。
- `register`/`activate`/`use` 遇到 `projectError !== null`（novel.yaml 损坏或缺失）时拒绝更新登记/绑定，先用显式 `project_root` 的 `novel_status` + `novel_amend` 修复；绝不把占位标题或 epoch `created_at` 写进元数据。
- `forget`：只删除注册行；如果 active 等于它，置 null；不删项目目录、不删会话绑定。
- `list`：返回 root/title/active/`state: ok|missing|damaged`/`created_at`；列表不加载整本书。
- `scan --register`：显式批量登记健康候选；不改 active、不绑当前会话；详见 §8.5。

### 8.3 多项目与标题冲突

- 项目唯一键是规范化 root，不是标题；同名书允许存在。
- `/novel use <title>` 命中多个时返回候选 root，要求用路径；不按 active 猜。
- 面板下拉显示 `《标题》 — /path`；同名时路径可区分。

### 8.4 active 的定位

- `active` 降级为“面板默认查看项目”和“无 Agent 调用的默认项”。
- 有 Agent 的多项目场景，active 不参与静默选择。
- 这是 0.2.2 最重要的行为变更，必须写进 README 与 CHANGELOG 的 **Changed**。

### 8.5 显式扫描：`/novel scan [--register]`

**定位**：扫描是“帮用户发现并登记”，不是新的默认选择器。它不改变会话绑定，不改变面板默认，也不在后台运行。

- 扫描范围只包括：`cwd` 自身、`cwd/novel`、`cwd` 的直接子目录；不做祖先回溯、不递归、不跟随符号链接目录。
- 复用 §6.4 的候选枚举：`project-selection.ts` 提供 `scanWorkspace(cwd)`，`discoverWorkspace(cwd)` 用同一份枚举再做 one/many/none 分类，避免两套扫描规则。
- 候选上限 50 个；`scanWorkspace` 返回 `{ candidates, truncated }`；`truncated === true` 时明确提示“只显示前 50 个，请缩小工作区”，不静默截断。
- 每个候选只做轻量头部读取（`novel.yaml` 的 `title` / `created_at`）与 `inspectProject` 状态判定，不构建完整 Snapshot；`damaged` 也列出但不读取正文。
- 输出字段：`title`、`root`、`state: ok|damaged|unreadable`、`registered`；`--register` 时额外输出 `identity_changed`；`not-project` 不作为候选行显示；排序为 cwd、cwd/novel、其余直接子目录按名称。
- 普通 `/novel scan` **只读**：不写 `projects.yaml`，不写 `session-bindings.yaml`，不写项目。
- `--register` 只登记 `state === 'ok'` 的候选；新增 root 走 `register` 的正常校验（可能构建一次 Snapshot）与元数据锁，已有 root 按下面的 `already` 语义处理；单条失败不中断整批，最终汇总 `added / already / skipped` 及原因。
- `already` 的精确语义：`root` 已存在，不新增行。`created_at` 相同、仅 title 变化时，`already` 且刷新 `title`/`updated_at`；`created_at` 不同时仍归 `already`，但**不覆盖登记行**，该候选带 `identity_changed: true`，提示需显式 `register`/`activate` 确认。`added` 只表示新增 root；`skipped` 只表示 damaged/unreadable。
- `--register` **不设置 active、不绑定当前会话、不选择工具默认项目**；登记后仍需 `/novel use` 或显式 `project_root` 才会改变写作项目。
- 扫描命令不需要 Agent 会话；缺少 cwd 时返回普通命令错误“请在项目工作区中执行 /novel scan”，不新增错误码。`--register` 也是命令级写元数据，不经过正文写门控。
- 不在 `scan` 中自动调用 `load()`，避免“看一眼就自动登记/绑定”；登记只发生在显式 `--register`。

## 9. 项目删除、移动、替换

### 9.1 状态分类

`inspectProject(root)` 返回：

| 状态 | 判定 | 处理 |
| --- | --- | --- |
| `ok` | 目录存在 + `novel.yaml` 可读 | 正常加载 |
| `damaged` | 目录存在；`novel.yaml` 缺失/不可读，但 state/正文等证据存在 | 允许 status/amend 修复；写操作继续由现有门控 fail-closed |
| `not-project` | 目录存在，但没有 `novel.yaml` 也没有项目证据 | `PROJECT_NOT_FOUND`，不当作已删除项目 |
| `missing` | 目录不存在 | `PROJECT_MISSING`（会话绑定）/`PROJECT_NOT_FOUND`（显式参数） |
| `unreadable` | 权限/IO 错误 | 原错误码 + 修复提示 |

### 9.2 各种删除场景

| 场景 | 行为 |
| --- | --- |
| 项目目录被 `rm -rf` | 绑定保留；工具返回 `ENGINE_PROJECT_MISSING`，附 root、最后标题、修复动作；不自动切到 B；不自动 `novel_init` |
| 项目被移动到新路径 | 旧 root 报 missing；若注册表里有同 `created_at` 的其他 root，工具错误提示 `moved_to`；面板只显示“项目不在了”和候选列表，不猜移动目标；不自动跳，用户 `/novel use <new>` 或 `project_root` |
| 项目被重命名但还在原路径 | `created_at` 不变，正常；绑定 title 可更新（下次显式绑定时） |
| 原路径被另一本书占用 | `created_at` 不同 -> 工具返回 `ENGINE_PROJECT_IDENTITY_MISMATCH`，禁止写入；显式 `register`/`activate` 可更新登记行并返回 `replaced: true`，但**不改绑定**；旧绑定需重新 `/novel use` 后才能切到新书 |
| 项目所在磁盘/挂载暂时离线 | 与删除同样报 missing；恢复挂载后同一绑定自动可用；不清绑定 |
| `novel.yaml` 被删但 state 还在 | `damaged`；允许 `novel_status`/`novel_amend` 修复；不自动重建 `novel.yaml` |
| 写事务进行中目录被删 | 现有事务 fail-closed；返回 `TXN_ABORTED`/IO 错误；不自动重建；建议从备份/文件快照恢复 |
| 面板正在看这本书时目录被删 | 面板返回 `missing` 状态，保留项目选择器；不自动切到其他书 |

### 9.3 不做的事

- 不自动删除注册行（目录暂时离线会误删）。
- 不自动删除会话绑定（删除后恢复目录就找不回来）。
- 不自动把 active 改到另一本。
- 不自动创建空项目“占位”。
- 不在面板提供“删除项目”按钮。

### 9.4 显式清理

- `/novel unbind`：清当前会话绑定；项目与注册表不动。
- `/novel admin novel_registry_forget {"root":...}`：只清注册行；项目、绑定不动。
- 若绑定指向已删除项目，用户可以先 `unbind`，再 `use` 新项目；或直接 `use` 新项目覆盖绑定。
- 后续版本可加“清理失效登记”，但必须是显式命令，且先展示将删除的行。

## 10. 面板 v4：项目选择器与缺失状态

### 10.1 数据流

```text
浏览器 NovelPanel
  -> GET novel-workshop?root=<encodeURIComponent(root)>   (可选)
  -> panelHandler 解析 query
  -> engine.panelBundle({ root })
  -> 返回 projects[] + selection + summary/chapters/gates/resume 或 missing
```

- 面板仍然只读；不新增 POST/PUT，不写项目、不写注册表、不写会话绑定。浏览器侧只写 `localStorage` 查看偏好和剪贴板，均不影响任何写作项目。
- `resume` 是 v4 payload 内由现有状态投影生成的只读文本，不是新端点；面板复制按钮只写浏览器剪贴板。
- `root` 只接受**注册表中已有**的项目、当前 `active` 指向的项目，或恰好等于配置 `projectRoot` 的项目；其他路径返回 `missing.reason='not_registered'`，不读取任意路径。配置项是管理员显式配置的受信路径，不需要为了看面板先写注册表。
- `projects[]` 至少包含注册表行、配置项和旧 active 指向的 root（去重）；`registered` 标记它是否真的在注册表里，避免旧数据里的 active 在面板里消失。
- `REMOTE_VERSION` 从 3 升到 4；旧标签页显示“需要刷新”。

### 10.2 DTO

```ts
interface ProjectOptionDto {
  root: string
  title: string
  active: boolean
  registered: boolean
  state: 'ok' | 'damaged' | 'missing' | 'unreadable'
}

interface PanelSelectionDto {
  root: string | null
  source: 'query' | 'active' | 'single' | 'config' | 'none'
}

interface PanelMissingDto {
  root: string
  title: string
  code: 'ENGINE_PROJECT_MISSING' | 'ENGINE_PROJECT_NOT_FOUND'
  reason: 'missing' | 'not-project' | 'damaged' | 'not_registered' | 'unreadable'
  hint: string
}

interface PanelPayloadDto {
  schemaVersion: 4
  projects: ProjectOptionDto[]
  selection: PanelSelectionDto
  summary?: SummaryDto
  chapters?: ChaptersDto
  gates?: GatesDto
  resume?: { text: string }
  missing?: PanelMissingDto
  empty?: true
  error?: string
}
```

`SummaryDto` 增加 `root: string`，面板标题区可以显示当前路径。`resume.text` 与 `/novel resume` 使用同一个纯格式化函数生成；没有 ready 项目或缺 `nextTool` 时缺省，不伪造文本，复制按钮隐藏。

### 10.3 面板状态机

| 状态 | 条件 | UI |
| --- | --- | --- |
| `loading` | 首次加载/切换项目 | 骨架 |
| `ready` | 有 summary | 正常面板 + 项目选择器；若选中项 `state: damaged`，顶部加一条“项目定义不可读，先 novel_state/amend 修复”的提示，不把 damaged 伪装成正常 |
| `choose` | `projects.length > 0` 且 `selection.root === null` | “发现多本书，先选一本”；列出项目按钮/下拉 |
| `missing` | `missing` 存在 | “项目不在了”；显示 root/原因/建议；保留选择器 |
| `empty` | `projects.length === 0` | “还没有项目”，提示 `novel_init` |
| `outdated` | schemaVersion 不匹配 | 要求刷新 |
| `error` | 请求失败/注册表损坏 | 错误 + 重试 |

### 10.4 交互

- 标题区右侧、教程和刷新按钮旁增加项目选择器（原生 `<select>`，带 `aria-label="切换项目"`）。
- 选项：`《标题》`；同名附路径尾段；`state !== 'ok'` 标记“（目录不存在）/（待修复）”。
- 选择后：
  - 只更新面板 `selectedRoot`，请求 `?root=...`；
  - 写入 `localStorage` 键 `nwe.panel-root.v1`；
  - 不调用 `activate`，不写会话绑定。
- 刷新时优先用 `selectedRoot`；若 `missing.reason` 是 `not_registered`（例如旧 localStorage 指向已从注册表移除的路径），清掉该偏好，用同一响应里的 `projects` 回退到 active/唯一项目并重新请求；若只是 `missing`（登记还在、目录不在），**保留**偏好，等目录恢复。
- 多项目且没有查询参数/localStorage/active 时，显示 `choose`，不默认 A；配置 `projectRoot` 若正是这些多项目之一，也不强行默认它。
- 项目选择器在 `missing` 状态仍可用，用户可切到其他书。
- 响应竞态：每次请求带递增 `requestId` 和 `AbortController`；旧响应回来时丢弃，避免快速切换时把 A 的数据显示在 B 的标题下。
- `ready` 状态在“下一步”卡旁增加“复制续写指令”按钮；文本来自 `resume.text`，只调用浏览器剪贴板，不触发任何写请求。
- 移动端：选择器在标题下方占满一行；不改变现有滚动与教程弹框。

### 10.5 面板不做的

- 不提供“设为当前会话项目”按钮（面板不知道会话，也不应跨层写绑定）。
- 不提供“删除/忘记项目”写按钮（仍走命令）。
- 不显示正文、不显示 token、不读取项目外路径。

### 10.6 完整卷视图

## 11. 命令与工具契约

### 11.1 工具

- 工具数量保持 **28**，操作数保持 **32**。
- `/novel scan`、`/novel resume` 是命令，不进入工具 schema，也不改变工具/操作计数。
- `novel_init` 的 root 只来自显式 `project_root` 或配置 `projectRoot`；不从会话绑定/工作区/active 推导，避免在 B 会话里把新书建到 A。创建成功后才写绑定。
- 所有 `project_root` 描述改为：

```text
Project root. Passing it selects this project for the current session and persists the
choice. When omitted: session binding -> unique project in the workspace -> single
registered project -> error. Multiple projects require an explicit choice.
```

- 例外：`novel_word_count` 的纯文本模式与 `novel_diff` 的 `before`+`after` 纯文本模式不读取项目，也不绑定会话；这两个工具在 schema/文档中单独标注“project_root 仅用于项目模式”。这样保留它们“无项目也能算字数/做文本 diff”的既有契约，不把纯工具变成项目写入口。

- `novel_status` 的文本输出增加一行：`项目根 <root> · 选择来源 <session|workspace|explicit|...>`，让模型能发现自己读错书。`/novel status` 使用同一个 `StatusReport.selection`，不另算一套。
- 工具适配层新增调用上下文：

```ts
interface EngineCaller {
  sessionId?: string
  cwd?: string
}
```

- `makeGuarded` 在调用 engine 前解析 `exec.agent?.id` 与 `workingDirectory.ensure(exec.agent, exec.signal)`；用 `engine.withCaller(caller, ...)` 包住 `withSignal`。
- 没有 `agent` 的测试/旧调用保持无 caller，走非 Agent 解析。

### 11.2 命令

新增 `/novel` 子命令（命令不算工具/操作计数）：

```text
/novel projects                 列出项目；* 当前会话，P 面板默认，! 目录缺失
/novel current                  当前会话绑定的项目与来源
/novel use <path|title|.>       绑定当前会话；不改变面板 active
/novel unbind                   清除当前会话绑定；不删项目
/novel scan [--register]        扫描工作区候选；--register 只登记健康项目
/novel resume                   输出可粘贴的续写指令；只读，不绑会话
```

- `/novel use .`：按当前会话 cwd 的工作区发现规则找唯一项目；多候选报错。
- `/novel use <title>`：注册表内精确标题匹配；多个则报错并给路径。
- `/novel use <path>`：加载成功才绑定；失败保留旧绑定。路径允许包含空格：`use` 后面的整段 remainder 作为一个参数解析，只有首尾成对引号会被去掉；不要按空白拆成多个参数。
- 参数先按“存在的路径”尝试（绝对路径、相对 cwd 的路径、`.`），不存在再按标题精确匹配；两者都不中时报 `PROJECT_NOT_FOUND`。
- `/novel current`：没有绑定时说明“未绑定；将按工作区/唯一项目推导”，不是“当前是 A”。
- `/novel projects` 不需要 Agent；`use/current/unbind/resume` 需要 Agent，缺少会话时报错。
- `/novel scan` 不需要 Agent，但需要可用的 cwd；`--register` 只写注册表，不改 active、不绑会话。详见 §8.5。
- `/novel resume` 需要 Agent；它使用当前会话的选择结果生成文本，不写绑定。详见 §11.3。

`/novel admin novel_registry_activate` 语义：

- 加载并登记项目；写 `active`；
- **不绑定当前会话**；
- 输出提示“active 只影响面板默认；当前会话请用 /novel use 或 project_root”。

这是行为变更，写进 CHANGELOG。

### 11.3 scan / resume 契约

#### `/novel scan [--register]`

- 语法：只有可选布尔参数 `--register`；不接受任意路径，不递归扫描。工作区由命令调用上下文的 cwd 决定（有会话用会话 cwd，无会话用命令工作目录）；没有 cwd 时报“请在项目工作区中执行 /novel scan”。
- 扫描范围、候选上限、输出字段和登记语义以 §8.5 为准；普通 scan 不写 `projects.yaml`/`session-bindings.yaml`，`--register` 只登记 `ok` 项目。
- 输出一行提示“扫描到 N 个候选；M 个已登记”，再列候选；没有候选时给“未发现项目”，并提示 `novel_init` 或检查 cwd。
- `--register` 结果按候选逐条汇总：`added`、`already`、`skipped`（damaged/unreadable）；`already` 中含 `identity_changed` 的候选不覆盖登记行，并在汇总中单独提示；不因单条失败回滚其他已登记项。
- 不设置 active、不绑定会话、不改变面板默认；命令末尾明确提示“登记不等于选择，写作请用 /novel use 或 project_root”。

#### `/novel resume`

- 使用与工具相同的当前选择结果（会话绑定 → 工作区 → 唯一项目/配置）；没有可用项目时返回 `PROJECT_NOT_FOUND`，多候选时返回 `PROJECT_AMBIGUOUS`，并列候选。
- **只读**：不写绑定、不写注册表、不写项目；不调用 `novel_init`，不修改 current chapter。
- 文本由 `formatResumePrompt(input)` 纯函数生成；`input` 只含 title/root/chapter/stage/nextTool。`/novel resume` 从 `StatusReport` 映射，面板从 `SummaryDto` 映射，两者共用同一模板，不额外加载项目。
- 文本必须包含：书名、绝对 root、当前章、阶段、下一步工具、首调用显式 `project_root`、只操作本项目、先核对书名。不得包含正文、token、其他项目路径。
- 文本模板：

```text
请继续《{title}》。
项目根：{root}（第一次工具调用必须显式传 project_root={root}）。
当前第 {chapter} 章，阶段 {stage}。
下一步：{next_tool}。
先调用 novel_status 核对项目根与书名，再按 novel_pipeline 的下一步执行；
只操作这个项目，不要读取或写入其他书。
```

- `resume` 是“提示词生成器”，不是新的状态源；章节/阶段/下一步全部来自已有状态投影（`StatusReport` / `PanelSummaryDto`），不另算一遍。
- 面板复制按钮只复制 `resume.text`；复制成功/失败都不改变任何项目状态。

### 11.4 命令上下文

- `createCommands` 的 handler 在注册时由 `apply()` 包装：从 `invocation.agent` 取 `SessionId`，从 `workingDirectory` 取 cwd，`engine.withCaller` 后执行。
- 直接调用 `createCommands(engine)` 的旧测试没有 caller，仍走非 Agent 解析；新增命令测试显式传 agent。
- 命令仍只调用 `EngineService`，不直接读文件。

## 17. 风险与处置

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 多项目无上下文直接报歧义 | 单项目用户无感；多项目首次多一步 | 唯一项目/唯一 cwd 自动；错误里给可直接执行的 `/novel use`；文档示例 |
| `active` 语义改变 | 旧用户以为 activate 会切换工具 | CHANGELOG Changed；命令输出明确提示；`/novel current` 显示来源 |
| cwd 误判 | 工作区里有多个项目 | 只做有限发现；多候选报错；显式绑定优先 |
| `created_at` 为空/重复 | 身份校验变弱；复制项目会共享 `created_at` | 空值降级为路径 + 标题；复制项目不自动同步，文档要求重新 `/novel use`；替换检测只提示，不自动跳 |
| 同一物理项目经符号链接/真实路径分别登记 | 按 `path.resolve` 是两个 root，可能出现两个面板行或歧义 | 0.2.2 的词法键设计；文档要求固定使用一个路径，不把两类路径自动合并，避免 symlink 别名改变用户选择 |
| 注册表/绑定文件损坏 | 无显式 root 的解析无法完成；显式 root 仍可只读 | 无 root 解析 fail-closed + 明确修复路径；显式 root 读取 best-effort、不更新损坏绑定；正文不受影响；不静默重建 |
| 元数据跨进程写竞争 | 丢绑定 | 进程内 mutex + `FileLock`；原子写；测试并发 |
| 面板 localStorage 残留 | 打开已删项目 | 服务端返回 missing；选择器可切；不自动删偏好 |
| 面板请求竞态 | 标题与内容错配 | AbortController + requestId；旧响应丢弃 |
| `/novel scan` 扫描范围或误登记 | 大工作区慢、登记不该登记的项目 | 只扫 cwd/cwd/novel/直接子目录；最多 50；跳过符号链接；普通 scan 不写；`--register` 只登记 `ok`，逐条汇总 |
| `resume` 文本在复制后过期 | 项目移动/换书后照旧文本执行 | 文本要求首调用显式 root 并先 `novel_status` 核对；解析失败报 missing/mismatch，不自动回退 |
| 完整卷列表过长 | 面板滚动区域过高或渲染变慢 | 全量渲染但放在 `max-height` 滚动容器；不用“展开更多”隐藏数据；测试 9 卷以上，不设新的截断 |
| 剪贴板 API 不可用 | 复制失败 | 展示只读文本供手动选择；不调用服务端，不把复制失败当成项目错误 |
| `service.ts` 过大 | 继续膨胀 | 把选择逻辑抽到 `project-selection.ts`；service 只做编排 |
| 自动登记写全局文件 | 用户意外 | 只写 stateDir；不写项目；幂等；best-effort；文档说明 |
| 模型显式传错 `project_root` | 仍会写错书 | 绑定只消除“默认串书”，不能消除显式错误；`novel_status` 显示 root/source，文档要求模型核对；后续可评估“跨绑定显式切换需确认”的写保护，不在 0.2.2 默认加，避免破坏显式覆盖 |

## 18. 反熵与决策记录

- **Retirement：`lastRoot` 采用 delete-first。** 它是内部全局状态，没有合法的外部契约需要保留；保留只会让 A/B 继续串。
- **`active` 不删除，但降级。** 它仍有合法职责：面板默认与无 Agent 默认；删除会破坏现有注册表语义。职责收窄，不是兼容例外。
- **不新增 `workspace-bindings.yaml`。** 工作区是会话 cwd 的派生，不是第二份持久化 owner；新增会与 session binding 冲突。
- **不新增 `project_id`。** 用已有 `created_at` 做身份，避免项目 schema 迁移；弱点在 §17 标注。
- **`scan` 不新增发现 owner。** 复用 `scanWorkspace`/`discoverWorkspace` 的同一套有界枚举；普通 scan 不写，`--register` 只写既有注册表。
- **`resume` 不新增状态 owner。** 它只是状态投影的文本格式化，与面板共用 `formatResumePrompt`；不重新计算章节/阶段。
- **完整卷视图不新增 wire 字段。** 复用已有 `book.volumes`，只删除 UI 截断；不引入第二套卷数据。
- **面板不写项目。** 选择器只改 GET 查询与浏览器偏好；复制只写剪贴板；写绑定仍只由工具/命令触发。
