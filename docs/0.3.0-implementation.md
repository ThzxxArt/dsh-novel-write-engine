## 2. 运行链路

```text
novel_init
  -> initProjectV2 (studio.yaml + bible/outline/manuscript/state + SQLite)

novel_run kind=chapter
  -> Director.createChapterRun
  -> Scheduler.run
       plan
       draft
       review.story | review.character | review.prose | continuity.precheck  (fan-out)
       review.merge (kernel gates PG/EG)
       pass -> continuity.final -> polish -> approve -> human gate
       fail -> revise -> reviews (max 3 rounds)
  -> host novel_approve
  -> archive (StateDelta + canon + manuscript atomic write + hash readback)
```

BookRun：`bible -> bible gate -> outline -> outline gate -> worldbook`。

MarketRun：Radar 只写 `MarketBrief`，不写 canon。

ReviewRun：对已有章节重跑三审 + continuity，不写正文。

## 4. 关键实现说明

### 4.1 为什么正文仍在文件

SQLite 只存编排、索引、审计和检索；正文、bible、outline、canon 仍是可 git、可 diff 的文件。Artifact blob 内容寻址存放在 `.studio/artifacts/`，DB 只存引用和 hash。

### 4.2 门控先于写盘

`evaluateGates` 是纯函数；`onArchive` 只有在 Draft、Review、Continuity、Decision 都存在且 hash 校验通过时才写 manuscript/canon；写后 readback 不一致则 run failed。

### 4.3 角色权限

`src/contracts/roles.ts` 定义 canWrite；`assertRoleCanWrite` 在每次 agent artifact 提交前执行；Drafter 不能提交 ReviewReport/Draft 之外的 artifact，Critic 不能提交 Draft，Archivist 只能提交 StateDelta。

### 4.4 规则包 v2

默认包 `schema_version: 2`。编译器保留读取 v1 包的能力，用于旧包校验/导入测试；运行时只发布 v2。AI_TONE 的检测顺序、密度和跨章重复见 `docs/0.3.0-rulepack.md`。

### 4.5 类型体系

`taxonomy/taxonomy.yaml` 是唯一源；`compileTaxonomy` 做 12 条编译断言；`validateGenreSelection` 做组合校验；`resolveGenreProfile` 按 `tag > sub > major > global` 合并。

### 4.6 工作台

React 19 + TanStack Query + Zustand + Radix Tabs + CodeMirror + React Flow + Recharts + cmdk + Sonner。所有写操作走 `/api/novel-write-engine/v8/action`，不直接改文件。

### 4.7 MCP

DSH 0.2.2 的 MCP 宿主包不在本仓库依赖内，因此 0.3.0 提供 HTTP JSON-RPC MCP endpoint：

```text
POST /api/novel-write-engine/v8/mcp
  initialize
  tools/list
  tools/call
```

写工具要求 `human_approved: true`；`novel_approve` 需要一次性 token。

### 4.6 第一轮全量 review 的根治修复

- 子 agent 成功路径也会 `dispose()`，不再泄漏会话。
- 运行中每 30s 续 lease；abort 立即取消；过期 lease 重排；archive 增加 recovery marker，崩溃后不会出现正文已写、canon 未写或 draft 未批准。
- review/continuity/polish 的 `base_hash` 由 prompt 注入并在 kernel 校验；stale 报告无法进 gate。
- blocker 只能 `fixed`，且修复证据必须来自当前正文；DB finding 状态会回灌到 gate 的 review/continuity 报告。
- `WorldbookPatch` 真正落盘到 characters/world/glossary/codex，并重建 FTS 索引。
- 全局 SQLite registry、backup safety restore、active-run 保护、SSE/错误 JSON 统一、API enum/数字校验补齐。
- 工作台：版本 diff 只列 Draft、恢复版本、未保存草稿不被 SSE 覆盖、Run Board 7 列、DAG 边、Inspector 移动端抽屉、发布 profile、Doctor/备份/角色路由。

### 4.7 第二轮全量 review 的根治修复

- 人工门收据绑定 `target_artifact_id` + `target_version`；approve 后修改 Draft 再归档会被拒绝。
- `Decision` 只有 `preset=human-gate/model=human` 才算人工收据；showrunner 角色提交的 Decision 只是建议。
- `director.decide` 先验证 token，再执行发布/落盘，最后关 gate；发布失败 gate 保持可重试。
- `edit` 必须携带 `editedContent`，否则拒绝；编辑稿先过确定性格式门。
- revise/redraft 必须回填当前 Draft 的 `base_artifact_id` 与 `expected_hash`；stale 稿不能覆盖。
- blocker 标 fixed 时必须有当前正文证据；gate 的 PG-08 会再次校验。
- `artifact.restore` 只允许创作类 artifact，Decision/Export/Review/Continuity 等审计记录 append-only。
- `ArtifactStore.submit` 幂等重试返回真实内容；同 task 跨 kind 复用直接冲突。
- `PG-07` 只产生一条结果；`EG-01/02/05/08` 从形式检查改为指纹、落点、去对白 POV、真实 polish patch 校验。
- 归档阶段 AI 味 advisory 升级为 blocker；恢复 marker 与 canon 不一致时拒绝覆盖。
- `novel_rewind`（artifact/chapter/run）与 `.studio/snapshots` manifest 补齐方案 §8.6。
- MCP `novel_export kind=publish` 走 Publish Gate；API/工具枚举、数字、chapter、limit、comment、settings 边界补齐。
- `settings.save` 的 models/budgets 改为与当前配置合并，避免局部编辑把 12 个角色路由清空。
- 新增 fast-check 不变量、门禁收据、artifact 边界、快照/rewind、路由适配、API 成功/失败全链、工具/角色 scoped 工具、调度预算/重试、导入边界、项目布局边界等测试。

### 4.8 第三轮全量 review 的根治修复

第三轮用真实 `agnes-2.5-flash` 跑完整 chapter 链路，暴露出前两轮“测试全绿但真实模型永远过不了门”的问题：

- **`ILLEGAL_QUOTE` 规则纠偏**：0.2.13 已把中文弯引号归入 `chinese_punct`，但格式规则仍把 `“”「」『』` 全部判为 blocker，任何有对白的真实章节都过不了 PG-04。现在只禁 ASCII 直引号 `"`/`'`，中文引号合法；测试同步改为 ASCII 反例 + 中文正例。
- **预提交门控**：schema 通过后立即执行格式、role 维度所有权、总分算术、引文逐字、章卡 hook/cast 落点检查；失败时带具体原因触发一次 repair，不再让整轮评审为一个可修的段落长度浪费。
- **机械排版**：ASCII/直角引号统一为中文引号，超长段落按句号切分；只改排版不改字，避免模型反复写 130 字段落。
- **章卡标题**：plan 阶段即校验「第N章 」+4–8 字；否则 draft 会继承坏标题，整章在 PG-04 失败。
- **polish/EG-08 一致**：polished Draft 不再二次 normalize；EG-08 比较的确定性结果与入库正文完全一致。
- **真实取消**：`run.cancel` 现在通过 scheduler 的活动 controller 真正 abort 正在进行的模型调用，而不是只改 DB 状态。
- **rewind 归档失效**：章节重写前把 `manuscript/ch-XXXX.md` 移入 `.studio/history`，`status.stage` 不再错误停留在 `archived`，导出也不会读到旧稿。
- **快照自校验**：`snapshot.verify` 校验 manifest 自身 `content_hash`、文件 bytes、路径逃逸和快照后新增文件，不再只信任清单内的 hash。
- **artifact 幂等收紧**：同一 task 重复提交相同内容返回旧 artifact；提交不同内容直接 `ARTIFACT_CONFLICT`，不再静默丢弃第二次输出。
- **人工编辑语义**：chapter gate 的 `edit` 保存新 Draft 后关闭旧 run 并分支 review run（下一轮评审以新 hash 为准）；bible/outline gate 支持 `editedArtifact` 并直接落盘；publish gate 明确拒绝 edit。工具层的 `editedContent` 之前漏传，已一并修复。
- **门控重评**：人工门打开前总是重新跑 gate，不再复用历史 gate 结果让未清 blocker 的稿子被批准；读取侧只取每个 gate 的最新一次裁决，避免旧的 fail 永久阻塞导出。
- **advisory 证据**：无法定位的 advisory 证据会被丢弃，blocker 仍要求逐字正文引用；短引文自动扩展到所在完整句，减少无意义 repair。
- **工作台**：人工门补齐“驳回”；Run Board 7 列保持可横向滚动的可读宽度。

新增质量门：

- `pnpm check:test-pairs`：每个 spec 必须有负向断言；32 个 API action、6 个 MCP tool、10 个 studio tool 必须至少被测试引用一次。当前 144/149 文件通过；22 个历史文件的测试标题仍偏“成功路径”命名，但文件内已有负向断言，脚本以 warning 输出供后续整理（第四轮已全部清零，见 §4.9）。
- `pnpm test:live-model`：opt-in 真实模型验收（Agnes OpenAI-compatible），跑 plan → draft → 3 review → continuity → polish → Chapter Gate；默认 `pnpm test` 不联网。

### 4.9 发布前第四轮 review 的根治修复

- **方案 §8.5 落地**：task 重试耗尽后 task 仍为 `failed`，run 进入 `awaiting_human`；`status.next` 在没有 pending gate 时返回 `run.cancel`（“人工处理：取消后重开”），不再给出无效的 `run.tick`。
- **旧项目导入器真实缺口**：缺失 goal/conflict/turn/outcome/hook 时生成空字符串，导入后 `ChapterPlan` 无法加载；缺失 title 时生成不带空格的 `第N章`。现在全部给可读占位值，并在报告中保留警告。
- **canon 字符串实体**：旧 `state/world.yaml` 常把 `artifacts/rules` 写成字符串数组，直接塞入 canon 会让 `canon.yaml` 自身 schema 失败；导入时统一转成 `{ name }`。
- **空 patch 崩溃**：`updateRun` / `updateAssignment` 收到全 undefined patch 时 Drizzle 抛 `No values to set`；现在作为 no-op 返回。
- **损坏 task input**：`parseTask` 对非法 JSON 回落 chapter 1 / round 1，而不是让 task 重试到耗尽。
- **§14.5 目录覆盖率全部达标**：kernel 97.9/90.0/95.7、studio 93.4/85.2、storage 95.8/92.6、contracts 97.1/100、agents 96.4/80.5、adapters 95.5/80.6、client 94.6/86.8；`vitest.config.ts` 按方案阈值上锁，不再使用低阈值。
- **标题级反例清零**：`check:test-pairs` 的 22 个历史文件名/标题改为负向语义或补充负向断言，现在 149/149 spec 通过且无 warning。
- **真实模型 smoke**：Agnes `agnes-2.5-flash` 的 plan/draft 真实调用跑完整 DAG 到 Chapter Gate（结果见 §7）。
