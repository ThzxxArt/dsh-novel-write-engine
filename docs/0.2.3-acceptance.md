- 升级审计：doctor `legacy-data` 只读标出旧 check、旧 effort、extra 角色、pre-0.2.3 无 anchor、无 advance_log、stale `pipeline.briefs`。

## 6. 未覆盖与边界

- 0.2.3 **不自动迁移**旧项目数据：旧 check、旧 rounds、旧 role、旧 anchor、旧 advance_log 只标 legacy，不静默改写。
- 数字算式已覆盖“同段乘式/人数×单价”，跨段、多单位换算仍留 0.2.4；这已明确写在规则说明里，不是半成品。
- 全操作同错重试指纹已覆盖有 key 的写操作；无 key 的维护操作（如部分 amend）不做指纹，避免误伤修复路径。
- 老 anchor/legacy 数据自动迁移仍不做：缺原句时必须人工确认，0.2.3 只提供 legacy 标记，不伪造迁移。
- `state/briefs.yaml` 读模型在损坏时按“无有效收据”展示，但 `getBrief` 会 fail-closed 拒绝覆盖审计文件；修复或移走损坏文件后才能重新领取任务书。
- 旧标签页会显示“需要刷新”，不兼容 v4 payload；刷新后是 v5。
- 面板截图是静态 payload 渲染，没有在真实宿主里做人工浏览器点击验收；宿主工具挂载与面板 HTTP 路由由 `check:host` 覆盖，客户端 `dsh.client` 清单/工厂由 `check:artifacts` 与客户端测试覆盖，键盘/ARIA 由客户端测试覆盖。
