## 4. 根因与所有权（反熵）

| 根因 | 旧 owner | 新 owner（唯一） | 退役行为 |
|---|---|---|---|
| R1 资源语义 | `current_state.resources`（集合）+ `resource_changes`（增量）两套并存 | 同一 `applyStateDelta` 内显式区分 set/add，并拒绝同章同资源双写 | 隐式「合并即语义」 |
| R2 PG-01 过期不可解释 | `gate` 只比 digest 是否相等 | 同一 digest 生成器给出 `changed` 差集 + `required_tool`；journal 区分 `revision` 与 `intended_revision` | 「stale 就是 stale」 |
| R3 简报 digest | 全文档 + pipeline + rounds | 每阶段一张依赖表（`BRIEF_DEPENDENCIES`） | 「一份 digest 管七个阶段」 |
| R4 简报预算 | protected 全量 + 轮转裁剪 | 每阶段 protected + 必读下限（floor） | 「先清空再说 over_budget」 |
| R5 诊断 | 字符串 message | `EngineError.details`（field/expected/received/allowed/example/nearest） | 只给「不符合」 |
| R6 advisory 身份 | 实例 id 直接当显示行 | 显示按 code 聚合、`instances[]` 带实例 id、确认支持两者 | 「一个 id 一行、勾一条替一条」 |
| R7 台账定位 | 一律 `paragraph` | `{paragraph}` 或 `{ledger, entity}` | 台账问题塞进第 1 段 |
| R8 计数 | effort（journal）、attempts（journal+history）、pipeline（当前章） | 一个 `EffortProjection`，三个视图只做标注 | 三套加法 |
| R9 证据匹配 | 纯 `includes` | `matchEvidence`：引号/空白归一 + 最近片段 + 真段号 | 「找不到就是没写」 |
| R10 计量口径 | brief 有、status 无 | 同一 `WordMetrics` 投影进 brief/status/章卡 | 只在一处说明 |
| R11 台账恢复 | 只有正文/大纲/pipeline | `restoreBackup` 扩展到 `state/*.yaml`，带不变量 | 改错只能手改 |
| R12 旧格式 | 严格 narrow 即损坏 | 读时 `migrateDocument` 归一 + doctor 标注 | 旧章永远不可读 |

| R14 评审修正 | issue 不可变 | `novel_review` 的 amend 模式只改元数据，不消耗轮次 | 只能重开一轮 |
| R15 PG-06 | 场景类型单调 blocker | 章卡优先（card wins），无卡才判单调 | 卡与门控互相锁死 |
| R16 关系/伏笔质量 | 自由文本 + 分散提示 | report 覆盖率 + amend 映射入口 + doctor 建议 | 「uncategorized 也是一种分类」 |

**退役声明（Anti-Entropy）**：

```text
Deletion Class: behavior-retirement
Old Path: 用 current_state.resources 的绝对值再叠加 resource_changes 的增量
New Owner: applyStateDelta 的 set/add 双通道 + 同章同资源双写拒绝
Preserved: 旧文档可读、旧 delta 仍可提交、资源仍是非负整数（除非显式允许）
Retired: 静默累加与静默覆盖
Data Destruction: none（不迁移、不改写历史台账）
```
