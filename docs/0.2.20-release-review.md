# 0.2.20 发布前复审

> 日期：2026-11-25 · 基线：`main` @ `0b1b2c6`（0.2.19）+ 未提交的 0.2.20 改动
> 约束：**不 commit、不 push、不打 tag、不发布**。本文件只记跑过的证据。

## 1. 方法

前六轮查的是「引擎说的和做的不一致」。这一轮查的是另一类问题：**发布这件事本身**。做法是把六个维度
换成发布视角，逐条对：

1. **版本与产物**：`package.json`、`PANEL_VERSION`、`DESIGN.md`、`README.md`、`CHANGELOG.md` 五处是否同一版；
   tarball 里是否带齐运行时文件；干净目录能否装上并用。
2. **升级路径**：README 里承诺的每一步迁移，引擎是否真的接受。
3. **文档自称的数字**：README 里的覆盖率、包体、文件数、截图数，是否还能被任何门禁验证。
4. **对外链接**：npm 页面上的 README 链接是否指向真实地址。
5. **门禁本身**：发布依赖的 18 道门禁是否都能独立跑通，失败时给的是不是可执行的说明。
6. **读模型**：作者完成迁移后，能不能从工具里看到结果。

每条先找证据（读代码、跑命令、写测试），再改，再跑。

## 2. 发现并修复

### 2.1 版本树整体漂移（阻塞发布）

`package.json`、`PANEL_VERSION`、`DESIGN.md`、`README.md` 全停在 `0.2.19`，只有 `CHANGELOG.md` 写着 0.2.20。
按这个状态发版，`npm view` 会拿到 0.2.19、面板会告诉旧标签页「当前就是最新」，README 的升级须知还是上一版的。

修：四处统一到 `0.2.20`；`README.md` 的「最近一版」升级须知按 0.2.20 的破坏性变更重写（见 2.4）；
`DESIGN.md` 的版本行同时改为指向 `docs/0.2.20-*.md`。

### 2.2 版本一致性没有任何门禁（根因）

漂移能发生，是因为**没有东西在看**。`tests/command-reference.spec.ts` 只把 `PANEL_VERSION` 和
`package.json` 绑在一起；`DESIGN.md` 与 `README.md` 的自称版本从未被验证。

修：`scripts/check-docs.mjs` 新增 `version/panel`、`version/design`、`version/changelog`、`version/readme`
四条断言。红灯证据：把 `PANEL_VERSION` 留在 0.2.19 时 `check:docs` 报
`version/panel: PANEL_VERSION is 0.2.19, package.json is 0.2.20`；把 `DESIGN.md` 改回 0.2.19 时
报 `version/design: DESIGN.md does not name the shipped version 0.2.20`。两条都实测过红→绿。

### 2.3 发布必须改测试才能过

`tests/preset.spec.ts` 把 `manifest.version` 钉死成字面量 `'0.2.19'`。每次发版都要改一个与预设无关的测试，
忘改就是全红——这正是发版当晚最容易误判的失败。

修：断言改成「名字对 + 版本是合法 semver + engines 不变」。它验的是「清单是这本插件的清单」，
不是「版本还是上次那个」。

### 2.4 README 的升级须知是上一版的

原文写着「最近一版是 0.2.19，升级前要知道三件事」，三条全是 0.2.19 的内容。0.2.20 的破坏性变更一条都没写，
而其中两条会让升级当天的写作直接卡住：**弯引号书必须声明 `quotes: curly`**（否则 PG-04 立刻拦）、
**自查缺答不再算 pass**（PG-12 拒归档）。

修：重写为五件事（`quotes`、自查缺答、`allow_delete` 移除、`TIME_REGRESSION` 升 blocker、任务书形状），
外加三条「知道就行」的行为变化（raw 上限、diff 上限、`final_check` 双域）。每条都给了可执行的改法。

### 2.5 迁移路径没被验证过（引擎侧）

README 说「用 `novel_amend` 改 `novel.yaml` 的 `quotes`」。实测两件事：

1. 0.2.19 建的书里**没有** `quotes` 键，所以 `patch` 用 `replace` 会被拒：`replace target "quotes" does not exist; use add`。
   迁移写法必须写清 `add`/`replace` 的分工，否则作者第一步就卡住。README 已补上可直接复制的 `add` 调用。
2. 改完之`后，**`novel_status` 里看不到这些开关**：`StatusReport.project` 只有 title/genre/platform/root。
   作者无法确认迁移是否生效，只能靠「下一次被门拦」来发现。

修：`StatusReport.project` 增加 `quotes`（缺省按 `ascii` 显示）、`strict_cross`、`self_check_required`、`style`；
`docs/tools.md` 记入契约；新增 `tests/0224-release.spec.ts` 断言「迁移后 `status.project.quotes === 'curly'`」，
并断言「归档后再改引号口径被拒」。红灯证据：加字段前该断言报 `expected undefined to be 'curly'`。

### 2.6 README 里有一套没人在验的数字

「覆盖率 94.29% / 分支 89.43%」「client bundle 251.38 KB」「hygiene 191 文件」——三个数字全部过期
（实测 94.16 / 89.35 / 269.90 kB / 204 文件），而且**没有任何门禁能验它们**：它们每跑一次就变。

修：README 只留能被门禁验证的数字（测试文件数，由 `check:docs` 实测），其余改为「见验收文档的门禁表」，
并指向 `docs/0.2.20-acceptance.md`。**不写死会变的数字**，就不会有下一次失真。

### 2.7 README 的 7 个 `docs/` 相对链接在 npm 上是 404

`files` 不含 `docs/`（有意，避免把 1.5MB 截图打进包），但 README 用相对路径链接 `docs/tools.md` 等 7 处。
GitHub 上能点，npm 页面上会指到 `npmjs.com/package/.../docs/...`——404。

修：七处全部改成 GitHub 绝对地址（文件用 `blob/main/`，目录用 `tree/main/`）。`check:docs` 仍通过。

### 2.8 验收文档的数字停在实施轮

`docs/0.2.20-acceptance.md` 的 §1 写的是 121 文件 / 1,623 项，与当前工作树差两轮。

修：新增 §6「发布前实测」，给出最终门禁表（130 文件 / 1,738 项、覆盖率、包体、19 道门禁结果与真实书数字），
并保留 §1 作为演进记录。

### 2.9 0.2.20 没有视觉证据目录

`docs/evidence/` 只有 0.2.17 与 0.2.19。

修：`NWE_VISUAL_DIR=docs/evidence/0.2.20 pnpm check:visual` 产出 13 张截图，README 的视觉那条改为指向它。

## 4. 偏差与边界

- **`check:preset` 不能裸跑**：需要 `DSH_BUNDLE_ROOT` 指向宿主 bundle 根。脚本给了提示并以退出码 2 结束，
  但 README 的门禁清单里没有写这个前置条件——本轮补在 README 的验证小节里。
- **`check:visual` 需要外置 Playwright**：本机用 `PLAYWRIGHT_MODULE=<另一个仓库>/node_modules/playwright`，
  Chromium 在 `~/.cache/ms-playwright`。缺工具时脚本以退出码 2 结束（不假装通过）。
- **`check:docs` 读的是 `lib/`**：版本断言在 `pnpm build` 之前跑会拿旧常量比较新 `package.json`，
  失败信息会指向 `PANEL_VERSION`。这是「构建产物必须新于源码」的另一种表达，`prepack` 的
  `check-build-fresh` 已经管住；本轮把它记在这里，避免下次误判为代码问题。
- **真实模型没有重跑**：本版改的是读模型、门禁口径与规则误报，没有动 P1–P8 的调用协议；0.2.19 的
  真实模型证据（含 `agnes-3.0-flash` 免费额度 429 的失败披露）继续有效，但**不声称本版跑过**。
- **Windows 真机仍未验证**：本机只有 WSL/Linux。`docs/0.2.20-acceptance.md` §3 有完整清单。

## 5. 发布前还剩什么

代码与文档已经是可发布状态；剩下的都是**需要仓库写权限的动作**，按约定没有执行：

1. `git add -A && git commit`（建议信息：`release: 0.2.20 read models stay honest`）。
2. `git tag v0.2.20 && git push origin main --tags`，等 CI 全部通过。
3. `npm publish`（tarball 已由 `check:install` 验证：0.2.20、42 文件、干净安装）。
4. GitHub Release 正文取 `CHANGELOG.md` 的 0.2.20 段。
5. 社区源同步（0.2.19 时 npmmirror 落后，需要手动触发同步）。
