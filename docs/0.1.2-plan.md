## 1. 目标与成功判据

**目标**：把 0.1.1 的“单章可归档”推进到“长书可运行、损坏可恢复、契约不可绕过”，同时不把 0.2.0 的书级规划塞进补丁版本。

**成功判据**：

1. P1/P2 的世界计划与章节计划在服务边界做运行时窄化；非法形状、空标题、少于 5 个节拍、短标题、负目标字数零写盘。
2. `novel_rollback` 只能退到当前阶段或更早阶段；P3 → P6 的跳过必须被拒绝。
3. plan/review/check 任一文件损坏时：`novel_status` / `novel_pipeline` 可读，显示 `state_errors`；当前阶段晚于重建点时 `next` 指向 `novel_rollback`，已经处在 P2/P4/P6 时直接指向 brief 与阶段修复工具，避免 rollback 循环；回退后可用既有阶段重建，不需要手改文件。
4. `novel_archive` 对“review 存在但没有 `review_digest`”的 0.1.1 旧数据 fail-closed，给出重新评审路径；不能静默绕过摘要校验。
5. 每个 brief 阶段都有独立上下文预算；受保护内容（正文、当前 plan/review/check、当前章摘要、上一章结尾、项目）不被裁剪；截断项和省略数写入 `context_meta`，并参与 digest。
6. 100 章、100 角色的 fixture 可生成不超预算的 P3/P4/P6 brief；正文与当前计划不被截断，`context_meta.truncated` 可核对。
7. 水词/爽点/感官窗口按非空白字符计数；空格、换行、全角空格不再改变窗口结果。
8. 资源变化校验资源名、符号和数量；仅“文本里出现 200”不再算已交代。
9. `ready_to_archive` 的九相位条显示 P7 进行中，P8/P9 未完成；不能把未发生的 P7 标成已完成。
10. `novel_check` 的 `scope` 真正生效：默认 `content + integrity`，允许只跑 content 或只跑 integrity；未知/空 scope 零写盘。
11. `scripts/check-host.mjs` 在真实临时 profile 中验证 18 个工具可见、一次 `novel_init` 工具调用成功、面板 401→200、remove 后层消失；没有模型凭据时用本地 Messages mock，不伪造真实模型。
12. 全量测试、覆盖率、构建、打包、安装、预设、宿主门全绿；无新增运行时依赖、无 schema bump。

**非目标（0.2.0）**：书级契约、卷/幕/章分层规划、作者故意豁免（intentional dismissal）、RAG/向量库、SQLite、富文本编辑器、自动导演、英文界面、额外技能包。

## 3. 切片与文件

### S1 · 输入契约收口（P0）

**文件**：`src/engine/service.ts`、`src/types.ts`、`src/tools/index.ts`、`tests/engine-extra.spec.ts`、`tests/engine.spec.ts`、`tests/e2e.spec.ts`。

- `initProject`：显式 `author`/`description` 必须是字符串；非字符串零写盘。
- `submitWorldPlan`：`constraints`/`continuity_notes` 为字符串数组；`characters` 为 `{name,role,current_state}` 字符串对象数组；`locations` 为 `{name,layout,capacity}` 对象数组，capacity 为有限数。
- `submitChapterPlan`：标题去掉 `第 N 章` 后 4–8 字；`narrator` 非空；`beats` 5–8 个非空字符串；`opening`/`ending` 非空；`target_words` 正整数且 min ≤ max。
- `submitReview`：issue 的 `dimension` 必须是 rulepack 的 15 维之一；`location` 必须是本章实际段落号；blocker 不得 `waived`。
- `submitRevision`：blocker 不得降级、不得 `waived`；issue 形状仍按现有校验。
- `rollback`：建立阶段序，目标必须 ≤ 当前阶段；`P3 -> P6` 拒绝。
- 工具默认值不替代服务校验；缺省数组可以补 `[]`，但形状错误必须报 `ENGINE_SCHEMA_INVALID`。

**测试**：每个非法输入断言零写盘（`snapshotTree`）；合法输入保持原行为；rollback 前进拒绝、同阶段/后退允许。

### S2 · 损坏状态可恢复（P0）

**文件**：`src/engine/service.ts`、`src/engine/context.ts`、`src/types.ts`、`src/tools/index.ts`、`tests/engine-extra.spec.ts`、`tests/round5.spec.ts`、`tests/tools-extra.spec.ts`。

- `load` 把 review/check 的读取与窄化包成可恢复读取，新增 `reviewError`/`checkError`；plan 已有 `planError`。
- `StatusReport` 增加 `state_errors`；`effectiveBlocking` 加入 `STATE_UNREADABLE`；`nextStep` 在错误存在且当前阶段晚于重建点时返回 `novel_rollback`，到达重建点后交给正常阶段工具。
- 恢复目标：plan → P2；review → P4；check → P6；多个错误按“plan 优先”给出最早可重建目标。
- `assertGates` 在需要该文档的写操作前拒绝：plan 错误阻断 draft/review/revision/check/archive；review 错误阻断 revision/check/archive；check 错误阻断 archive。允许用 `novel_plan_chapter`、`novel_review`、`novel_check` 覆盖对应文件。
- `novel_brief` 的 `fields` 与 `context` 暴露 `plan_error`/`review_error`/`check_error`。
- `archiveChapter`：review 存在但 `pipeline.review_digest` 缺失时 fail-closed，提示重新 `novel_review`。
- `novel_rollback` 在 state 错误存在时仍可用；不新增“修复工具”。

**测试**：损坏 plan/review/check 三种文件；status 可读且当前阶段晚于重建点时 next=rollback、到达重建点后 next=brief；回退后可重建；旧 review 无 digest 时 archive 拒绝；允许覆盖的写操作仍能恢复。

### S3 · 分阶段上下文预算（P1）

**文件**：`src/engine/context.ts`、`src/engine/service.ts`、`src/types.ts`、`tests/brief.spec.ts`、`tests/coverage-round2.spec.ts`。

- `briefContext` 返回 `context` 并附加 `context_meta`：`{version, stage, budget, used, over_budget, protected, truncated, omitted, strategy}`。
- 每阶段预算：P1 6000、P2 8000、P3 16000、P4 24000、P5 24000、P6 32000、P8 12000（按 JSON 字符计；只用于上下文，不改字数规则）。
- 受保护键：`project`、`chapter`、`stage`、`previous_ending`、`text`、`plan`、`review`、`check`、`machine`、`summary`、`context_meta`；正文永不截断。
- 可裁剪：characters、world 四个列表、locks、open_foreshadows、timeline、relationships、recent_summaries、score_history。
- 排序优先级：正文/plan 提到的实体 → 最近/最久未推进（按类型）→ 稳定 key；同分按名称/ID 排序，保证 digest 稳定。
- 裁剪顺序固定；每次删除累计 `omitted`；被裁剪的键进入 `truncated`。受保护内容本身超预算时 `over_budget=true`，不丢正文。
- `briefDigest` 已包含完整 context，因此 `context_meta` 自动参与签名；0.1.1 的旧 brief 会在升级后失效，文档说明重新取 brief。

**测试**：小项目内容不裁剪；100 章/100 角色 fixture 裁剪后 ≤ 预算；正文/当前 plan/review/check 仍在；truncated/omitted 可核对；同输入 digest 稳定；顺序变化不改变输出。

### S4 · 连续性与面板诚实（P1/P2）

**文件**：`src/rules/checks.ts`、`src/engine/gates.ts`、`src/engine/service.ts`、`src/engine/projections.ts`、`src/types.ts`、`tests/rules.spec.ts`、`tests/projections.spec.ts`、`tests/engine-check.spec.ts`。

- `slidingWindows` 按非空白字符推进：窗口含 `size` 个非空白字符；尾部窗口同样；空格/换行/全角空格不再改变窗口数量与命中。
- `RESOURCE_MISMATCH`：必须同时出现角色、资源名、数量；符号与 `delta` 一致（正/负词或 `+`/`-`），否则 advisory。
- `phaseStrip`：`ready_to_archive` → P7 active，P8/P9 pending；`done` 语义不变。
- `runCheck(scope)`：允许 `content`、`integrity`，默认两者；空数组/未知值拒绝；content 只跑内容规则，integrity 只跑跨章规则；`CheckDocument.scope` 记录实际范围；`scope` 进入幂等 key。
- `GateInput.scope` 传入 runCheck；`PG-04` 在无 content 时跳过，`PG-10` 在无 integrity 时跳过。

**测试**：同一文本插空格前后窗口结果一致；资源符号反了会命中；phaseStrip 的 P7/P8 状态；scope 的默认/单范围/空/未知；单范围不跑另一类规则；scope 变化使 replay key 不同。

### S5 · 真实宿主门补全（P1）

**文件**：`scripts/check-host.mjs`、`package.json`（必要时）、`README.md`。

- 保留现有 pack → web profile → 面板 401→200 → remove 链路。
- 新增 headless 工具链：临时 profile 从默认 headless 创建，安装同一 tarball；启动本地 Messages mock（仅测试脚本，不新增运行时依赖）；让 mock 依次返回 `novel_init` tool_use 和最终文本；断言：
  - 请求体中包含 `novel_init`/`novel_status` 等插件工具声明；
  - `novel_init` 执行后临时项目出现 `novel.yaml`；
  - headless stdout 出现最终标记；
  - 结束后删除 headless profile。
- 没有 `dsh` 或 mock 失败时明确失败，不打印“通过”。
- 不把真实模型 Key 写入脚本；若用户提供 `DSH_NWE_LIVE=1` 与真实凭据，可作为额外人工验证，不作为默认门。

**测试**：本机 `pnpm check:host` 实际通过；脚本失败路径至少断言缺少 `DSH_BIN` 时报错（现有逻辑保留）。

### S6 · 文档与升级路径（P1）

**文件**：`README.md`、`DESIGN.md`、`PLAN.md`、`CHANGELOG.md`、`docs/tools.md`、`docs/states.md`、`briefs/P1.md`、`briefs/P2.md`、`briefs/P4.md`、`briefs/P6.md`、`package.json`。

- 版本 0.1.2；不 bump schema，不加依赖/工具/命令。
- README：`state_errors`、`context_meta`、scope、rollback 只后退、P2 计划约束、旧 brief 失效说明。
- DESIGN：更新阶段表、brief 契约、PG 说明、phaseStrip、测试布局；不得保留“scope 可配置但未生效”的表述。
- PLAN：0.1.2 状态与验收；0.2.0 书级规划边界不变。

- 每片先写失败测试，再改实现，再跑该片与全量。

- 不提交、不推送、不发布；最终报告列出改动文件、验证命令、未覆盖边界。
