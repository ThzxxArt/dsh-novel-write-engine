## 1. 这张图是什么

图是一张**投稿前的自查表**，两栏十三行，最后一列是作者自己打勾的「√/×」：

| # | 类别 | 自查内容 |
| --- | --- | --- |
| S1 | 文风呆板 | 比喻：只保留最贴切的一个，其余全部删掉 |
| S2 | 文风呆板 | 画面感：过于精确或抽象的描写删掉，不能想象出具体画面的描写也删掉 |
| S3 | 文风呆板 | 固定句式：没有重复使用由相同关联词构成的固定句式 |
| S4 | 文风呆板 | 短句排比：没有反复使用结构相同或者一行一句的排比短句 |
| S5 | 文风呆板 | 清单罗列：不用大段文字罗列清单（系统面板、任务列表等除外） |
| S6 | 文风呆板 | 短对话：短对话之间穿插了动作、神态或场景 |
| S7 | 排版问题 | 破折号：慎用，只在真正需要补充说明或语气转变时使用 |
| S8 | 排版问题 | 对话标点：人物对话使用引号，对话与旁白区分清楚 |
| S9 | 排版问题 | 标点统一：中文全角标点，不留空格，也没有使用特殊符号 |
| S10 | 排版问题 | 段落：没有几百字的长段落，也没有三五个字就另起一段 |
| S11 | 排版问题 | 分行：完整的一句话放在同一段，没有在中间随意回车 |
| S12 | 排版问题 | 分章：在句子完整结束处，或者形成悬念的卡点位置分章 |
| S13 | 排版问题 | 转场：省略号、分割线只用于场景转换、时间跳转，没有乱入 |

这张表的性质要说清楚：它不是**风格偏好**（那是风格包的事），而是**退稿理由的高频排行榜**。左边六项是「读起来像 AI 写的」，右边七项是「排版不像人做的」。前者影响读者留存，后者影响编辑的第一眼判断。

### 2.1 为什么「部分覆盖」等于没覆盖

S1 是个典型：一整章只出现一个比喻，密度永远合格——但那一个比喻如果和另外两个挤在同一句里，读者的感受就是「作者在堆词」。密度是**章节级统计量**，图上的要求是**句级/段级结构**。两者不是精度差异，是坐标系不同。

S4 同理：`UNIFORM_SENTENCE` 要求「同一段里至少 8 句、且 60% 长度相近」，而图上的排比是「一行一句」跨段发生的——那是**排版层**的现象，单段窗口根本看不见。

## 3. 三个断层（本轮的立论）

### 断层一：0.2.17 建的是测量层，图上要的是结构层

0.2.17 的十项 `STYLE_*` 全部是「每千字密度」或「全章占比」：句长分档、变异系数、段宽、段句数、对白双口径、抽象情绪密度、比喻密度、爽点空窗、情绪线索密度（`src/domain/style.ts:38-72`）。

这套指标回答的是「这一章像不像这个风格」，回答不了「这一句里塞了几个比喻」。图上 13 项里有 **7 项是局部结构**（S1/S3/S4/S5/S6/S11/S12），密度指标对它们天然失明。

### 断层二：能判的不计分，判了的不进任务书

- 56 个规则码里 **42 个恒为 advisory**，而 advisory **不进入评分**：`totalScore` 只读 `review.dimensions[].deductions`（`src/domain/scoring.ts:31-57`），机器 finding 一条都不参与。
- P4 的 20 分 `R-W-12 反文青病`、4 分 `R-W-07 去 AI 味`，**全仓没有任何定义**。扣分条目里的 `rule` 是自由字符串（`scoring.ts:96-105` 只判非空），模型写 `"rule": "NO_MOTIVE"` 也能过（`briefs/P4.md:54`）。
- 结果：清单上的问题，机器报了不扣分；模型漏报了也没人能查。

### 断层三：DESIGN 写了机检度，代码里不存在

`DESIGN.md:1584` 原文：

> **机检度是新增元数据**：● 的维度由引擎直接给分（模型不得覆盖）；◐ 的维度引擎给「事实层」证据、模型给「判断层」结论。

而 `src/domain/scoring.ts:4-20` 的 `SCORE_DIMENSIONS` 只有 `{id, max, group}`。

`service.ts` 全文 14,661 行通读后的结论（不是抽样）：

- 维度唯一来源是入参：`5945 const provided: ScoreDimension[] = input.dimensions`。
- 总分唯一来源是 `5947 totalScore(excluded.dimensions)`。
- 引擎只做三件事：`total` 省略时求和（5950）、给错时硬失败（5951-5972 `SCORE_MISMATCH`）、按 `rulepack.exclusions` 删重复扣分（5946）。
- **全文没有任何 `code → R-W-xx` 的映射**（已用 `R-W-`、`ruleScore`、`codeToDimension`、`violationToDimension` 等 17 个关键词全文件反向核验）。

也就是说：**格式硬性 15 分（R-W-06…10）本该机器算，现在全靠模型自评**——包括段落长度、字数、标题这些完全客观的东西。这是 0.2.17 修过的那类「门看起来在、其实没在」。

## 5. 设计原则（不变量）

1. **一个 code 一个 owner。** 新码不与既有码判同一件事；同一 span 命中多码时按既有让位规则（更具体的胜出）。
2. **只有客观、可机械修复的才是 blocker。** 主观项一律 advisory，advisory 永不阻塞归档（沿用 0.2.17 的分级）。
3. **清单是全局标准，与风格包无关。** 没有 `novel.yaml.style` 的项目照样跑这 13 项——图和风格包是两件事。
4. **每条判定必须落到段落号与原句。** 沿用 0.2.17 的证据纪律：报了什么，就要能指出在第几段。
5. **模型可以判断，但不能凭空判断。** 机器已判 fail 的项，模型不得填 pass；要推翻必须给正文证据与理由。

## 6. 目标 / 非目标

**目标**

- 13 项全部有稳定 id（`SC-*`）、判定来源（machine / hybrid / model）、证据与去处。
- 机检度落地：`R-W-06/07/08/09/10` 由引擎给分，模型的声明值被记录但不生效。
- 自查表进入 check 文档、P4 任务书、面板与全书报告。

**非目标（明确不做）**

- 不做「文风好不好」的美学判断——那是 P4 模型的事，本轮只把它变成**有锚点**的判断。
- 不改 15 维满分与 150 分制；不新增维度。
- 不做跨章文风漂移分析（需要另开 0.2.20）。
- 不引入第二套 UI 库；面板只用现有 `--nwe-*` 变量与语义 HTML。
- 不放松任何既有 blocker。

## 8. 13 项逐条设计

统一的判定模型：

```ts
export type SelfCheckId =
  | 'SC-METAPHOR' | 'SC-CONCRETE' | 'SC-FORMULA' | 'SC-PARALLEL' | 'SC-LIST' | 'SC-DIALOGUE-BEAT'
  | 'SC-DASH' | 'SC-QUOTE' | 'SC-PUNCT' | 'SC-PARAGRAPH' | 'SC-LINEBREAK' | 'SC-CHAPTER-BREAK' | 'SC-TRANSITION'

export interface SelfCheckItem {
  id: SelfCheckId
  category: 'voice' | 'layout'
  title: string                    // 图上原文
  basis: 'machine' | 'hybrid' | 'model'
  verdict: 'pass' | 'fail' | 'na'
  codes: string[]                  // 支撑本次判定的规则码
  evidence: Array<{ paragraph: number; quote: string; detail: string }>
  note?: string                    // hybrid/model 项的判断理由
}
```

`na` 只用于「正文为空」或「本章没有可判对象」（例如全章无对白时的 S6）。

**已经具备、不需要新建的基础设施**（通读 `service.ts` 与 `domain/text.ts` 确认）：

| 能力 | 位置 | 本轮怎么用 |
| --- | --- | --- |
| 段落切分 | `domain/text.ts` `splitParagraphs` | 所有段级检测的唯一口径 |
| 字符偏移→段落号 | `service.ts:13260 paragraphOfOffset` | 句级命中回填段落号 |
| 最近段落定位 | `service.ts:13267 nearestMatch` | 证据引文与正文对不上时给「最接近的第 N 段」 |
| 段落号越界校验范式 | `service.ts:6037-6044` | 复用同一条错误文案格式 |
| advisory 聚合与实例化 | `pipeline.ts dedupeAdvisories` | 一个 code 多实例的既有模型，直接沿用 |
| 句子切分（带 span） | `domain/text.ts` `splitSentenceSpans` | S1/S3/S4 的句级窗口 |

这六样都已经在跑，本轮只写「判定逻辑」，不重造基础设施。

### S1 SC-METAPHOR · 比喻只留一个

- **basis**：hybrid。
- **机器**：`METAPHOR_STACK`（新，advisory）。
- **算法**：
  1. 修 D2 的匹配器：marker 右侧 12 字内必须出现具体名词/量词/动作词；左侧若是 `好/图/偶/影/录/想/雕/佛` 不算；`似的` 必须左邻 `像/跟/和/如`。
  2. 逐**句**统计命中数，`>1` 记一次 stack。
  3. 逐**段**统计 stack 数，`≥2` 报一次。
- **阈值**：`selfcheck.metaphor.max_per_sentence: 1`、`max_stacks_per_paragraph: 2`。
- **证据**：段落号 + 该句原文（截 40 字）+ 命中词列表。
- **误报边界**：对白段落照常判（人物堆比喻也是堆）；`像` 作介词（「像他这样的人」）由右侧名词类型排除。
- **验收**：
  - 反例（必须 0 报）：`好像是这样的，画像挂在墙上，他偶像的照片。`
  - 正例（必须报）：`她的眼睛像两口井，像两潭死水。`
  - 边界：同段两句各一个比喻 → 不报（未达 stack 阈值）。

### S2 SC-CONCRETE · 画面感

- **basis**：model（机器只给事实层）。
- **机器**：`PROSE_ABSTRACT`（新，advisory）。
- **算法**：段落内抽象名词（`气氛/氛围/情绪/感觉/状态/意义/命运/灵魂/气息/气场`）≥3，且该段感官词与情绪线索命中数为 0 → 报。
- **模型**：P4 必须对每个 `PROSE_ABSTRACT` 命中段回答「可成像 / 不可成像」；判「不可成像」才允许扣 `R-W-12`。
- **误报边界**：对白主导段（引号字符 ≥60%）跳过。
- **验收**：`空气里有一种说不清的气氛，整个人的状态都变得很微妙。` 必报；`他摸到桌沿，凉的，有一层灰。` 不报。

### S3 SC-FORMULA · 固定句式

- **basis**：hybrid。
- **机器**：`FRAME_REPEAT`（新，advisory）。
- **算法**：
  1. 规则包 `selfcheck.frames`，复用风格包已有的 `……` 模板语法（`A[\s\S]{0,12}B`），逐条计数超 `max` 即报。
  2. 通用层：句首 2 字（排除 `他/她/我/你/这/那/但/而/就/也/还/又`）在同一章出现 ≥3 次 → 报（同一 opener 每条只报一次）。
- **默认帧**：`不是……而是……(1)`、`与其说……不如说……(1)`、`如果说……那么……(1)`、`当……的时候(2)`、`因为……所以……(2)`、`一边……一边……(2)`、`越……越……(2)`。
- **owner 划分**：风格包禁句归 `STYLE_BANNED_PATTERN`；关联词帧归 `FRAME_REPEAT`。同一 span 同时命中时 `STYLE_*` 胜出（沿用 0.2.17 C8 让位机制）。
- **验收**：一段里连用两次「不是……而是……」必报；正常叙述出现一次不报。

### S4 SC-PARALLEL · 短句排比

- **basis**：hybrid。
- **机器**：`PARALLEL_RUN`（新，advisory）。
- **形态**：
  - (a) 句内排比：连续 ≥3 句，句长两两差 ≤2，且首字相同或首二字相同。
  - (b) 一行一句：连续 ≥3 段，每段恰好 1 句且 ≤12 字。
- **阈值**：`selfcheck.parallel.min_run: 3`、`length_delta: 2`。
- **误报边界**：对白段跳过；`system_labels` 命中段跳过；战斗/动作章 `min_run + 1`（连击短句是风格）。
- **验收**：`他走。他停。他看。` 必报；`他走。风停了。远处有人在喊。` 不报。

### S5 SC-LIST · 清单罗列

- **basis**：hybrid。
- **机器**：`ENUMERATION`（新，advisory）。
- **形态**（任一命中）：
  - (a) 连续 ≥3 句以序数开头（`第一/第二/第三`、`其一/其二`、`首先/其次/再次/最后`、`一是/二是`）。
  - (b) 单句含 ≥5 个顿号，且其中 ≥3 个分项 ≤6 字。
  - (c) 连续 ≥3 段形如「短名词：说明」。
- **豁免**：`system_labels` 命中段；`【】` 包裹段（系统面板、任务列表）。
- **验收**：`第一，他要钱。第二，他要命。第三，他还要脸。` 必报；`他先要钱，再要命。` 不报。

### S6 SC-DIALOGUE-BEAT · 短对话穿插

- **basis**：hybrid。
- **机器**：`DIALOGUE_RUN`（新，advisory）。
- **形态**：连续 ≥4 段为对白主导（引号内字符 ≥60%）且中间无叙述段；或单段内连续 ≥3 行纯引号对白无 tag。
- **阈值**：`selfcheck.dialogue_run.max_consecutive: 4`；`allow_interruptions: true` 的风格包 +2。
- **验收**：四段「他说…」「她说…」交替必报；每段之间夹一个动作不报。

### S7 SC-DASH · 破折号

- **basis**：machine。
- **落点**：复用 `DASH_BUDGET`（`checks.ts:360-382`），自查判定 = 该码是否命中。
- **说明**：「只在补充说明或语气转变时用」的语义判断机器不做，作为 P4 提示写进任务书，不设新码。

### S8 SC-QUOTE · 对话标点

- **basis**：hybrid。
- **机器**：`QUOTE_UNBALANCED`（新，**blocker**）——段落内 `"` 计数为奇数。已有 `ILLEGAL_QUOTE` 继续管弯引号。
- **模型**：对话与旁白是否区分（P4）。
- **为什么是 blocker**：未闭合引号会让后续整段被渲染成对白，属于客观损坏，和全角分号同级。
- **验收**：`他说："走吧。` 必报；`他说："走吧。"` 不报。

### S9 SC-PUNCT · 标点统一

- **basis**：machine。
- **机器**：`PUNCT_STANDARD`（新，**blocker**）。
- **三种形态**：
  1. 半角 `, . ? ! : ; ( )` 且左右**至少一侧**是中文（两侧均为数字/拉丁字母/单位时豁免）。
  2. 两个中文字之间的 ASCII 空格；段首/段尾的 ASCII 空格。
  3. 特殊符号 `~ ～ ※ ★ ☆ → ← ↑ ↓`（`【】` 不在此列）。
- **允许**：段首单个 U+3000 缩进。
- **误报边界**：`3.5%`、`10,000`、`U.S.`、`A/B`、整句英文豁免。
- **验收**：`他说,走吧。` 必报；`身高 1.85 米` 不报。

### S10 SC-PARAGRAPH · 段落

- **basis**：machine。
- **机器**：`LONG_PARAGRAPH`（已有 blocker）+ `SHORT_PARAGRAPH`（新，advisory：非空白 ≤6 且非对白行）。
- **口径诚实**：图上是「几百字」，引擎是 **90 个计数单位（含标点）**，比图更严。本轮**不放宽**，只在 P3/P4 任务书里写明引擎口径，避免模型按「几百字」写。
- **验收**：`他走了。` 单独成段必报短段；100 字段必报长段。

### S11 SC-LINEBREAK · 分行

- **basis**：machine。
- **机器**：`MID_SENTENCE_BREAK`（新，advisory）。
- **形态**：段末是 `，、：；,` 或 `——`，且下一段不是新对白（不以引号开头）。
- **验收**：`他推开门，` / `里面没人。` 必报；`他说："走吧。"` / `她没动。` 不报。

### S12 SC-CHAPTER-BREAK · 分章

- **basis**：hybrid。
- **机器**：`CHAPTER_END_OPEN`（新，advisory）——最后一个非空段末字符 ∉ `。！？…"`。
- **模型**：`hook_strength`（已有，1–5）。
- **验收**：正文以「他抬起头，」结尾必报。

### S13 SC-TRANSITION · 转场

- **basis**：machine。
- **落点**：复用 `SCENE_SEPARATOR`（blocker），并扩展「整段只有 `……`/`——`/`—`」也按分割线处理（同一 owner，不加新码）。
- **口径诚实**：图上说「只用于场景转换」，引擎的选择是**一律禁止**——比图更严，但避免了「这是转场还是偷懒」的语义判定。这个取舍要写进文档，不能假装是同一个标准。

### 8.14 一张表看清：哪些是机器判，哪些只能人判

| 判定来源 | 项 | 数量 |
| --- | --- | --- |
| **纯机器**（模型不得推翻） | S7 破折号、S9 标点、S10 段落、S11 分行、S13 转场 | 5 |
| **机器给事实 + 模型下结论** | S1 比喻、S3 固定句式、S4 排比、S5 清单、S6 短对话、S8 对话标点、S12 分章 | 7 |
| **纯模型**（必须引原文） | S2 画面感 | 1 |

这张表是本轮最重要的一句话：**13 项里有 5 项可以完全交给引擎，7 项可以交给引擎「举证」**。真正只能靠人（模型）的只有「这一段到底能不能拍出来」一项。不做这个拆分，清单就永远只是提示；做了，那 20 分的「反文青病」才第一次有可引用的证据清单——而不是一句「感觉有点文青」。

### 9.3 扣分公式

代码里新增一张常量表（不放规则包——机检度是设计决策，不是口味）：

```ts
export const MACHINE_SCORING: Readonly<Record<string, Array<{ code: string; weight: number; cap: number }>>> = {
  'R-W-06': [{ code: 'LONG_PARAGRAPH', weight: 2, cap: 4 }, { code: 'SHORT_PARAGRAPH', weight: 1, cap: 2 }],
  'R-W-07': [{ code: 'AI_TONE_META', weight: 2, cap: 4 }, { code: 'AI_TONE_TEMPLATE', weight: 1, cap: 2 },
             { code: 'FRAME_REPEAT', weight: 1, cap: 2 }, { code: 'PARALLEL_RUN', weight: 1, cap: 2 }],
  'R-W-08': [{ code: 'PUNCT_STANDARD', weight: 2, cap: 4 }, { code: 'QUOTE_UNBALANCED', weight: 4, cap: 4 },
             { code: 'ILLEGAL_QUOTE', weight: 2, cap: 4 }, { code: 'SEMICOLON', weight: 1, cap: 2 },
             { code: 'SCENE_SEPARATOR', weight: 2, cap: 4 }, { code: 'MD_CONTAMINATION', weight: 2, cap: 4 }],
  'R-W-09': [{ code: 'WORD_COUNT_SHORT', weight: 2, cap: 2 }],
  'R-W-10': [{ code: 'TITLE_FORMAT', weight: 1, cap: 1 }],
}
```

```
deduction_dim = min(max_dim, Σ_code min(cap_code, weight_code × hits_code))
effective     = max_dim − deduction_dim
```

`WORD_COUNT_SHORT` 不是新规则码，是 `R-W-09` 的内部信号（字数低于下限时由引擎直接置位）。

### 9.4 review 处理流程

1. 模型仍提交全部 15 维（保持既有契约与互斥算法）。
2. ● 维度：引擎以自己算的为准；`declared` 与 `effective` 都落盘，回执列 `adjusted: [{id, declared, effective, reason}]`。
3. `total` 用 effective 复算；模型提交的 `total` 必须等于它，否则回执同时给「你写的 / 引擎算的」两行（沿用 0.2.17 的「回执即修复说明」风格）。
4. ◐ 维度：模型判；若机器事实层命中而该维度零扣分，写 `DEDUCTION_NOT_ANCHORED` advisory（不阻塞）。

### 9.5 为什么不做「模型不得提交 ● 维度」

因为 15 维全提交是既有契约（`briefs/P4.md:77`），改成「只提交 10 维」会破坏所有下游读取（report 的 `quality.dimensions`、面板十五维卡、`scoring-contract` 测试）。让模型继续提交、引擎覆盖，是改动面最小且可观测的做法。

| 面板 payload 增大 | 64KB 上限 | 自查卡片只带当章 13 行，聚合在 report |

回滚：所有新增字段可选、所有新码可进 `exemptions`；紧急情况在 rulepack 里 `exemptions: [PUNCT_STANDARD, ...]` 单条关闭，不改代码。
