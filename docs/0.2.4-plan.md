# 0.2.4 大纲 upsert 根治方案

## 1. 缺陷

`novel_outline.chapters` 旧语义是“提交集合 = 计划卡全集”。只提交第 9、34 章时，其余 planned 卡被静默删除；strict 的活动章守卫还会把用户引向 `strict:false`，从而打开真正的数据丢失入口。工具描述没有声明替换语义，写入没有 `dry_run`、没有 changed 回显、没有 outline 级恢复路径。

## 2. 根因

1. **语义不在契约里**：`chapters`/`volumes` 是 replace，但只有 `book` 是 patch；工具 schema 没有数组语义声明。
2. **删除没有名字**：删除是“省略”的副作用，无法看见、确认或拒绝。
3. **守卫按症状设计**：只保护活动章，且把保护开关交给 strict。
4. **写入不可解释**：无 dry_run、无 changed 回显、无 deprecated、`novel_restore` 够不到 outline。

## 3. 新契约

- `chapters` 按 `num` upsert；`volumes` 按 `title` upsert；省略 = 保持。
- 删除只走 `remove: number[]` / `remove_volumes: string[]`；活动章、归档章、不存在的章、`status=done` 的卷拒绝删除。
- `dry_run:true` 返回 `would_add/would_update/would_remove`，零写盘、零 journal。
- 成功返回 `added/updated/removed` 与 `volumes_added/volumes_updated/volumes_removed`。
- `novel_outline` 正常写入保留 `outline/outline.deprecated.yaml`；`novel_restore` 支持 `paths:["outline/outline.yaml"]`，但恢复结果必须与当前章索引一致。
- `novel_blueprint.volumes` 保持整体 replace，但删卷必须 `confirm_remove:true`。
- 持久集合的数组参数在描述与 `src/tools/semantics.ts` 中声明语义；DSH 的 JSON Schema 子集不接受未知 `x-semantics` key，因此由 `tests/tool-contract.spec.ts` 对 schema 数组 + 持久集合注册表强制，不依赖模型自觉。

## 4. 验收

| 编号 | 判据 |
| --- | --- |
| A1 | 部分提交后 planned 数量不变，未提交卡逐字节保持 |
| A2 | 删除必须显式，返回体回显 `removed`；省略不再删除任何卡 |
| A3 | strict 关闭/打开都不影响“省略不删”；活动章显式 remove 被拒 |
| A4 | dry_run 后 outline 与 journal 逐字节不变；outline 可用 `novel_restore` 取回 |
| A5 | 工具契约测试能对漏声明的新数组参数报错 |
| A6 | 全量测试、覆盖率、typecheck、lint、build、pack、install、host、crash 等门禁全绿 |
| A7 | 2.5/3.0 真实模型在临时项目完成 P1→P8 全链路 |

## 5. 明确不做

- 不保留旧的 replace 语义再加守卫：那只是把“删 36 张”变成“多点一次确认”。
- 不靠 strict 保护数据：strict 是写作模式，不是数据安全开关。
- 不改 `outline.yaml` 数据格式，不迁移旧项目；只反转写入口语义。
- `novel_outline_import` 仍是显式全量导入（带 dry_run），不使用 upsert。
