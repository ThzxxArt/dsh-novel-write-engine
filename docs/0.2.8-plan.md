# 0.2.8 · 边界与可信性

0.2.8 不新增章节阶段、工具、门控或规则阈值。它只修一个核心问题：**引擎的持久状态是对的，但读模型把“上一章已归档”误读成“下一章已经完成”。** 同时收口三处会影响信任的边界：备份路径逃逸、PG-05 与归档的叙述者别名不一致、面板健康缓存假绿。

## 目标

1. 归档第 N 章后，所有人类可读面都显示“第 N 章已归档；下一章 N+1 从 P1 开始”，不再出现“当前第 N+1 章 · 阶段 done”。
2. 全书达到 `targets.total_chapters` 后，`/novel resume`、面板复制按钮、`novel_guide`、`novel_status`、`novel_doctor` 都显示全书完成，不再生成“请继续第 N+1 章”。
3. `backups/` 或项目内任一父目录是符号链接时，事务在写入前返回 `ENGINE_PATH_ESCAPE`，项目外零写入；项目根被删除时，备份阶段也不会用 `mkdir` 重建根。
4. `narrator: "林砚（第一人称）"` 在 PG-05、state_delta、归档三处得到同一判定；第一人称取证使用“我”，不再依赖引号别名。
5. 面板健康状态在外部改动或 journal 追加后不再命中旧缓存；`totalWords` 与 `/novel-stats` 使用同一口径并拆出 `archivedWords` / `draftWords`。
6. `ready_to_archive` 缺 P8 任务书时先返回 `novel_brief P8`，不再错误建议回退 P6。
7. 归档章卡的 `goal/conflict/hook/notes` 与 `title/scene_type/target_words/cast` 一样不可改写；`created` 角色的 `growth` 正常落盘。
8. 面板九阶段名称与 README/DESIGN 一致：P7 状态同步、P8 终审、P9 归档；教程不再把“首次提交章卡默认 strict”说成可选，也不再声称纯文本 `novel_word_count`/`novel_diff` 会绑定会话。

## 不在 0.2.8

- 不改 `pipeline.stage` 枚举、`StatusReport.stage` 的协议含义，也不改 `active_chapter`。
- 不处理卷 id/卷改名/模糊导入的兼容扩展；这些留到 0.2.9。
- 不修规则引擎的既有 advisory 误报（`RELATION_UNKNOWN`、`RESOURCE_MISMATCH` 等）；它们不阻塞归档，留到 0.2.9。
- 不改工具数（28）、操作数（32）、门控数（13）、语义项（5）或导出种类（6）。
- 不提交、不推送、不发布；版本号与 CHANGELOG 只做本地收口。

## 设计

### 1. 单一进度投影

在 `src/engine/projections.ts` 新增 `projectChapterProgress`，输入 `activeChapter`、`stage`、已归档章号、`target`，输出：

```ts
interface ChapterProgress {
  active_chapter: number
  stage: Stage
  current: { chapter: number; stage: Stage } | null
  last_archived: number | null
  next: { chapter: number; stage: 'P1' } | null
  finished: boolean
  label: string
  resume: string
}
```

规则：

- `stage !== 'done'`：`current` 是活动章；`label = 第 N 章 · 阶段 S`；`resume = 当前第 N 章，阶段 S。`
- `stage === 'done'` 且达到目标：`finished = true`；`current/null`、`next/null`；`label = 全书完成：已归档 X 章`；`resume` 说明如需续写先改 `targets.total_chapters`。
- `stage === 'done'` 且未达目标：`current/null`、`last_archived` 是已归档最大章号、`next = { active_chapter, 'P1' }`；`label = 第 N 章已归档 · 下一章第 N+1 章待开始（P1）`；`resume = 第 N 章已归档；当前不处于写作阶段，下一章第 N+1 章从 P1 开始。`

`statusFor`、`advise`、`guide`、`doctor`、`panelSnapshot`、`projectSummary` 都从同一个函数取，不再各自拼 `第 ${chapter} 章 · ${stage}`。

### 2. 读面接入

- `StatusReport.progress` 新增；`/novel status`、`novel_status` render 先显示 `进度：<label>`。`chapter` 仍是 metrics 查询章，`active_chapter` 仍是活动章。
- `formatResumePrompt` 接受 `progress`，用 `progress.resume` 替换硬编码的“当前第 X 章，阶段 Y”；`resumePrompt` 在 `finished` 时返回 `text: null`，`/novel resume` 命令层显示“全书已完成”，不把完结当故障。
- `PanelSnapshot.progress` 与 `PanelSummaryDto.progress` 新增；`PanelView` 的副标题、`stageLabel`、当前章卡使用 `progress`。
- `GuideInput.progress` 新增；`buildGuide` 的 title 与“写第 N 章”步骤使用它。
- `doctor` 的 `pipeline` check detail 使用 `progress.label`。
- `novel_pipeline` 的 JSON 带 `progress`。
- 旧 payload 没有 `progress` 时，viewmodel/命令保留现有 fallback；这是 wire 兼容，不是第二 owner。

### 3. 备份路径

`runTransaction` 的 backup 分支：

1. 在每次写 `staging/backup` 前调用 `assertRootPresent()`；写完后再次检查。
2. 用 `store.ensureDir(BACKUP_DIR)` 创建 `backups/`，它会拒绝符号链接。
3. 用 `store.safePath(backupDir(txid))` 解析目标；`fs.rename` 的目标来自该安全路径。
4. 保留现有 staging→rename 的原子模式；失败清理仍走 `store.removeTree`。

不做“先 `fs.mkdir` 再 `fs.rename`”的裸路径。

### 4. 叙述者

新增 `src/domain/narrator.ts`：

```ts
narratorName(narrator)        // 去掉括号后缀
firstPersonAliases(narrator)  // 「我」/“我”等引号别名 + 第一人称声明时的“我”
isNarratorAlias(name, narrator, text)
```

`gates.ts` 的 PG-05 和 `state-delta.ts` 的 `appearsInManuscript` 共用它。`locks` 取证在叙述者第一人称时也把“我”作为别名，避免取到无关首段。

### 5. 读模型一致性

- `panelCacheKey` 在现有字段外加入 `journal.rows.length`、最后一行 `seq`、`journalBlocking` 的摘要；journal 追加或外部改动后不再复用旧 health/activity。
- `stats()` 返回 `totalWords`（归档 + 活动草稿）、`archivedWords`、`draftWords`；`/novel-stats` 显示拆分。`PanelSnapshot` 同步新增 `archivedWords`/`draftWords`。
- `nextStep` 在 `ready_to_archive` 且 P8 任务书不当前时，先返回 `novel_brief {stage:'P8'}`，再进入 `archivePreflight`。

### 6. 状态契约

- `book.ts` 的归档卡分支对 `goal/conflict/hook/notes` 显式比较，任何变化返回 `ENGINE_SCHEMA_INVALID`；省略仍保留。
- `state-delta.ts` 的 `created` 角色把已校验的 `declared.growth` 写成 `[{...growth, chapter}]`，而不是固定 `[]`。

### 7. 文案与文档

- `PHASE_LABELS`：P7 状态同步、P8 终审、P9 归档。
- 教程：首次 `novel_outline` 默认 strict；`novel_word_count`/`novel_diff` 的纯文本模式不绑定会话；面板 v6 当前章在 `done` 时显示“下一章未开始”或“全书完成”。
- README/DESIGN/CHANGELOG 与上述行为同步；版本收口到 0.2.8。

## 验收

1. 归档第 1 章后：`/novel status`、`/novel resume`、`novel_status`、`novel_pipeline`、`novel_guide`、`novel_doctor`、`panelSummary` 全部显示“第 1 章已归档；下一章第 2 章从 P1 开始”；`/novel resume` 文本含该句且不含“当前第 2 章，阶段 done”。
2. `total_chapters: 1` 归档后：`resumePrompt().data.text === null`；`/novel resume` 命令返回“全书已完成”；`panelBundle().resume === undefined`；`panelSummary().finished === true`；`getStatus().data.progress.finished === true`。
3. `backups` 指向外部目录：事务返回 `ENGINE_PATH_ESCAPE`，外部目录为空，项目内不产生 backup；在 backup 阶段删根不会重建根。
4. `narrator: "林砚（第一人称）"` + 正文“我”可以归档；PG-05 不再报 `characters_appeared`；locks 取证取到含“我”的段落。
5. panel 在外部改 ledger 后不再返回旧 `health.ok`；journal 追加后 activity 更新。
6. `stats.totalWords === stats.archivedWords + stats.draftWords`；面板与命令对同一项目给出一致拆分。
7. `ready_to_archive` 且 P8 brief 缺失时，`next.tool === 'novel_brief'`、`stage === 'P8'`。
8. 归档卡改 `goal/conflict/hook/notes` 被拒，`chapters.yaml` 损坏时同样被拒；旧卡空 `goal/conflict/hook` 原样重交通过；`created` 角色带 growth 时 ledger 保存 `{chapter, change, status_change}`。

10. 全量门禁全绿；工作区无临时文件、无项目外写入。

## 风险与回滚

- **读模型扩散**：`progress` 是 additive 字段，旧 payload 保留 fallback；不做 schema migration。
- **备份改动**：staging→rename 的原子性不变；新增的 `ensureDir`/`safePath` 只会更严格，不会放宽路径。
- **面板 v6**：新增 `progress` 是 additive，`REMOTE_VERSION` 保持 6；旧标签页刷新即可。
- **叙述者判定**：只接受“叙述者名 + 第一人称声明 + 正文含我”，不扩大到任意代词。
- 回滚：所有改动在单次工作区内，未提交；如失败按文件回退，不改用户项目数据。
