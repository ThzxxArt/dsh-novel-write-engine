# 0.2.17 视觉验收：真浏览器截图

> 记录时间：2026-11-10
> 环境：DSH `0.2.2-rc.1`、临时 `DSH_HOME`、真实监听端口、Chromium 158（Playwright 1.61）
> 复跑：`pnpm check:visual`
> 留档截图：`docs/evidence/0.2.17/`（`style-card.png`、`panel-1280-overview.png`、`panel-1280-质量.png`、`panel-390-quality.png`）

## 为什么要做这一层

0.2.17 前两轮的面板验证都是把 React 渲染成静态字符串再断言字符串。那能证明组件树，
不能证明**发到浏览器上的那一页**：CSS 截断、390px 溢出、客户端没有请求的 section、
以及把内部脚手架当成作者设定显示出来——这些只在像素上出现。

这一轮装了真 Chromium，在临时 profile 里打开真面板，逐个页签截图后才发现下面四处。

## 发现的四处问题

| # | 现象（截图可见） | 根因 | 修法 |
|---|---|---|---|
| 1 | 文风卡「情绪线索 **10.204** / 千字」，同一张卡其他行是 `12.5%`、`0.0%` | 每千字密度是除法结果，直接 `String(number)` | 统一一位小数，`抽象情绪`/`比喻标记` 一并修 |
| 2 | 书脊写「悬疑推理 · 番茄小说 · 第 2 章 · 阶段 P4 · **第一卷 · 第一幕 2/5**」，同屏档案卡写「卷 0 · 这本书还没有蓝图」 | `volumeLabel` 直接投影 handoff 的默认脚手架 | 书纲没有卷时不显示位置 |
| 3 | 章节页签徽标「**1 章**」，它下面的表头写「共 2 章」 | 徽标读 `stats.chapters`（已归档数），表格数全部行 | 徽标与表格用同一投影 |
| 4 | 文风卡只有 **8** 项，方案要求 9 项 | `burstiness_min` 是规则真的在判的指标，但没上卡 | 补「句长变异 `cv / 下限`」，低于下限标警告色 |

四处都补了单元回归，并且**先在旧实现上跑红**再转绿。

## 门禁化

`pnpm check:visual` 把上面的检查固定下来：

1. `build → npm pack → dsh plugin add`（临时 profile，`DSH_HOME`/`HOME` 双双隔离）
2. 用引擎在临时目录建一本有正文、有归档、有草稿的书（`style: cold-suspense`）
3. 真端口启动 Web，Chromium 打开 token URL
4. 逐个页签（概览/章节/人物/线索/设定/质量/健康）截图，另加文风卡元素截图与 390px 截图，共 10 张
5. 断言：书脊标题、九项指标与目标值、偏差项警告色、徽标与表格一致、
   390px 无横向溢出、控制台无报错、截图非空白
6. 缺 Playwright/Chromium 时 `exit 2`，不静默跳过

截图默认落临时目录，`NWE_VISUAL_DIR=/tmp/shots pnpm check:visual` 可保留。

## 证伪

- 回退「无卷不显示第一卷」→ 门禁报 `panel claims a volume for a book whose outline defines none`
- 回退千字精度 → 门禁报 `the style card renders raw float precision`
- 回退九项指标 → 门禁报 `the style card is missing the 句长变异 row`
- 回退徽标修复 → 单元回归红（只断言 chip 元素本身，`共 2 章` 不会误匹配）

## 边界

- 覆盖 Chromium 158 headless、1280×1000 与 390×844 两个视口。
- **没有覆盖**：Safari/Firefox、触屏真机、屏幕阅读器、深色主题下的对比度、动画。
- 截图证明「渲染成什么样」，不证明「模型会不会正确选风格」——后者由真实模型链路覆盖。

## 真实模型链路（同轮）

两个模型在临时目录跑同一条 `P1 → P8 → 归档 → 导出`，用来证明面板看到的数据不是夹具。

| 模型 | 正文 | 引擎真实拒绝 | 结果 |
|---|---|---|---|
| `agnes-2.5-flash` | 1,089 字 / 27 段 | P1×1（`objective` 空）、P4×4（总分与 Σdelta 不闭合） | 归档 1,034 词、评分 150、P6 `verdict=pass`（模型语义证据被接受）、导出 3 文件 |
| `agnes-3.0-flash` | 1,056 字 / 32 段 | P4×1、P6×1，另有 4 个弯引号由驱动规范化 | 归档 989 词、评分 142、P4 与 P6 各有一次模型输出被接受、导出 3 文件 |

拒绝的形态值得记下来，它们都不是脚本造出来的：

- `PG-03` 字数不足（742 < 900）、`PG-04` Markdown 污染 / 场景分隔符 / 弯引号 16 处、`PG-05` 声明的角色不在正文里。
- `PG-09` 引文落在「首段/末段边缘」、引文段落号与实际位置不符、引文根本不是原文。
- `PG-10` 声明总分 140，但 150 − Σdelta = 144；换一次仍是 141 vs 139。
- `PG-11` 同句/重叠：两项语义证据引同一句、或 13 字重叠 62%。
- `PG-01` 上一轮 `runCheck` 被拒后 P6 任务书过期，必须重新取。

**没有放宽任何门控。** 驱动做的三件事都记录在报告里：把模型写在 `cast[].knowledge` 的单字符串包成数组、把弯引号换成 `U+0022`（3.0 共 4 处）、以及当模型彻底写不出合规的 P4/P6 时用确定性夹具补齐并标注 `fallback`。
