# 0.2.3 可信工作台实施方案

> 基线：`5c0710e`（v0.2.2）。本方案不新增正文写入口，不改变 P1→P8 的创作语义；重点是让账本、工作流、提示、面板和测试项目说真话。

## 1. 目标与验收

0.2.3 的目标是把 0.2.2 之后的真实使用反馈收口为一条可验证的产品线：

1. **账本可信**：`novel_report` 的 effort、quality、cast、briefs 不再因为旧章、重复评审或跨章收据而失真。
2. **工作流完整**：`ready_to_archive` 失败不用先 rollback；P5 能直接拿到当前正文 hash；P8 给完整 delta 契约；错误码能区分格式错与不可变规则。
3. **提示可行动**：advisory 带证据/差异、同一章同 code 只报一次；不再把中文正常叙事报成资源符号错误。
4. **面板可用**：项目选择器按写作/待修复/失效分组，同名标签唯一；首屏先看到“当前章 + 下一步”；advisory 与 legacy 数据可见；Host Smoke 不再污染真实注册表。
5. **升级可审计**：旧 check、旧章 effort、extra 角色、pre-0.2.3 的无 anchor 伏笔、stale `pipeline.briefs` 由 doctor 明确标出，不自动改历史数据。

**完成标准**：18 条实测问题全部有“修复/可解释的遗留”结论；新增测试先红后绿；真实 `1971` 项目只读回归符合预期；1440/390 两张渲染截图；`typecheck/lint/test/test:coverage/build/check:pack/check:artifacts/check:host` 全过；0.2.3 版本与文档同步。

## 2. 范围与非目标

### 范围

- `novel_report` 读模型：effort 回填、quality 口径、cast role、briefs。
- 工作流：`submitRevision` 从 `ready_to_archive` 回 P4；`manuscript_hash` 暴露；P8 delta schema；错误码拆分。
- `getBrief` 同章同阶段缓存快路径。
- advisory 证据、去重、`RESOURCE_MISMATCH` 规则收紧。
- `doctor` 升级审计；`check-host` 隔离；`/novel projects --prune`。
- 面板 v5：选择器分组/搜索/唯一标签、书桌式布局、advisory/legacy 展示。
- 版本、CHANGELOG、README、DESIGN、docs/tools、briefs 同步。

### 范围外

- 跨段、多单位换算的完整数字算术（0.2.3 只做同段乘式/人数×单价）。
- 无 key 维护操作的失败指纹（有 key 的写操作已覆盖）。
- 历史伏笔 anchor/legacy 的自动迁移（缺原句必须人工确认）。
- 磁盘 YAML schema 升级。

这些范围外项不以半成品形式进入 0.2.3；0.2.3 对旧数据只提供 legacy 标记，对可判定的新写入直接修复。

## 3. 基线与权威

- 代码与行为以当前工作树和 0.2.2 已发布契约（`docs/0.2.2-plan.md`、`docs/tools.md`、`README.md`）为基线。
- `docs/0.2.2-plan.md` 的行为保证继续有效；本方案只做增量修正。
- 面板 wire payload 从 v4 升到 v5；不兼容旧标签页，旧页面显示“刷新”。
- 工具 28、操作 32、门控 13、语义项 5、导出 6 不变。

## 4. TDD Route

- **模式**：`auto`。
- **决定**：`strict`（权威：账本、公共契约、持久化读模型、面板 DTO 均属于高风险/回归敏感面）。
- **测试姿态**：每个行为切片先写失败测试，再实现，最后回归；纯文档/脚本配置可 light，但 Host Smoke 隔离必须有回归检查。
- **验证命令**：`pnpm test`、`pnpm test:coverage`、`pnpm typecheck`、`pnpm lint`、`pnpm build`、`pnpm check:pack`、`pnpm check:artifacts`、`pnpm check:host`。

## 6. 工作包

### WP0：升级审计

- 新增 `legacyFindings` 读模型（service 私有 + `doctor` 输出）：
  - 旧 check：`machine.advisories` 缺失，或 `machine.violations` 中仍有 `severity=advisory`。
  - 旧章：`rounds` 或 `archived_at` 缺失。
  - 角色：`role=extra` 但 worldbook 角色提示为主角/配角/反派。
  - 伏笔：`anchor` 缺失且没有 0.2.3 写入标记（新写入的 anchorless 合法条目不算旧数据）。
  - briefs：`pipeline.briefs` 中的签名与当前章收据不一致（`state/briefs.yaml` 的历史收据是正常 append-only 审计，不报）。
- `doctor` 增加 `legacy-data` check，severity=`warning`，detail 最多列 3 项，hint 指向升级建议；不自动修改。
- 面板摘要新增 `legacy` 数组，只展示快速发现（旧章、extra、pre-0.2.3 无 anchor、stale `pipeline.briefs`），不读 800 个 check 文件；历史 receipts 不算 stale。
- 验证：混合 0.2.0/0.2.2 fixture；doctor 命中 5 类；panel payload 带 legacy；旧数据未被改写。

### WP1：可信账本

- `buildBookReport` 增加可选 `reviewAttempts`，quality：
  - 每章只取一份最终评审（service 只传当前 reviews）。
  - `dimensions[].samples` = 包含该维度的最终评审数；`quality.samples` = 最终评审章数；`quality.attempts` = committed 评审轮次（journal，历史缺口时回退文档数）。
  - `trend` 改为 `number | null`：少于 3 章返回 null；previous 少于 5 章也返回 null；新增 `trend_basis`。
- `report.effort` 从 journal 回填旧章：
  - 对 `rounds` 或 `archived_at` 缺失的已归档章，按 `op + chapter + status=committed` 统计。
  - 不写回 `chapters.yaml`；报告是读模型。
  - `final_check` 缺失时读 check 文档；读不到则 null，并保留 warning。
- `load` 只把 `receipt.chapter === pipeline.chapter` 的收据合入 `snapshot.briefs`；`queryState pipeline` 显示当前章收据。`queryState briefs` 仍返回全量审计。
- 角色：`applyStateDelta` 在 existing 角色未显式声明 role 时，用 `roleHints` 修正 `extra`；不覆盖显式 role。
- 伏笔 resolve：写入 `advance_log`（chapter、note、new_info），保持可审计。
- 验证：`1971` 两章 fixture 的 effort=8/6/8/4；每章 6/5/5/3 与 2/1/3/1；samples=2；attempts=8；第 3 章 briefs 为空；cast protagonist；FS resolved 有日志。

### WP2：工作流

- `TRANSITIONS` 增加 `ready_to_archive → submitRevision → P4`；`briefStageFor` 对 ready_to_archive 使用 P5。
- `StatusReport` 增加 `manuscript_hash: string | null`；所有 brief 的 `fields` 增加 `manuscript_hash`；P5 brief 明确 patch 示例。
- `P8` 的 `fields.delta_rules` 增加 `minimal_schema` 与 `examples`；`briefs/P8.md` 补齐每个 section 的必填字段。
- 错误码：新增 `ENGINE_ISSUE_IMMUTABLE`；`submitRevision` 修改 issue 的 dimension/location/problem/fix/severity 时使用该码，并回显 field 与 received 类型/值。
- 状态 delta 错误：`entry()` 与 `current_state`/`profile` 校验错误追加 `expected` 简要 schema。
- `getBrief` 重放：同章同 stage 的 digest 与预计算一致时，`mutate.run` 直接返回 `replayed: true`，不写新 journal、不升 revision；仍取项目写锁并先恢复 pending journal。无锁快路径因可能误恢复其他写者的 pending 事务而移除。
- 验证：归档失败后直接 revise 成功；P5 hash 可用；P8 字段含 schema；错误码分离；重复 getBrief 不新增 journal 行。

### WP3：提示降噪

- `runCheck` 对 advisories 按 code 去重，保留首条位置，合并 detail（`；`）；`machine.advisories` 只保留去重结果。
- `LOCKED_DETAIL_DRIFT` detail 带 `expected`/`actual` 片段；`DUPLICATE_PARAGRAPH` 带相似度与阈值；`RESOURCE_MISMATCH` 带 `expected sign` 与 `received` 说明。
- `RESOURCE_MISMATCH` 只在正文同窗口明确出现反向符号时报告；缺少资源名/没有符号不再报。
- advisory 面板区：未 acknowledge 的 advisories 单独展示，不混入 blocking；已 acknowledge 显示计数。
- facts 空提醒：P8 或 doctor 在 strict 模式且 worldbook.facts 为空时给 info；不阻断。
- 同段乘式/人数×单价：使用已有数字解析做局部算式校验，advisory；跨段/多单位换算不在本轮。
- 同错重试：有 key 的写操作在 journal 记录 `retry_key`/`retry_context`；同内容同 brief/stage/revision 直接拒绝 `ENGINE_RETRY_UNCHANGED`，换 brief 或改内容后放行。
- 中文句密度上限 8→10，避免把普通短句叙事当异常；仍是 advisory。
- 验证：同 code 只一条；证据文本可读；无符号中文叙事不再报；反向符号仍报；acknowledge 后面板计数变化；乘式错误/正确各一条。

### WP4：项目卫生与面板 v5

- `check-host.mjs`：临时 `HOME`、`DSH_HOME`、`stateDir` 都指向临时目录；跑完校验真实 `projects.yaml` 未新增 `Host Smoke`；不删除真实注册表。
- `/novel projects --prune [--yes]`：
  - 默认列出 `missing/not-project/unreadable` 注册行；
  - `--yes` 才调用 `forgetProject`，不删除项目目录；
  - 如果 active 被清理，registry.active 同时清空。
- 选择器：
  - 分组：写作中（ok）、待修复（damaged）、失效（missing/not-project/unreadable）。
  - 默认隐藏失效组；有当前选中失效项时显示该项；提供“显示失效项目”开关。
  - 可见项目 >6 时提供搜索框（隐藏失效项不计入，避免单书被搜索框占据）；同名标题用最短唯一路径后缀区分；失效项标签带状态。
- 面板 v5：
  - payload `schemaVersion=5`；`SummaryDto` 增加 `advisories`、`legacy`；`quality` 增加 `samples/attempts/trend` 可空。
  - 布局：紧凑顶栏 → “当前章/下一步”首屏卡 → 统计条 → 双栏工作台（左：阶段+门控+提示+可滚动章节表；右：全书+活动）。
  - 视觉：单强调色、无径向渐变/大阴影、标题 24–28px、统计条非卡片、12–14px 正文。
  - 辅助：advisory 黄色区、legacy 灰色区、门控红色区；移动端 390px 单列无横向溢出。
- 验证：真实注册表 fixture 中 7 条 Host Smoke 被分组/隐藏且标签唯一；`--prune` 只删注册行；v5 旧标签页提示刷新；1440/390 截图；键盘/ARIA 保持。

### WP5：文档、版本与发布验收

- `DESIGN.md`：report 读模型、advisory 去重、面板布局、Host Smoke 隔离。
- `docs/tools.md`：`novel_status.manuscript_hash`、`novel_report.quality` 新字段、错误码。

- `docs/0.2.3-acceptance.md`：18 条问题矩阵、真实项目证据、截图路径、未覆盖边界。
- 验证：全量门禁 + 真实 2 章链路 + 只读 1971 回归 + 1440/390 截图。

## 8. 兼容与回滚

- 不升磁盘 schema；旧项目原样可读。
- 面板 v5 只升 wire；旧标签页显示“刷新”，不读错数据。
- `report` 新字段是增量；旧字段保留。
- `/novel projects --prune` 必须显式 `--yes`；默认零写入。
- `check-host` 只改测试脚本，不影响生产状态目录。

## 9. 风险

- **真实项目 fixture 含旧 check 与旧章**：必须区分“修复新代码”与“展示旧数据”，不能把 legacy 数据当新 bug 重写。
- **面板重构**：保持 `select[aria-label="切换项目"]`、`nwe-next`、`全书规划`、`目录不存在` 等既有可访问/测试锚点。
- **brief 重放 race**：返回缓存 digest 前必须在项目锁内确认 receipt 与当前章匹配，并完成 pending journal 恢复；写入路径仍二次校验。
- **advisory 去重**：不能吞掉 blocker；blocker 保持逐条。
