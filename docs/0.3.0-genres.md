# 0.3.0 类型体系：大类 / 小类 / 标签

> 状态：已实施（运行时 `taxonomy/taxonomy.yaml` 已落地）
> 目标版本：`0.3.0`
> 类型体系版本：`taxonomy_version: 1`
> 关联：`docs/0.3.0-plan.md` §7.10、`docs/0.3.0-rulepack.md`

---

## 0. 结论先行

0.2.x 只有 12 个平铺题材（`玄幻修仙`、`都市现代`、`西方奇幻`……），问题不是数量少，而是**维度混在一起**：

- “无限流”既是世界观，又是结构，又是题材；
- “甜宠”是情节，也是情感，也是市场标签；
- “大女主”是主角类型，也是受众；
- “克苏鲁”是世界观，也是风格；
- 旧 12 类型无法表达“都市异能 + 无限流 + 群像 + 无 CP + 快节奏”这种真实组合。

0.3.0 固定为三级：

```text
大类（major，12 个）
  └─ 小类（sub，100 个）
       └─ 标签（tag，137 个，11 个 facet）
```

一句话：

> **大类决定“书架”，小类决定“写法”，标签决定“卖点与约束”。**

固定结论：

1. 12 个大类、100 个小类、137 个标签；全部有稳定 ASCII ID。
2. 每本书必须选 **1 个大类 + 1 个小类 + 3–12 个标签**；小类必须属于大类。
3. 标签分 11 个 facet：世界观、主角、情节、风格、主题、设定、结构、视角、情感、节奏、市场。
4. 每个 facet 最多 3 个标签；总标签 3–12 个；冲突标签拒绝，缺失依赖标签拒绝并给建议。
5. 受众（男频/女频/通用/青少年/成人）和平台（番茄/起点/七猫/晋江）是**独立字段**，不塞进标签。
6. 标签排序固定：facet 顺序 + tag ID；保证 brief/digest 稳定。
7. 规则包按小类 ID 建 profile；大类提供默认值；标签提供覆盖值；优先级 `tag > sub > major > global`。
8. 同一组标签对同一规则键给出不同值时，规则包编译/项目校验直接拒绝，不做“后者覆盖前者”。
9. 旧 12 类型只做单向映射到“小类 + 推荐标签”；导入后需要作者确认，不静默改写。
10. 工作台提供级联选择器、标签搜索、冲突提示、推荐标签、规则预览；不允许自由文本类型。

## 1. 设计原则

| 原则       | 含义                                               |
| ---------- | -------------------------------------------------- |
| 单一维度   | 一个字段只回答一个问题；受众、平台、类型、标签分开 |
| ID 稳定    | ID 一旦发布永不复用；中文 label 可改，别名可加     |
| 可组合     | 小类决定主写法，标签表达交叉卖点                   |
| 可校验     | 每个组合都能在编译期/保存期验证                    |
| 可解释     | 每个标签带说明、推荐小类、冲突、规则影响           |
| 可迁移     | 旧 12 类型有明确映射，不靠猜                       |
| 不自由生长 | 0.3.0 不接受用户自定义标签；新增走 taxonomy 版本   |

## 2. 数据结构

项目文件 `studio.yaml`：

```yaml
schema_version: 2
format_version: 2
genre:
  major: fantasy
  sub: fantasy.xianxia
  tags:
    - world.eastern_cultivation
    - plot.progression
    - prot.weak_to_strong
    - set.leveling
    - tone.hot_blooded
    - pace.fast
audience: male # male | female | general | teen | adult
platform: fanqie # fanqie | qidian | qimao | jinjiang
```

展示：

```text
幻想 / 仙侠
东方修真 · 升级流 · 废柴逆袭 · 等级 · 热血 · 快节奏
```

### 2.1 taxonomy 文件

```text
taxonomy/
  taxonomy.yaml          # 唯一源：majors / subs / tags / aliases / profiles
  schema.json            # 生成给编辑器/工作台
  CHANGELOG.md           # taxonomy 版本变更
```

```yaml
taxonomy_version: 1
majors:
  - id: fantasy
    label: 幻想
    aliases: [奇幻, 幻想类]
    audience_default: general
    platform_fit: { fanqie: high, qidian: high, qimao: medium, jinjiang: low }
    subs:
      - id: fantasy.xianxia
        label: 仙侠
        aliases: [修真, 修仙, 仙侠修真]
        audience_default: male
        recommended_tags:
          - world.eastern_cultivation
          - plot.progression
          - set.leveling
        profile:
          foreshadow_min_dormancy: 2
tags:
  - id: world.eastern_cultivation
    label: 东方修真
    facet: world
    aliases: [修真世界, 修仙世界]
    conflicts: [world.western_magic]
    requires: []
    recommended_for: [fantasy.xianxia, fantasy.xuanhuan]
    profile:
      lexicon_add: [灵气, 丹田, 筑基]
```

### 2.2 字段

| 字段               | 适用          | 含义                                    |
| ------------------ | ------------- | --------------------------------------- |
| `id`               | major/sub/tag | 稳定 ASCII ID；小类格式 `<major>.<sub>` |
| `label`            | 全部          | 中文展示名                              |
| `aliases`          | 全部          | 搜索/导入别名；不参与 digest            |
| `audience_default` | major/sub     | 默认受众；项目可覆盖                    |
| `platform_fit`     | major/sub     | 平台适配提示；不限制创建                |
| `recommended_tags` | sub           | 推荐标签；工作台排序用                  |
| `conflicts`        | tag           | 互斥标签；双向校验                      |
| `requires`         | tag           | 依赖标签；缺失时拒绝并提示              |
| `recommended_for`  | tag           | 推荐小类                                |
| `profile`          | major/sub/tag | 规则覆盖；见 §7                         |
| `status`           | 全部          | `active` / `deprecated`                 |
| `replaced_by`      | 全部          | 弃用后的替代 ID                         |

## 6. 组合规则

### 6.1 必填

```ts
interface GenreSelection {
  major: MajorId
  sub: SubId // 必须属于 major
  tags: TagId[] // 3–12 个
  audience: 'male' | 'female' | 'general' | 'teen' | 'adult'
  platform: 'fanqie' | 'qidian' | 'qimao' | 'jinjiang'
}
```

### 6.2 标签约束

1. 3–12 个。
2. 每个 facet 最多 3 个。
3. 不允许重复。
4. `conflicts` 双向拒绝。
5. `requires` 缺失时拒绝，并给出“加上 X”提示。
6. 至少 1 个 `tone` 或 `theme` 标签。
7. 排序：facet 顺序 `world,prot,plot,tone,theme,set,struct,pov,emo,pace,market`，同 facet 按 ID。
8. 标签只影响 profile 与推荐，不改变硬门控代码。

### 6.3 冲突示例

| 组合                                                | 结果                           |
| --------------------------------------------------- | ------------------------------ |
| `prot.invincible` + `prot.weak_to_strong`           | 拒绝                           |
| `world.eastern_cultivation` + `world.western_magic` | 拒绝                           |
| `prot.no_cp` + `emo.one_v_one`                      | 拒绝                           |
| `pov.first` + `pov.ensemble`                        | 拒绝                           |
| `plot.system_flow` + `set.system_panel`             | 允许（互补）                   |
| `world.infinite_world` + `struct.infinite`          | 允许（强化）                   |
| `romance.sweet` + `emo.angst`                       | 允许但警告：甜虐混合需明确比例 |

### 6.4 受众与平台

- `audience` 独立字段，不从标签推断。
- `platform` 独立字段，不参与 digest 的规则 profile，只影响导出/雷达。
- 小类有 `audience_default`，项目创建时可一键采用；允许覆盖。
- `platform_fit` 只做提示，不阻止创建。

## 7. 与规则包集成

### 7.1 profile 层级

```text
global
  └─ major profile
       └─ sub profile
            └─ tag profile（多个标签按固定顺序）
```

优先级：`tag > sub > major > global`。

### 7.2 可覆盖的键

只允许规则包白名单：

- `foreshadow_min_dormancy`
- `motif_min_dormancy`
- `foreshadow_dormant_after`
- `dialogue_ratio`
- `paragraph_max_words`
- `water_words`
- `pleasure_keywords`
- `lexicon_add`
- `lexicon_remove`

不允许标签改：门控编号、评分维度、规则码、硬 blocker 语义、事务行为。

### 7.3 冲突检测

- 同一项目选中的多个标签，对同一 key 给出不同值 → 保存/编译拒绝。
- 同一 key 值相同 → 允许。
- 标签 profile 与小类 profile 冲突 → 标签优先，但工作台显示“覆盖提示”。
- `lexicon_add/remove` 按集合并集/差集处理，不冲突。

### 7.4 规则包结构

```yaml
genres:
  fantasy.xianxia:
    note: '...'
    profile:
      foreshadow_min_dormancy: 2
  mystery.infinite:
    note: '...'
    profile:
      foreshadow_dormant_after: 10

genre_majors:
  mystery:
    profile:
      foreshadow_dormant_after: 15

tag_profiles:
  world.eastern_cultivation:
    profile:
      lexicon_add: [灵气, 丹田, 筑基]
  pace.fast:
    profile:
      paragraph_max_words: 90
```

规则包编译器校验：

- 所有 `genres` key 必须是 taxonomy 小类 ID。
- 所有 `genre_majors` key 必须是大类 ID。
- 所有 `tag_profiles` key 必须是标签 ID。
- profile 只能出现 §7.2 的键。
- 同一标签组合冲突由项目保存期校验。

## 8. 与工作台集成

### 8.1 创建项目

1. 选大类（12 张卡）。
2. 选小类（按大类过滤，显示一句话定位 + 推荐标签）。
3. 选标签（按 facet 分组，搜索、冲突灰显、依赖提示）。
4. 选受众、平台。
5. 右侧实时预览：
   - 类型路径 `幻想 / 仙侠`
   - 标签摘要
   - 规则影响（如“伏笔休眠 2 章”“对话比 0.35–0.55”）
   - 平台适配提示
6. 保存前校验组合；失败给出具体冲突/缺失。

### 8.2 已有项目

- 类型路径显示在 Topbar/面包屑。
- Settings 可修改类型；修改会生成新 `studio.yaml` 版本，旧版本保留。
- 修改类型不自动改已写章节；下一次 brief 使用新 profile。
- 修改标签时，若与当前 canon 冲突（如“无CP”加入但有恋爱线），给 warning，不阻断已有文本。

### 8.3 Brief / Studio

- 每个任务包带 `genre_path`、`audience`、`tags`、`profile_snapshot`。
- `profile_snapshot` 是该章实际生效的规则阈值，保证 digest 稳定。
- Review Center 显示“类型约束”卡：哪些标签影响了哪些阈值。
- Radar 用 taxonomy ID 聚合趋势，不用自由文本。

## 10. 校验与编译

### 10.1 taxonomy 编译断言

1. `taxonomy_version` 正整数。
2. 12 个大类，ID 唯一，`^[a-z][a-z0-9_]*$`。
3. 100 个小类，ID 唯一，格式 `<major>.<sub>`，父大类存在。
4. 137 个标签，ID 唯一，facet 合法。
5. 同一 facet 内 label 唯一；全局 alias 不冲突。
6. `recommended_tags` 必须存在，且不冲突。
7. `conflicts` 双向；不能自指。
8. `requires` 无环，深度 ≤2。
9. `recommended_for` 必须是小类 ID。
10. 所有 `status: deprecated` 必须有 `replaced_by`。
11. 大类/小类/标签的 profile 只能出现白名单键。
12. 默认项目组合必须通过 §6 校验。

### 10.2 项目保存校验

```text
validateGenreSelection(selection, taxonomy):
  1. major exists & active
  2. sub exists & active & sub.major === major
  3. 3 <= tags.length <= 12
  4. tags unique & active
  5. per-facet <= 3
  6. no conflicts
  7. requires satisfied
  8. at least one tone/theme tag
  9. audience valid
  10. platform valid
  11. profile conflicts none
```

失败返回：

```json
{
  "code": "GENRE_SELECTION_INVALID",
  "message": "标签组合冲突",
  "details": {
    "conflicts": [["prot.invincible", "prot.weak_to_strong"]],
    "missing": ["emo.one_v_one"],
    "suggestions": ["prot.weak_to_strong", "emo.one_v_one"]
  }
}
```
