# 0.2.9 · 可信工作台与工具契约

0.2.9 不是给面板换一层皮。三份只读审计确认，当前真正影响信任的是三件事：**归档卡的证据链可以被绕过、面板冷刷新已经不适合 15 秒轮询、工具参数的自由 JSON 仍在制造不可恢复的解析失败。** 工作台重构必须建立在这三件事修好之后。

本计划把 0.2.8 遗留的卷 id/改名/导入、规则包误报，以及两份面板审计、后端审计、工具契约审计、DSH 解析链审计全部并入 0.2.9，不拆到“以后”。

**Aegis Visibility**：这次同时动持久化记录（`ChapterRecord`）、公开读模型（`panel-contract`/remote DTO）、工具契约（28 个工具的参数 schema）、客户端交互和规则包。每一条都可能被旧项目、旧标签页或模型调用链放大，必须有可交接的长期计划，不能靠一次性的 UI 改动。

## 目标

1. `novel_amend` 在 `outline.yaml` 不可读、备份缺失时也不能改写归档卡的 `goal/conflict/hook/notes/target_words/cast/archived_at`；真实卡能修，猜的卡不能修，没有前像时 fail closed。
2. 面板冷刷新在 300/600 章项目上相对 0.2.8 至少降低 50%，目标 ≤800ms / ≤1.2s；warm ≤200ms；2000 章项目仍可分页浏览。
3. 面板所有 section 有 64KB 字节上限、`{total,returned,truncated,next_cursor}` 窗口信息和 `ETag/304`；不再用字符数冒充字节数，也不再把截断数据说成完整。
4. 26 个自由 JSON 入参收敛到 2–4 个真正泛型；`summary`、review、check、archive、handoff、worldbook 全部定形；正文的引号/换行风险有压力用例；工具参数失败能定位到工具名。
5. 预设、briefs、skill、工具描述统一“严格 JSON、写工具串行、失败恢复、归档后回 P1”，删除“JSON 字符串也可以”的诱导。
6. 规则包先修既有 advisory 误报（`RELATION_UNKNOWN` 子串、`NUMERIC_FACT_MISMATCH` 单位、算术口语数、`RESOURCE_MISMATCH` 符号/绑定/证据、`DUPLICATE_PARAGRAPH` 证据、`LOCKED_DETAIL_DRIFT` 首段），再做 genre profile 与 soft 词表；不新增门控、不放宽阈值。
7. 面板从单页摘要改成七栏工作台；先修 4 个 P1，再做信息架构、可访问性、浅深色、390px 和键盘操作；所有图表/列表/表格有可读的文本值。
8. 0.2.9 发布前有真实模型 20 章、性能、最大 payload、损坏状态、旧项目兼容、发布门禁六类证据。

## 不在 0.2.9

- 不新增章节阶段、工具、操作、门控、语义项或导出种类；工具数 28、操作 32、门控 13、语义项 5、导出 6 保持不变。
- 不把 DSH 的 malformed tool JSON 改成“协议层非致命”。那是 0.3 的决策；0.2.9 只做诊断、有限重试和插件侧降发生率。
- 不做 SQL 查询台、会话记录、评审历史假栏目；引擎没有 SQLite/ORM，sessions/reviews 不是项目状态。
- 不引入 Ant Design、ECharts 或第二套设计系统；没有对应 primitives 的地方用语义 HTML/CSS/SVG。
- 不加第二条侧边栏；DSH 已经有侧边栏，工作台用顶部 tabs。
- 不重写旧项目数据；`archive_card` 是可选新字段，旧记录走只读回退，不能证明时 fail closed。
- 不改 `pipeline.stage` 枚举、`active_chapter`、归档门控、评分 minScore 或规则 blocker 阈值。
- 不 commit、不 push、不打 tag、不发布；发布必须另一次明确指令。

## 技术栈与架构

- Node `>=24.9.0`，pnpm `11.28.9`，TypeScript 5.6，React 18.3，DSH `>=0.2.1-rc.2 <0.3.0`。
- 客户端：React + `@deepseek-ai/dsh-client-ui-primitives`；面板布局用一段 layout-only CSS 字符串，不新增 `.module.css`（当前 tsdown 没有 CSS loader）。
- 服务端：TypeScript + YAML/JSONL 文件存储；不使用 SQL。
- 测试：Vitest + happy-dom；性能基准单独跑，不放进默认测试的硬时限。

### 当前数据流

```text
project files (novel.yaml / state/*.yaml / outline / worldbook / chapters)
  -> EngineService.loadAt / Snapshot
  -> buildBookReport + buildPanelBookData
  -> panelSnapshot (full payload)
  -> remote panelBundle
  -> client buildView + panel render
```

问题：`panelSnapshot` 每次都构建完整报告，读全部归档 review、全部 history、多次 journal；`panelBundle` 只返回摘要和 30 行，但成本已经在服务端付掉。客户端 15 秒轮询一次全量。

### 目标架构

```text
project files
  -> Snapshot (single load, one journal read)
  -> PanelReadModel
       summary (small, cached)
       section(overview|chapters|characters|foreshadows|timeline|
               relationships|worldbook|quality|health)
       detail(chapter|quality)  // only when explicitly requested
  -> panelBundle (v6-compatible summary) + panelSection (v7 section)
  -> client shell + tabs + section cache
```

**单一 owner**：

- 归档卡证据：`ChapterRecord` + `service.ts` 的归档/amend 路径，不在 outline 里另存一份“可信副本”。
- 读模型：`src/engine/insight.ts` 的 `buildBookReport` / `buildPanelBookData` 是唯一聚合 owner；`panelSnapshot` 不另算一套 quality。
- 公开契约：`src/panel-contract.ts` + `src/client/dto.ts` + `src/remote/index.ts`。
- 工具契约：`src/tools/index.ts` 的 `parameters`；引擎校验仍是跨字段/计数/范围的 owner。
- 规则包：`src/rules/*` + `rulepacks/default.yaml`；genre profile 只由 compiler 解析一次。
- 大纲卷：`src/engine/outline-merge.ts` + `book.ts`；导入/导出不另写一套合并规则。

## Ripple Signal Triage

- **持久化/兼容**：`ChapterRecord.archive_card` 影响归档、amend、备份、索引校验、restore、导出和旧项目读取。旧记录没有该字段，必须走只读回退，不能自动写。
- **公开读模型**：`panel-contract.ts`、`dto.ts`、`remote/index.ts` 影响旧标签页、client tests、panel-v5/v6。`panelBundle` 保持 v6 兼容；新 section 是 additive。
- **工具契约**：26 个 schema 影响 28 个工具的调用、`tool-contract` 测试、briefs、skill、`asJson` 兼容分支。严格 schema 会拒绝以前“能到引擎再报错”的坏形状，这是预期，但必须补回归。
- **规则包**：`genres.profile` 影响 compiler、`validate-rulepack`、checks、README/DESIGN；只影响 advisory，不影响 blocker。
- **大纲卷 id**：影响 `novel_outline`、`novel_outline_import`、`novel_blueprint`、restore、export；旧卷没有 id，必须 title/range 回退。
- **UI**：影响 client 入口、primitives external、build、53 条现有测试、响应式与主题；不新增第二套 UI owner。

## Plan Pressure Test

- **Owner / contract fit**：D1 的 owner 是 `ChapterRecord`，不新建“归档卡仓库”；D2 的 owner 是 `panelSnapshot`/`panelSection`，不另写 quality 逻辑；工具契约的 owner 是 `src/tools/index.ts`，引擎只保留跨字段校验；规则包只有一个 compiler 解析 profile；卷 id 只走 `outline-merge.ts`/`book.ts`。
- **Higher-level path**：先用 section 化解决成本和 payload，再换 UI；先修证据链，再做工作台；先定工具 schema，再改预设文案。顺序反了会返工。
- **Verification scope**：D1 有真实/猜卡/无前像回归；D2 有读次数结构测试 + 300/600 章基准；D3 有最大文档字节测试；UI 有 role/text、键盘、390px、浅深色；规则包有正反例；卷 id 有 round-trip。
- **Task executability**：每个 WP 都有文件、变更、测试、兼容/回滚；WP0 可独立先发布，WP1/WP3 可在 UI 前完成，WP4–WP7 依赖 v7 contract，WP8/WP9 独立。
- **结论**：没有未决 owner 冲突，可以进入任务分解；唯一外部依赖是 DSH 上游 issue/PR，已单独隔离。

## TDD Route

- 模式：`auto`。
- **strict**（先写会失败的回归，再实现到绿）：
  - D1 真实卡成功/猜卡失败/无前像失败；
  - D2 的“非 quality section 不读 review/history 正文”“单请求只读一次 journal”结构测试；
  - D3 的 64KB 字节上限、最大文档；
  - D4–D14 的读模型行为；
  - 26 个 schema 的类型/必填/归档卡兼容；
  - 4 个面板 P1 和 P2 的可访问性/交互行为；
  - 卷 id/改名/导入。
- **light**（实现后补现有测试）：CSS 视觉、字号、浅色对比、tutorial 文案、文档。
- **skipped**：仅限纯文档改写；代码项没有 skipped。
- 不把“改测试断言”当修复；旧测试里对 CSS 字符串、源码文本、class 的断言必须在 UI 重构时改成 role/text 行为断言。

## 兼容边界

- `panelBundle` 的 v6 字段保持；新 `panelSection` 是 v7 additive。旧标签页刷新前仍能读摘要。
- `REMOTE_VERSION` 保持在 6；section payload 自己带 `payload_version: 7`，避免旧 tabs 误判。
- `ChapterRecord.archive_card` / `archive_card_digest` 可选；旧记录没有时，amend 先尝试当前 outline 卡；仍无可证明前像则 `ENGINE_SCHEMA_INVALID` + 恢复指引，不自动改数据。
- 工具 schema 严格化会拒绝字符串形式的大对象；`asJson` 只保留给动态 map/旧 provider，不再出现在 briefs/描述/skill 的推荐写法里。
- `novel_outline.chapters` 必须接受归档卡回传的 `status:'archived'`、`word_count`、`score`、`archived_at` 等额外字段，不能把合法回传新拒掉。
- `genres.profile` 可选；旧 rulepack 没有 profile 时沿用全局阈值。
- 大纲卷没有 `id` 时沿用 title/range；新写入才分配 id；不强制迁移旧项目。
- 旧项目选择 localStorage key 保留；新增“跟随当前项目”用空字符串 sentinel，不自动清用户选择。

**变更**：

1. `ChapterRecord` 增加可选：

   archive_card_digest?: string

   `ArchivedCardSnapshot` 固定 `title/scene_type/target_words/cast/goal/conflict/hook/notes/archived_at`，在归档事务中从**已验证的归档卡**写入。
