# dsh-novel-write-engine 0.2.0 迭代方案：整书生命周期

> 状态：已完成（本地验证）。目标版本 `0.2.0`。本文件是 0.2.0 的唯一范围声明。
> 原则：**0.2.0 不做“先发一半、下版再补”**。本文列出的每一条都必须在 0.2.0 内闭环；没有列入的能力不属于 0.2.0 承诺，也不以“遗留项”形式进入后续版本。

---

## 1. 一句话

0.1.x 解决的是「一章能不能被机械地写对、审对、归档对」；0.2.0 解决的是「**一本书能不能被完整地规划、持续地写、随时看清、坏了能修**」。

0.2.0 把引擎从「单章状态机」升级为「整书操作系统」：

```
书级蓝图 → 卷/章大纲 → 世界观设定集 → 单章流水线（P1–P9）
      ↑                                      │
      └────────── 归档回写大纲 ←─────────────┘
      └────────── 报告 / 诊断 / 搜索 / 面板 ──┘
```

---

## 2. 用户旅程（0.2.0 必须全部走得通）

1. **开书**：`novel_init` 建项目，同时建立书级蓝图骨架、空大纲、空世界观设定集；不强制用户先写大纲。
2. **规划全书**：`novel_blueprint` 写书名之外的梗概、主题、基调、视角、读者、卖点、结局与卷结构；`novel_outline` 写卷/章卡；也可用 `novel_outline_import` 从 Markdown / YAML / JSON 导入现成大纲。
3. **规划世界观**：`novel_worldbook` 写设定、规则、势力、地点、角色小传、术语、前史；可增量更新。
4. **写一章**：P1 世界计划、P2 章节计划、P3 初稿、P4 评审、P5 修订、P6 校验、P7–P9 归档；P1/P2/P3 的任务书自动带入本书蓝图、当前卷目标、当前章卡与相关世界观条目。
5. **大纲对齐**：一旦大纲进入严格模式，P2/P3 必须与当前章卡一致（标题、场景类型、目标字数区间、章卡 cast）；不一致由 PG-13 拒绝，并给出修复动作。
6. **归档回写**：归档事务同时把章卡标记为 `archived`，写入实际字数、评分、标题与场景类型；大纲成为书的真实进度视图。
7. **看清全书**：`novel_status` 带书级摘要；`novel_report` 给进度、质量、节奏、角色、伏笔、时间线、关系、活动；面板（`GET /api/novel-write-engine/panel`）给全书规划、世界观、质量趋势、健康度、最近活动。
8. **诊断与修复**：`novel_doctor` 检查项目、日志、索引、正文、大纲、世界观、锁与备份；`novel_amend` 可修可读性损坏的文档；`novel_reopen` 可把已归档章安全重开到 P3。
9. **查阅**：`novel_search` 跨正文、摘要、大纲、世界观、台账搜索，带章号、段落号与片段。
10. **成书**：导出 `md` / `txt` / `epub`，以及 `outline` / `worldbook` / `proposal`（书级提案）。
11. **上手**：`novel_guide` 按当前状态给「下一步 + 命令 + 提示」；面板空状态、命令帮助、README 五分钟路径使用同一套术语。

## 3. 数据模型

### 3.1 新增文档

所有新文档仍使用 `schema_version: 1`；0.2.0 **不修改** 0.1.3 已落盘的 `novel.yaml` / `state/*` 字段，因此不需要迁移链。新增文档由 `narrow()` 统一窄化，未知顶层键拒绝。

#### `outline/outline.yaml`

```yaml
schema_version: 1
updated_at: '2026-10-28T12:00:00.000Z'
book:
  premise: '一句话前提'
  logline: '一段话梗概'
  themes: ['成长', '选择']
  tone: '冷峻、克制'
  pov: '第三人称限知'
  audience: '男频，18–30'
  selling_points: ['反套路', '群像']
  ending: '主角放弃复仇，保住城市'
  strict: true
volumes:
  - id: V1
    title: '第一卷 雨夜来信'
    start_chapter: 1
    end_chapter: 30
    goal: '主角被卷入旧案'
    arc: '从旁观到入局'
    climax: '第30章 当面对质'
    status: planned
chapters:
  - num: 1
    volume: 1
    title: '开端之雨'
    scene_type: '日常过渡章'
    goal: '收到无名信'
    conflict: '是否拆开'
    hook: '蜡印上的日期是明天'
    cast: ['他']
    target_words: [2000, 3000]
    notes: ''
    status: planned
    archived_at: null
    word_count: null
    score: null
```

规则：

- `book.strict` 默认 `false`；`novel_outline` 首次提交且作者从未显式选择过 strict 时默认置 `true`。`book.strict_explicit` 是持久化的内部来源标记，用来区分“从未选择”和显式 `strict:false`；它不改变严格模式的语义。
- 卷区间不得重叠；`end_chapter >= start_chapter >= 1`；若项目 `targets.total_chapters` 非空，卷末不得超过目标，章卡编号也不得超过目标。
- 章卡 `num` 唯一；标题为 4–8 字正文（与 P2/P3 同一规则）；`scene_type` 四选一；`goal/conflict/hook` 非空；`cast` 最多 8 个且不重复；`target_words` 为正整数区间。
- `status` 只允许 `planned | archived`；`archived_at/word_count/score` 只能由归档事务写。
- 已归档章卡不可删除、不可改标题/场景/目标字数/cast/归档字段；要改必须先 `novel_reopen`。

#### `outline/worldbook.yaml`

```yaml
schema_version: 1
updated_at: '...'
premise: '世界一句话'
setting: '时代、地点、基本秩序'
rules:
  - { name: '灵气不能离体', description: '离体即溃散' }
factions:
  - { name: '巡夜司', description: '负责处理异常', goal: '维持表面秩序' }
locations:
  - { name: '旧城区', description: '被遗忘的街区', layout: '窄巷与废弃厂房', capacity: 3000 }
characters:
  - { name: '他', role: '主角', description: '档案员', arc: '从自保到承担' }
glossary:
  - { term: '蜡印', definition: '旧案相关的封缄' }
backstory:
  - { time: '十年前', event: '旧案发生' }
themes: ['记忆', '责任']
```

世界观是**规划层**，不是正文影子：它不会自动写进 `state/world.yaml`；只有正文出现并经归档 delta 核销的实体才进入台账。它只用于任务书上下文、报告、大纲校验与导出。

### 3.2 既有文档的扩展

- `state/chapters.yaml` 不变；大纲是独立文件，避免把两套真相混在一起。
- `state/pipeline.yaml` 不变；大纲不参与阶段推进，只在 PG-13 处作为输入。
- `novel.yaml` 不变；书级蓝图放在 `outline/outline.yaml`，避免项目定义频繁重写。

### 3.3 文件布局（0.2.0）

```
<projectRoot>/
├── novel.yaml
├── outline/
│   ├── outline.yaml          # 书级蓝图 + 卷 + 章卡
│   └── worldbook.yaml        # 世界观设定集
├── chapters/
├── plans/
├── reviews/
├── checks/
├── state/
├── exports/
└── backups/
```

## 4. 服务操作（31 个）

在 0.1.3 的 22 个操作上新增 9 个；`novel_reopen` 计入维护操作。面板路由使用 `panelBundle`，它是三个 panel 投影的组合入口，不增加业务操作计数。

| 类别 | 操作 | 写盘 | 说明 |
| --- | --- | --- | --- |
| 书级 | `submitBookPlan` | 是 | 写书级蓝图与卷结构 |
| 书级 | `submitOutline` | 是 | 写章卡；严格模式、归档卡保护、归档章回填 |
| 书级 | `importOutline` | 否/是 | 解析 Markdown/YAML/JSON；`dry_run` 只预览 |
| 书级 | `submitWorldbook` | 是 | 增量合并世界观各段 |
| 维护 | `reopenChapter` | 是 | 从归档备份恢复，重开到 P3 |
| 查询 | `search` | 否 | 跨正文/摘要/大纲/世界观/台账 |
| 查询 | `doctor` | 否 | 结构化体检 |
| 查询 | `report` | 否 | 全书报告 |
| 查询 | `guide` | 否 | 上手与下一步引导 |

既有 22 个操作不变；`getStatus`、`stats`、`export`、`panelSummary` 的返回增加书级字段。

### 4.1 `novel_init` 扩展

新增可选参数：`premise`、`logline`、`themes`、`tone`、`pov`、`audience`、`selling_points`、`ending`、`strict_outline`。初始化时写入：

- `outline/outline.yaml`：`book` 写入 `premise/logline/themes/tone/pov/audience/selling_points/ending`；`strict` 取 `strict_outline ?? false`；无卷、无章卡。书名/类型/平台/目标章数仍以 `novel.yaml` 为唯一真相，不复制进 `book`，避免两个 SSOT。
- `outline/worldbook.yaml`：空文档，`premise` 取 `premise`。

不填也能开书；`novel_guide` 会把蓝图/大纲/世界观列为推荐步骤，而不是硬门槛。

### 4.2 `novel_blueprint`

参数：`premise`、`logline`、`themes[]`、`tone`、`pov`、`audience`、`selling_points[]`、`ending`、`strict`、`volumes[]`（`title/start_chapter/end_chapter/goal/arc/climax`）。

- 全部可选；未提供的字段保留原值。
- `volumes` 提供时整体替换；校验不重叠、连续、合法区间、与 `total_chapters` 不冲突。
- 返回 `{premise, logline, strict, volumes, chapters}`。
- 事件：`novel/planned`（kind=`blueprint`）。

### 4.3 `novel_outline`

参数：`book?`（同 blueprint 的部分字段）、`volumes?`、`chapters`（必填数组）、`strict?`。

- 章卡字段同 3.1；引擎补齐 `status/archived_*`。
- 已归档章节若不在输入中，引擎从 `state/chapters.yaml` 自动回填归档卡；已归档卡若被改动，拒绝。
- 卷可省略；省略时保留原卷。章卡 `volume` 省略时按卷区间推导；落在卷外则为 `null`。
- 返回 `{planned, archived, total, strict, volumes}`。
- 事件：`novel/planned`（kind=`outline`）。
- 严格模式：`strict` 省略时沿用当前值；首次提交默认 `true`。

### 4.4 `novel_outline_import`

参数：`format`（`markdown|yaml|json`）、`content`、`dry_run`。

- 解析后与 `novel_outline` 使用同一套校验；`dry_run=true` 只返回结构化结果、警告与差异预览，不写盘。
- Markdown 语法：

```markdown
# 书名
> 一句话梗概
主题：成长、选择
基调：冷峻
视角：第三人称限知
读者：男频
卖点：反套路、群像
结局：主角保住城市

## 第一卷 雨夜来信（第1-30章）
目标：主角被卷入旧案
弧线：从旁观到入局
高潮：第30章 当面对质

### 第1章 开端之雨
场景：日常过渡章
字数：2000-3000
角色：他
目标：收到无名信
冲突：是否拆开
钩子：蜡印上的日期是明天
备注：无
```

- 解析器对未知行给出警告并跳过；缺少章节标题/场景类型/目标区间直接报错，不静默补默认值。
- `format=yaml|json` 接受 `{book?, volumes?, chapters}`；与 `novel_outline` 同形。

### 4.5 `novel_worldbook`

参数：`premise`、`setting`、`rules[]`、`factions[]`、`locations[]`、`characters[]`、`glossary[]`、`backstory[]`、`themes[]`。

- 按段替换：只传某一段就只替换该段；空数组表示清空该段。
- 校验名称唯一、必填文本非空、`capacity` 非负整数。
- 返回各段计数。
- 事件：`novel/planned`（kind=`worldbook`）。

### 4.6 `novel_reopen`

参数：`chapter`、`reason`（必填，写入 journal）。

- 只允许已归档章；活动章必须是 `chapter + 1` 且尚未写正文，防止覆盖正在写的下一章。
- 从该章归档事务的 `backups/<txid>/` 恢复 `novel.yaml` 之外的所有预映像（索引、台账、handoff、archive-digests、正文），再把 pipeline 设为 `chapter=N / stage=P3 / rounds=0 / briefs={}`。
- 保留 `reviews/ checks/` 旧文件；后续 P4/P6 会覆盖它们。
- 备份缺失或被清理（`backupRetention`）时拒绝，并提示无法重开。
- 事件：`novel/reopened`。

### 4.7 `novel_search`

参数：`query`、`scope`（`all|chapters|summaries|outline|worldbook|ledgers`）、`limit`（1–50，默认 20）。

返回 `{query, scope, total, truncated, results[]}`；每条结果带 `kind`、`chapter?`、`title?`、`paragraph?`、`snippet`。

### 4.8 `novel_doctor`

返回 `{ok, root, checks[], summary:{errors,warnings,infos}}`。检查项：

1. `novel.yaml` 可读；2. pipeline 可读；3. 八个台账可读；4. 大纲存在且可读；5. 世界观存在且可读；6. journal 无 malformed、无外部改动；7. 锁文件状态；8. 索引正文存在且 hash 匹配；9. 目录内孤立正文；10. 大纲覆盖率与归档漂移；11. 当前阶段产物齐全；12. 备份数量；13. 目标章数进度；14. 下一步建议。

没有项目时返回一条 `PROJECT_NOT_FOUND` 错误检查，不抛异常。

### 4.9 `novel_report`

返回：

```
progress   { archived, target, words, average_words, percent, remaining_words }
outline    { present, strict, planned, archived, coverage, volumes[], drift[] }
worldbook  { present, characters, locations, factions, rules, glossary, backstory }
quality    { average, median, min, max, last_five[], trend, dimensions[] }
pacing     { scene_types, hook_strength, plot_advancement, longest, shortest }
cast       { total, top[] }
foreshadows{ open, dormant, overdue, resolved, oldest[] }
timeline   { events, first_chapter, last_chapter }
relationships { total, types }
activity   []
warnings   []
```

### 4.10 `novel_guide`

返回 `{state, title, steps[], next, commands[], tips[]}`。状态：`no-project | new | planning | writing | blocked | finished`。每一步带 `done` 与可选 `tool`。不写盘。

### 4.11 `getStatus` / `stats` / `export` 扩展

- `StatusReport.book`：`{premise, logline, strict, outline:{total,planned,archived,coverage,volumes,current}, worldbook:{...counts}}`。
- `stats` 增加 `plannedChapters`、`outlineCoverage`、`blueprintReady`、`worldbookEntries`、`strictOutline`、`targetChapters`。
- `ExportKind` 增加 `outline | worldbook | proposal`；分别导出 Markdown 大纲、世界观、书级提案。

## 5. 门控与质量

### 5.1 新增 PG-13 `OUTLINE_ALIGNMENT`

适用：`submitChapterPlan`、`submitDraft`、`archiveChapter`。

判定（仅在 `outline` 存在时）：

1. 严格模式且当前章无章卡；
2. 章卡已归档却仍是活动章；
3. 章卡标题与计划/草稿标题正文不一致；
4. 场景类型不一致；
5. 计划字数区间与章卡区间不相交；
6. 章卡 `cast` 非空而计划 cast 未覆盖。

以上六种原因统一返回门控码 `PG-13`，具体原因写在 `blocking[].detail`（不是六个独立错误码）。

修复动作固定：`novel_outline` 改章卡，或 `novel_plan_chapter` 改计划；归档后需先 `novel_reopen`。

### 5.2 P6 语义项增加 POV

`SEMANTIC_CHECK_IDS` 从 4 项改为 5 项：`L2-SCENE-ANCHOR`、`L2-CHARACTER-STATE`、`L2-CAUSALITY`、`L2-VOICE`、`L2-POV`。POV 项要求一条独立原文证据，且不能与其他四项共用句子。

### 5.3 归档与大纲的一致性

- 归档事务把章卡写成 `archived`，并写 `archived_at / word_count / score`。
- 严格模式下若归档时章卡不存在，PG-13 已在 P2/P3 拒绝；非严格模式归档时自动补一张归档卡，保证大纲是完整进度视图。
- 归档后大纲与索引的标题/场景类型不一致由 `novel_report.outline.drift` 与 `novel_doctor` 报告，不再反向修改正文。

### 5.4 既有缺陷修复（0.2.0 内完成）

- `queryState` 读取非活动章的世界计划时补 `validateWorldPlanShape`，避免损坏数组进入调用方。
- `getStatus`/`panel` 在 `novel.yaml` 存在但 outline/worldbook 损坏时显示 `state_errors` 与修复动作，不静默当作空文档。
- `submitChapterPlan` 的标题/场景/字数进入 PG-13 校验，避免“计划通过、草稿被拒”的断裂。
- `novel_export` 的幂等键加入 outline/worldbook 内容摘要，导出结果随规划变化。
- 面板空状态、错误状态与 15 秒轮询在 0.2.0 新数据下保持可用；旧 DTO 版本触发“刷新页面”。
- `novel_amend` 的允许列表加入 `outline/outline.yaml` 与 `outline/worldbook.yaml`；损坏文档可修，且不会绕过归档卡保护。

## 6. 可见性与可观测性

### 6.1 状态卡

`novel_status` 文本增加：书级蓝图是否就绪、大纲覆盖率、严格模式、当前章卡标题/目标字数/场景类型、世界观条目数、下一步。

### 6.2 面板 2.0

侧边栏保持只读，新增区块：

1. **全书规划**：蓝图/大纲/严格模式徽章；已规划/已归档/目标章数进度条；卷列表（计划/归档计数）。
2. **世界观**：角色/地点/势力/规则/术语/前史计数。
3. **质量趋势**：最近 10 章评分条形图与平均分。
4. **项目健康**：阻塞项、state_errors、下一步。
5. **最近活动**：最近 5 条 journal 操作（章节、状态、时间）。

保留：Hero、统计、九阶段轨、下一步、章节卡、门控。面板 payload 版本升到 2；旧版本显示“刷新页面”。

### 6.3 事件

新增：`novel/planned`（blueprint/outline/worldbook）、`novel/reopened`、`novel/exported`。既有 `novel/archived`、`novel/blocked`、`novel/amended` 不变。

### 6.4 命令

`/novel` 子命令增加：`outline`、`guide`、`report`、`doctor`、`search <query>`；`export` 支持六种 kind。`/novel-export` 同步。

## 7. 易用性

- `novel_guide` 是所有新用户的第一入口；`novel_status.next` 在严格模式缺章卡时直接指向 `novel_outline`。
- `novel_init` 不强制规划；但 `novel_guide` 把“蓝图 → 大纲 → 世界观”作为推荐路径，并显示完成状态。

## 12. 风险与处置

| 风险 | 处置 |
| --- | --- |
| 大纲成为第二真相 | 大纲只做规划输入与进度视图；正文/台账仍是 SSOT；归档只回写章卡状态，不反向改正文 |
| 严格模式挡住老用户 | `strict` 默认关闭；`novel_outline` 首次提交才开启；`novel_blueprint {strict:false}` 可关闭 |
| 归档卡被模型改坏 | `novel_outline` 拒绝改动已归档卡；`novel_amend` 也校验 |
| reopen 恢复错版本 | 只认 journal 中该章最后一次 `archiveChapter` 的 committed txid；备份缺失即拒绝 |
| 面板变慢 | 面板只读最近 30 章 + 最近 5 条活动；报告才是全量 |
| 上下文膨胀 | 世界观按当前章提及裁剪并设上限；蓝图/章卡受保护但字段有硬上限 |
| 解析器过度宽松 | 未知行警告、关键字段缺失报错、行号定位；dry-run 先预览 |
