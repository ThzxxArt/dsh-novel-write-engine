# P5 · 修订

只改评审指出的问题，不重写整章。第 {{round}} 轮。

## 规则

1. 每条 `blocker` issue 必须变成 `fixed`，并给 `evidence`——修订后正文里的**逐字引用**，引擎会回查。
2. `issues` 里只能改 `status` 与 `evidence`；`dimension`、`location`、`problem`、`fix`、`severity` 是评审归属，改写会被拒绝。新发现留到下一轮 P4。
3. `blocker` 不许 `waived`；只有 advisory 可以带理由豁免。
4. 改完字数仍要 ≥ {{min_words}}，格式要求同 P3。
5. 改动会抬高或压低评分时，不要自己改分；下一轮 P4 重新评。

## 提交

调用 `novel_revise`，二选一：

**推荐：patch 模式**（只传改动，省 token）：

```json
{
  "chapter": 3,
  "patch": {
    "expected_hash": "任务书 fields.manuscript_hash 的值",
    "edits": [{ "old_text": "原文里的唯一片段", "new_text": "替换后的片段" }]
  },
  "proof": { "opening": {}, "middle": {}, "ending": {} }
}
```

- `expected_hash` 必须是当前正文的 SHA-256；`fields.manuscript_hash` 就是它。
- `old_text` 默认必须在当前正文中唯一；重复出现时用 `occurrence` 指定第几次。
- 多处编辑不能重叠；hash 不匹配、锚点不唯一都会零写入拒绝。

**整章模式**：

- `content`：修订后的完整正文（不是 diff）。
- `summary`：如果事件、伏笔、资源有变化，同步更新；没变化可省略。**如果改动前两段/opening，必须同时提交新的 summary**，否则引擎会拒绝。
- `proof`：修订后正文的三个逐字引用（opening/middle/ending），每段至少 12 字；PG-09 会逐条回查，开头/结尾按实际段落判定，不能改写、编造或靠提交段落号挪动边界。

`ready_to_archive` 阶段也允许直接 `novel_revise`：正文会退回 P4 重新评审，不需要先 `novel_rollback`，也不会多写一份废稿快照。

## 常见返工原因

- 只改了措辞，没解决 issue 指出的信息缺口。
- `evidence` 抄的是旧句子。
- 改完段落超 90 字。

提交后回到 P4 重新评审；轮次由引擎自增，你不需要也不允许传轮次。
