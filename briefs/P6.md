# P6 · 一致性校验

引擎跑机检，你补语义项。**不要重写正文**。

## 语义项（你提供）

`novel_check` 的 `semantic` 必须是数组，五项各一次：`{ "id": "L2-VOICE", "verdict": "pass|fail", "evidence": "正文逐字引用", "note": "理由" }`。

| id                   | 检查                                         |
| -------------------- | -------------------------------------------- |
| `L2-SCENE-ANCHOR`    | 本章场景与 P1 计划的地点一致                 |
| `L2-CHARACTER-STATE` | 人物状态与 `characters` 台账一致             |
| `L2-CAUSALITY`       | 关键转折有前置因果，不是突然降神             |
| `L2-VOICE`           | 对话能区分说话人                             |
| `L2-POV`             | 叙述视角与 `narrator`/计划一致，没有中途越界 |

- `evidence` ≥ 8 字、逐字出现在正文（可跨句跨段），五条互不相同、不得复用同一句。
- 同一句不同子串、完全重复、或达到 `max(8, 较短引文一半)` 的区间重叠会被按 `same_sentence`/`duplicate`/`interval_overlap` 拒绝并回传配对 `conflicts`；不同段落只共享常用词不算重叠。
- 引文不存在/太短/形状不合法是 **submission error**（`ENGINE_CHECK_SUBMISSION_INVALID`）：不写 check、不消耗轮次，改好 `semantic` 再调一次。
- 每项必须带 `evidence`；找不到引用＝该项不成立。

## 机检（引擎自动）

格式与字数、跨章对账（重复段落、伏笔休眠/逾期、资源余额、时间倒退、锁定描写漂移）、质量提示（对话比例双口径、数字矛盾、strict 模式 facts 为空）。段落口径与 P4 相同：一段 = 一段非空文本，章标题不计段，引文先归一化再逐字匹配。

`advisory` 不阻塞归档；同一 code 的多个实例聚合显示，但 `acknowledge:[id]` 只消掉那一条，且必须同时传 `acknowledge_reasons[token]`（token 为实例 `id` 或 code）。`blocker` 不会被 acknowledge 放行；`acknowledge_until_chapter` 让长期确认在指定章后自动恢复。

## 自查清单复核（必答 8 项）

13 条投稿标准里机器判其中 5 项，剩下的 8 项由你判：`SC-METAPHOR` `SC-CONCRETE` `SC-FORMULA` `SC-PARALLEL` `SC-LIST` `SC-DIALOGUE-BEAT` `SC-DASH` `SC-QUOTE`（13 行全表见 `docs/selfcheck.md`）。P6 的 `context` 不再附带 `self_check` 块——0.2.20 起它只发 P3/P4——所以按上表回答，不要去找 `self_check.checklist`。**这 8 项不回答，PG-12 会拒绝归档**——0.2.19 会把它当成 pass，那等于没人判也放行。

每项写 `{ "id": "SC-CONCRETE", "verdict": "pass|fail", "note": "理由", "evidence": "正文原句" }`。

- 机器已判 fail 的项不得填 `pass`，引擎会带行号与规则码打回。
- 正文改过时机器半边会重判，你只需确认 8 项没因修订失效。
- 某项本章确实无法判定：用 `self_check_waivers` 豁免并写理由；机器项不可豁免。
- 不答也不豁免 → check 记 `na`（`summary.unanswered`），归档被拒。

## 判定与下一步

- `scope` 默认 `["content","integrity"]`；只跑一类合法，但管线停在 P6 并返回 `CHECK_SCOPE_PARTIAL`，必须再跑一次完整 scope。
- 完整 scope 全过 → 管线进 `ready_to_archive`：先 `novel_brief P8` 领终审任务书，再 `novel_archive`。
- 任一项 `fail` 且引文有效 → content failure，写 check 并消耗一轮：重新领 `novel_brief P6`（check 变了，旧 digest 失效），再 `novel_revise` 修订并回 P4 重评。
- 只是 summary 与正文不符 → `novel_revise {chapter, summary}` 做 summary-only 修复：不消耗 revise、不改正文。

## 损坏与恢复

`novel_status` 报 `state_errors` 或 `STATE_UNREADABLE` 时不要手改文件：plan/review/check 按 `next` 调 `novel_rollback`；八个台账按 `next` 调 `novel_amend`，先用 `novel_state` 取 raw 文档再提交完整替换。`novel_archive` 报 review 缺 `review_digest` 时回 P4 重走 `novel_review`，不要编辑 `state/pipeline.yaml`。

## 不许做的

不要为了让校验过而删掉有信息量的段落；不要把语义项全填 `pass` 而不给证据。
