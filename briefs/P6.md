# P6 · 一致性校验

本阶段由引擎跑机检、你补语义项。**不要重写正文**。

## 机检（引擎自动）

- 格式与字数：引号、分号、省略号、长段、标题。
- 跨章对账：重复段落、伏笔休眠、资源余额、时间倒退、关系未声明、锁定描写漂移。
- 质量提示：对话比例、数字/单位矛盾、数字事实不一致。`advisory` 不阻塞归档，可用 `acknowledge` 记录知悉；`blocker` 不会被 acknowledge 放行。

## 语义项（你提供）

调用 `novel_check` 传 `semantic`，形状必须是：

```json
[
  { "id": "L2-SCENE-ANCHOR", "verdict": "pass", "evidence": "正文中的逐字引用", "note": "场景与计划一致" },
  { "id": "L2-CHARACTER-STATE", "verdict": "pass", "evidence": "正文中的逐字引用", "note": "心理状态与台账一致" },
  { "id": "L2-CAUSALITY", "verdict": "pass", "evidence": "正文中的逐字引用", "note": "转折有前置因果" },
  { "id": "L2-VOICE", "verdict": "pass", "evidence": "正文中的逐字引用", "note": "对话可区分" },
  { "id": "L2-POV", "verdict": "pass", "evidence": "正文中的逐字引用", "note": "叙述视角与计划一致" }
]
```

五个 id 必须各出现一次；`verdict` 只能是 `pass`/`fail`；`evidence` 至少 8 字、必须逐字出现在正文里，可以跨句/跨段。五条引用必须互不相同、不得复用同一句，也不得与已接受引文的区间重叠；同一句不同子串、重复引用或区间重叠会被按 `same_sentence`/`overlap` 拒绝。引文不存在/太短/形状不合法属于 **submission error**（`ENGINE_CHECK_SUBMISSION_INVALID`）：不写 check、不消耗轮次，修正 `semantic` 后仍调用 `novel_check`。

| id | 检查 |
|---|---|
| `L2-SCENE-ANCHOR` | 本章场景与 P1 计划的地点一致 |
| `L2-CHARACTER-STATE` | 人物状态与 `characters` 台账一致 |
| `L2-CAUSALITY` | 关键转折有前置因果，不是突然降神 |
| `L2-VOICE` | 对话能区分说话人 |
| `L2-POV` | 叙述视角与 `narrator`/计划一致，没有中途越界 |

每项必须带 `evidence`：正文中的逐字引用。找不到引用＝该项不成立。

## 判定

- 调用时可以传 `scope`：默认 `["content","integrity"]`；只跑 `content` 或只跑 `integrity` 是合法的，空数组/未知值会被拒绝。只跑一类时另一类规则不参与本次 check，但**不会**进入 `ready_to_archive`：管线停在 P6 并返回 `CHECK_SCOPE_PARTIAL`，必须再跑一次完整 scope。
- 完整 scope 全过 → 管线进入 `ready_to_archive`，先 `novel_brief P8` 领取终审任务书，再调用 `novel_archive`。
- 任一项 `fail` 且引文有效 → content failure，写 check 并消耗一轮；先重新领取 `novel_brief P6`（check 已改变上下文，旧 digest 会失效），再调用 `novel_revise` 修订并回到 P4 重评。
- 如果只是 summary 字段与正文不符（正文无需改），用 `novel_revise {chapter, summary}` 做 summary-only 修复：不消耗 revise、不改正文，然后可直接继续 check/archive。

## 损坏与恢复

- 如果 `novel_status` 返回 `state_errors` 或 `STATE_UNREADABLE`，不要手改文件；plan/review/check 按 `next` 指向的 `novel_rollback` 回到重建点；八个 ledger 则按 `next` 调 `novel_amend`，先用 `novel_state` 取 raw 文档再提交完整替换。
- 如果 `novel_archive` 报 review 没有 `review_digest`，回退到 P4 重新 `novel_review`；不要编辑 `state/pipeline.yaml`。

## 不许做的

- 不许为了让校验过而删掉有信息量的段落。
- 不许把语义项全部填 `pass` 而不给证据。
