# P6 · 一致性校验

本阶段由引擎跑机检、你补语义项。**不要重写正文**。

## 机检（引擎自动）

- 格式与字数：引号、分号、省略号、长段、标题。
- 跨章对账：重复段落、伏笔休眠、资源余额、时间倒退、关系未声明、锁定描写漂移。

## 语义项（你提供）

调用 `novel_check` 传 `semantic`，形状必须是：

```json
[
  { "id": "L2-SCENE-ANCHOR", "verdict": "pass", "evidence": "正文中的逐字引用", "note": "场景与计划一致" },
  { "id": "L2-CHARACTER-STATE", "verdict": "pass", "evidence": "正文中的逐字引用", "note": "心理状态与台账一致" },
  { "id": "L2-CAUSALITY", "verdict": "pass", "evidence": "正文中的逐字引用", "note": "转折有前置因果" },
  { "id": "L2-VOICE", "verdict": "pass", "evidence": "正文中的逐字引用", "note": "对话可区分" }
]
```

四个 id 必须各出现一次；`verdict` 只能是 `pass`/`fail`；`evidence` 至少 4 字且必须逐字出现在正文里。

| id | 检查 |
|---|---|
| `L2-SCENE-ANCHOR` | 本章场景与 P1 计划的地点一致 |
| `L2-CHARACTER-STATE` | 人物状态与 `characters` 台账一致 |
| `L2-CAUSALITY` | 关键转折有前置因果，不是突然降神 |
| `L2-VOICE` | 对话能区分说话人 |

每项必须带 `evidence`：正文中的逐字引用。找不到引用＝该项不成立。

## 判定

- 任一项 `fail` → 校验不过，调用 `novel_revise` 修订并回到 P4 重评（轮次 +1）。
- 全过 → 管线进入 `ready_to_archive`，先 `novel_brief P8` 领取终审任务书，再调用 `novel_archive`。

## 不许做的

- 不许为了让校验过而删掉有信息量的段落。
- 不许把语义项全部填 `pass` 而不给证据。
