# P3 · 初稿

本阶段只做一件事：把 P2 的节拍写成正文。

## 硬指标

- 字数 ≥ {{min_words}}（引擎口径：汉字 + 英文单词 + 数字 + 标点）。
- 单段 ≤ 90 字；段与段之间空一行。
- 对话只用英文直引号 `"`；**中文弯引号 `“ ”`、直角引号 `「 」` 都是 ILLEGAL_QUOTE blocker**；禁全角分号 `；`、禁 `...`。
- 不写 Markdown：禁 `#`、`**`、`---`、`>`、表格。
- 不写「Day 1」「第X卷」「读者」「作者」这类出戏标签。

## 写法

1. 一段一个信息点。先动作，后反应，最后才允许一句心理。
2. 对话要有区分度：不同角色说话的句长、口头禅、攻击性不同。
3. 每 600 字左右至少一个爽点或新信息，不许连续铺垫。
4. 结尾断在动作中间或新信息刚落地时。

## 提交

调用 `novel_write_draft`，除正文外必须给全 `summary` 十个字段。**形状必须完全如下**：

```json
{
  "events": ["本章发生的事件，至少一条"],
  "characters_appeared": ["本章出现的人物名"],
  "foreshadows": {
    "planted": [{ "key": "letter", "title": "旧信封", "description": "无名信" }],
    "advanced": [{ "key": "FS-001", "note": "日期被改", "new_info": true }],
    "resolved": ["FS-002"]
  },
  "new_elements": { "locations": ["旧办公室"], "abilities": [], "artifacts": [] },
  "resource_changes": [
    { "character": "他", "resource": "铜钱", "delta": -200, "reason": "买信封" }
  ],
  "opening": "正文前两段里的逐字引用，至少 12 字",
  "continuity": { "opens_from": "上一章结尾", "ends_with": "本章结尾的钩子" },
  "hook_strength": 4,
  "pleasure_points": ["本章的爽点"],
  "plot_advancement": "high"
}
```

- `foreshadows.planted` **不是字符串数组**，每项是 `{key,title,description}`。
- `new_elements` 是**对象**，不是数组；三个键都必须是字符串数组（没有就 `[]`）。
- `resource_changes` 每项是 `{character,resource,delta,reason}`，`delta` 是非零整数；没有变化就 `[]`。
- `opening` 必须逐字出现在正文前两段，不能写剧情概括。
- `continuity` 是 `{opens_from,ends_with}` 对象。
- `hook_strength` 是 1–5 的整数，`plot_advancement` 是 `high|mid|low`。

## 提交前自检

先调 `novel_word_count` 看字数，再提交。门控失败会返回**全部**阻塞项，一次改完再交。

完成后管线进入 P4，下一步调 `novel_brief` 取 P4 任务书。
