# P3 · 初稿

本阶段只做一件事：把 P2 的节拍写成正文。

## 硬指标

- 总字数 ≥ {{min_words}}（引擎口径：汉字 + 英文单词 + 数字 + 标点）。
- 汉字下限：{{min_cjk_chars}}（0 表示本项目未设；总字数与汉字下限是两道独立的长度检查）。
- 单段不超过 `{{paragraph_max}}` 个汉字（标点不计；规则包 `format.paragraph_max_words` 为准）；段与段之间空一行。
- 引号：{{quotes_rule}}。半角引号还要成对。禁止全角分号 `；`、禁止 `...`。
- 提交时 `content` 是 JSON 字符串：段落换行写 `\n`，正文里的每个英文直引号写 `\"`；不要把整段内容再包一层 JSON。
- 不写 Markdown：禁 `#`、`**`、`---`、`>`、表格。
- 不写「Day 1」「第X卷」「读者」「作者」这类出戏标签。

## 上下文

P3 brief 的 `context.world_plan` 是 P1 的本章约束；`context.characters` 是本章活跃角色的完整档案，`context.other_characters` 只是压缩索引；`context.outline_card` 是本章章卡，`context.worldbook` 是相关世界观条目。先读 `world_plan`、`characters` 与 `outline_card` 再落笔；不要在正文里临时发明未申报的世界规则或人物。

## 写法

1. 一段一个信息点。先动作，后反应，最后才允许一句心理。
2. 对话要有区分度：不同角色说话的句长、口头禅、攻击性不同。
3. 每 600 字左右至少一个爽点或新信息，不许连续铺垫。
4. 结尾断在动作中间或新信息刚落地时。

## 提交

调用 `novel_write_draft`，参数至少包含 `chapter`、`chapter_title`、`content`、`scene_type`、`narrator` 与完整 `summary` 十个字段。**形状必须完全如下**：

```json
{
  "events": ["本章发生的事件，至少一条"],
  "characters_appeared": ["本章出现的人物名"],
  "foreshadows": {
    "planted": [
      {
        "key": "letter",
        "title": "旧信封",
        "description": "无名信",
        "anchor": "桌上那只旧信封压着邮票",
        "planned_resolve": 6,
        "kind": "plot"
      }
    ],
    "advanced": [{ "key": "FS-001", "note": "日期被改", "new_info": true }],
    "resolved": ["FS-002"]
  },
  "new_elements": { "locations": ["旧办公室"], "abilities": [], "artifacts": [] },
  "new_element_anchors": { "locations": { "旧办公室": ["三楼尾房的门半开着"] } },
  "resource_changes": [{ "character": "他", "resource": "铜钱", "delta": -200, "reason": "买信封" }],
  "opening": "正文前两段里的逐字引用，至少 12 字",
  "continuity": { "opens_from": "上一章结尾", "ends_with": "本章结尾的钩子" },
  "hook_strength": 4,
  "pleasure_points": ["本章的爽点"],
  "plot_advancement": "high"
}
```

- `foreshadows.planted` **不是字符串数组**，每项是 `{key,title,description}`；新标题 2–16 字，`anchor` 必须是正文逐字原句（至少 8 字）。`planned_resolve` 是计划回收章，`kind` 是 `plot|motif`，两者可选。
- 把伏笔标为 `resolved` 时，P8 delta 必须同时给 `resolved_anchor`（正文逐字原句，至少 8 字）；`note` 不能替代证据。
- `new_elements` 是**对象**，不是数组；三个键都必须是字符串数组（没有就 `[]`）。
- `new_element_anchors` 可选：只用于新地点/能力/物品；键必须同时出现在对应 `new_elements` 数组；每个实体 1–8 个正文锚点，每个 8–120 字（短名请用正文里的完整短语，不要只写两三个字）。有锚点时任一锚点逐字命中即可，不再要求正文出现可读登记名。
- `resource_changes` 每项是 `{character,resource,delta,reason}`，`delta` 是非零整数；没有变化就 `[]`。
- `opening` 必须逐字出现在正文前两段，不能写剧情概括。
- `continuity` 是 `{opens_from,ends_with}` 对象。
- `hook_strength` 是 1–5 的整数，`plot_advancement` 是 `high|mid|low`。

## 投稿自查清单（13 项硬约束）

`context.self_check.checklist` 是本轮必须守住的 13 条投稿标准。它们**不是风格建议**，是退稿理由的高频排行榜；`basis` 说明谁判：

| basis | 含义 |
| --- | --- |
| `machine` | 引擎直接判，不接受解释。S7 破折号、S9 标点、S10 段落、S11 分行、S13 转场 |
| `hybrid` | 引擎给证据、P4 下结论。S1 比喻、S3 固定句式、S4 排比、S5 清单、S6 短对话、S8 对话标点、S12 分章 |
| `model` | 只有 P4 能判。S2 画面感 |

写正文时按这 13 条自检，重点是引擎能直接判死的五条：

- 破折号 `——` 有预算，别拿它当逗号用；
- 标点全角、中文字之间不留空格、不用 `~ ★ →` 之类装饰符；
- 一段别超过 `{{paragraph_max}}` 个汉字（标点不计），也别连续三段都只有三五个字（对白行除外）；
- 一句话放在一段里，别在逗号处回车；
- 转场不写分割线，`……` 也不要单独成段。

## 提交前自检

先调 `novel_word_count` 看字数，再提交。门控失败会返回**全部**阻塞项，一次改完再交。

完成后管线进入 P4，下一步调 `novel_brief` 取 P4 任务书。
