# P2 · 章节预检

本章计划决定「怎么写」，不是「写什么」。写的是可执行的节拍表，不是剧情梗概。

## 输入

- P1 的世界观计划：`novel_state {"kind":"planWorld","chapter":{{chapter}}}`（对应 `plans/ch{{chapter_pad}}.world.yaml`）。
- 上一章结尾（`state/handoff.yaml` 的 `last_summary`）。
- 未回收伏笔：`novel_state foreshadows`。
- 当前章卡：`novel_state {"kind":"outline"}`（`context.outline_card` 已带入 brief）。只要存在章卡，标题、场景类型、目标字数区间与 cast 就必须一致，否则 PG-13 会拒绝；严格模式还要求章卡必须存在。
- 更新章卡时用 `novel_outline` 的 upsert：只提交要改的 `num`，省略的章卡不会被删除；删除必须显式 `remove`。不要靠重交全量卡来“确保存在”。
- 世界观相关条目：`context.worldbook`。

## 产出

调用 `novel_plan_chapter`：

| 字段 | 要求 |
|---|---|
| `title` | 不带「第N章」前缀；长度读 rulepack 的 `format.title.min_chars/max_chars`，引擎会拼前缀并校验 |
| `scene_type` | 四选一：战斗/动作章、日常过渡章、情感爆发章、纯叙事章 |
| `narrator` | 视角人物，必须在本章出场；第一人称写成 `主角（第一人称「我」）`，引擎接受括号/引号里的正文别名 |
| `beats` | 5~8 个节拍，每个是一句话的可检验动作 |
| `opening` | 前两段打算怎么写（场景 + 动作 + 一个钩子） |
| `ending` | 断章点，必须是新信息或新麻烦 |
| `target_words` | `[{{min_words}}, {{max_words}}]` |
| `cast` | 可选，1–8 个本章真正上场的人物：`{name,entry_state?,goal?,knowledge?,exit_change?}`；name 必须来自 P1 世界计划或角色台账 |

`cast` 不是出场名单的重复：它告诉 P3 这一章谁在舞台上、各自带着什么目标与信息差。没有 cast 时，引擎会从计划正文与人物台账推断；新计划建议显式给出，避免 120 个角色里裁掉真正上场的人。

章卡有 cast 时，P2 的 cast 必须覆盖章卡里的每一个名字；章卡没有 cast 时不强制。

## 场景类型纪律

- 不许连续三章同型；战斗章不许连排两章。
- 情感爆发章必须有一个明确的情绪转折点，不许整章都在铺垫。

## 断章

结尾落在一个**未解决的问题**上。不要总结、不要升华、不要预告下一章。

完成后管线进入 P3，下一步调 `novel_brief` 取 P3 任务书。
