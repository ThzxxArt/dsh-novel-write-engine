# P8 · 终审

归档前最后一遍。引擎执行事务，你只确认两件事。

1. **正文没变**：`novel_check` 之后没再改正文；改了必须重新校验。
2. **摘要属实**：`summary` 里的伏笔、资源变化能在正文找到依据。
3. **delta 齐了**：本章出现过的每个角色、新地点/能力/物品、伏笔、事件、关系，都在 `state_delta` 里逐条声明 `created` / `updated` / `no_change`；`no_change` 必须写 `reason`。

## 调用

`novel_archive` 必须同时传 `chapter` 与 `state_delta`：

```json
{
  "chapter": 3,
  "state_delta": {
    "characters": { "主角": { "action": "no_change", "reason": "本章没有状态变化" } },
    "foreshadows": { "FS-007": { "action": "updated", "note": "日期被改动", "new_info": true } },
    "timeline": { "0": { "action": "created", "story_time": "Day 3 清晨", "description": "收到信" } },
    "world": {},
    "relationships": {}
  }
}
```

五个 section 都要有，值形状与字段名按 `fields.delta_rules.minimal_schema` 填（那是唯一权威，含 `type_code` 枚举）。`state_delta` 必须是 JSON 对象，不要再包成 JSON 字符串。

## 键与校验

- `characters` 用人物名；`world` 用新地点/能力/物品名；`foreshadows` 用 summary 里的 planted key 或已分配的 `FS-xxx`。
- `timeline` 的键是 `summary.events` 下标（字符串）或 `fields.timeline_event_keys` 的稳定 `event_key`；两种键指向同一事件，新写入落 `event_key`。
- `relationships` 的键是 `"甲|乙"`；两端必须已在 `characters` 声明（本章 `created` 或台账已有），缺 `type`/`type_code` 会被拒。
- **伏笔的 `title` 是可读标签，`anchor` 才是校验证据**：`anchor` 放正文逐字原句（≥8 字）；没有 `anchor` 时 `title` 必须逐字出现在正文，否则 `ENGINE_DELTA_UNVERIFIED`。`summary.foreshadows.resolved` 里的 key 必须写 `action:"updated"` 且带 `resolved_anchor`，引擎会写 `resolved_at` 并把 `note`/`new_info`/`anchor` 追加进 `advance_log`。
- `world` 以 `state/world.yaml` 的存在性为唯一真源：已有实体写 `created` 会归一化为 `updated` 并给 warning；新实体写 `updated` 且正文出现、kind 可确定时归一化为 `created`；kind 冲突仍拒绝。`summary.new_elements` 只是意图声明，新实体可用 `new_element_anchors` 提供正文锚点（1–8 个，每个 8–120 字）。
- 未知伏笔 key、未声明角色、`no_change` 缺原因、`timeline.<key>.characters` 里的名字不在台账，都会被 `ENGINE_DELTA_UNVERIFIED` 拒绝；引擎不会猜。
- `current_state.resources` 是**绝对值（set）**，`resource_changes[].delta` 是**增量（add）**；同一章同一角色同一资源只能走一条通道，否则 `ENGINE_RESOURCE_DOUBLE_COUNT`。余额默认必须非负，欠债需要项目开 `allow_negative_balances`。
- 第一人称叙述者若在 `narrator` 里声明为 `主角（第一人称「我」）`，正文用「我」也算出现，但角色键仍写 `主角`。
- 错误回执带 `details`（`field/expected/received/received_type/allowed/example`）；按报错补齐，不要猜字段名。不要传正文、评分或轮次；`handoff` 可选，用于覆盖卷/幕/进度。

## summary 与 delta 不符时

`novel_archive` 不接受 summary，它校验的是 P3/P5 已固定的 draft summary。若 summary 与本章事实不符，先做 **summary-only** 修复：`novel_revise {chapter, summary}`（不带 content/patch/proof）只更新 draft.summary，不消耗 revise 轮次、不改正文，然后继续当前阶段；只有正文要改才走 P5 全文修订。

## 归档后

管线进 `done`，章节号 +1，轮次清零。还有下一章就从 `novel_brief P1` 重新开始。
