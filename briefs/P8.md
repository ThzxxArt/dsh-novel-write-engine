# P8 · 终审

归档前最后一遍。本阶段由引擎执行事务，你只确认两件事。

## 确认清单

1. **正文没变**：`novel_check` 之后没有再改正文。改了就必须重新校验。
2. **摘要属实**：`summary` 里的伏笔、资源变化能在正文中找到依据。
3. **delta 齐了**：本章出现过的每个角色、新地点/能力/物品、伏笔、事件、关系，都在 `state_delta` 里逐条声明 `created` / `updated` / `no_change`；`no_change` 必须写 `reason`。

## 调用

`novel_archive` 必须同时传 `chapter` 与 `state_delta`：

```json
{
  "chapter": 3,
  "state_delta": {
    "characters": { "主角": { "action": "no_change", "reason": "本章没有状态变化" } },
    "foreshadows": { "FS-007": { "action": "updated", "note": "日期被改动", "new_info": true } },
    "timeline": { "0": { "action": "created", "story_time": "Day 3 清晨", "description": "收到信" } },
    "world": {},
    "relationships": {}
  }
}
```

- `timeline` 的键是 `summary.events` 的下标（字符串）。
- `relationships` 的键是 `"甲|乙"`；每项至少 `{ "action": "created", "type": "关系类型", "description": "..." }`，缺 `type` 会被拒绝。
- `characters` 的键是人物名；`world` 的键是新地点/能力/物品名；`foreshadows` 的键是 summary 里的 planted key 或已分配的 `FS-xxx`。
- `foreshadows` 的 `summary.foreshadows.resolved` 里列出的 key，delta 必须写 `action: "updated"`；引擎会把 `resolved_at` 写成当前章，并把 `note`/`new_info` 追加到 `advance_log`。示例：`"FS-002": {"action":"updated","note":"欠条被收回，债清了","new_info":true}`。

## 最小 schema

```json
{
  "characters": {
    "<人物名>": {
      "action": "created|updated|no_change",
      "reason": "no_change 必填；其余建议写",
      "role": "protagonist|supporting|antagonist|extra（可选）",
      "profile": {},
      "current_state": { "resources": { "<资源名>": 0 } },
      "growth": { "change": "string", "status_change": "string" }
    }
  },
  "foreshadows": {
    "<planted key 或 FS-xxx>": {
      "action": "created|updated|no_change",
      "title": "可读标签",
      "anchor": "正文逐字原句，至少 8 字",
      "description": "string",
      "note": "resolve/advance 时写清如何兑现",
      "new_info": true
    }
  },
  "timeline": {
    "<summary.events 下标>": {
      "action": "created",
      "story_time": "Day 3 清晨",
      "description": "string",
      "location": "string",
      "characters": ["人物名"]
    }
  },
  "world": {
    "<新地点/能力/物品名>": {
      "action": "created|updated|no_change",
      "kind": "location|ability|artifact|faction|rule",
      "description": "string"
    }
  },
  "relationships": {
    "<甲|乙>": {
      "action": "created|updated|no_change",
      "type": "关系类型（created 必填）",
      "description": "string",
      "note": "updated 时写变化"
    }
  }
}
```

错误会带上 `expected` 形态和收到的字段值，例如 `characters.陈嘉树.current_state must be an object; expected {"resources":{"港币":-3},...}`。不要猜字段名，按报错补齐即可。

## summary 与 delta 的联动（归档前必核）

`novel_archive` **不接受 summary**；它校验的是 P3/P5 已经固定的 draft summary。delta 必须与这份 summary 对齐：

- `characters` 里每个 `action:"created"` 的人物名，必须出现在 draft `summary.characters_appeared`。
- `world` 里每个 `action:"created"` 的 location / ability / artifact，必须出现在 draft `summary.new_elements` 的对应数组，且 `kind` 一致；`faction` / `rule` 只需正文出现并按 kind 写入，`summary.new_elements` 没有对应数组。
- `timeline` 的键必须是 draft `summary.events` 的下标（字符串）。
- `relationships` 的两端必须已在 `characters` 里声明（本章 created 或台账已有），否则先声明人物。

如果 summary 与本章事实不符，**不要直接改 delta 硬凑**：先 `novel_brief P5` → `novel_revise` 修正正文和 summary，再重走 P4/P6/P8。归档阶段没有第二次 summary 入口。

- **伏笔的 title 是可读标签，anchor 才是校验证据**：`title` 可以写「船费债」这样的短语；要归档，请把正文原句放进 `anchor`（summary 的 planted 项或 delta 项都行，至少 8 个字符）。没有 `anchor` 时，`title` 必须逐字出现在正文里，否则 `ENGINE_DELTA_UNVERIFIED`。示例：`{"action":"created","title":"船费债","anchor":"三百蚊的船费先欠着","description":"欠船费三百蚊"}`。
- 归档失败的报错会指出字段、值和缺失的锚点；不要把 title 改成碎片来“凑命中”，补 `anchor` 即可。
- 第一人称的叙述者若在 `narrator` 里声明为 `陈默（第一人称「我」）`，正文用「我」也视为出现，但角色键仍写 `陈默`。
- 每个新实体至少写 `action: "created"`；已存在且没变化写 `action: "no_change", reason: "..."`。
- `world` 新实体还要写 `kind: "location"|"ability"|"artifact"|"faction"|"rule"` 和 `description`。
- `state_delta` 可以是对象，也可以是 JSON 字符串；引擎两者都接受。
- 未知伏笔 key、未声明角色、`no_change` 缺原因都会被 `ENGINE_DELTA_UNVERIFIED` 拒绝，引擎不会猜。
- 不要传正文、不要传评分、不要传轮次。`handoff` 可选，用于覆盖卷/幕/进度。

## 归档后

- 管线进入 `done`，章节号 +1，轮次清零。
- 若还有下一章，从 `novel_brief P1` 重新开始。
